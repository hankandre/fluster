# Playback architecture

`JellyfinGateway` is the only server boundary. Jellyfin's SDK supplies device identity and the authenticated Axios transport; the gateway exposes only the calls needed by this slice. Its access token and user ID are private fields and are cleared on logout. Every server may use HTTPS. Plain HTTP is allowed for loopback hosts, and for private-LAN hosts after the user confirms an unencrypted-connection warning once per server `Id` and origin; public `http://` URLs are refused before any request (`docs/security.md`). Gateway requests never follow redirects. The gateway's Axios client uses the fetch adapter, so in WebKitGTK requests carry `User-Agent: axios/<version>` rather than the WebView's user agent. Fluster sends its client and device identity in the `Authorization: MediaBrowser` header instead. This is not a security issue.

`PlaybackPolicy` is the frozen `PLAYBACK_POLICY` value. `createPlaybackPlan` sends the decision 0002 flags (`PLAYBACK_INFO_FLAGS`) in both the posted DTO and query parameters with the Fluster DeviceProfile, and `decideSource` (`source-acceptance.ts`) turns each source into DirectPlay (a file-backed source the server offers for direct play, never a disc or ISO; a `Static=true` original-file URL), DirectStream or Transcode (an HLS `TranscodingUrl` rebuilt by `hls-url.ts`: same origin, exact `master.m3u8` path for the item, no credential parameter, `EnableTrickplay=false`), or a typed refusal. A disc folder or ISO offered for direct play gets one more PlaybackInfo request with `EnableDirectPlay: false`. The plan carries `delivery` (`static` or `hls`), `playMethod`, and `conversionReasons`; an `hls` plan also carries the signed-in `serverUrl` and `mediaKind`. The native engine sends the plan to `launch_playback`, where the typed `delivery` field selects Rust's static or HLS path (`src-tauri/src/player/media.rs`; boundary in `docs/security.md`); the browser engine refuses an `hls` plan with `UnsupportedDeliveryError` before any player call. External subtitle URLs are authenticated only after same-origin and credential checks; unsafe URLs fail the plan before native launch.

`PlaybackCoordinator` requests that plan with an abortable attempt, launches a `PlayerEngine`, and translates player state into Jellyfin reports. Start is sent only after `file-loaded`; progress is sent every ten seconds and after pause, seek, or track changes; stop is sent after natural completion, explicit stop, recoverable player failure, or graceful window close. A dedicated queue preserves report order without blocking player events, and final draining is bounded. Every report declares `DirectPlay`. Retry waits for teardown, discards the old authenticated URL, and requests a new PlaybackInfo plan and play-session identity.

React reduces typed player events with switch statements into a small `PlaybackSessionState`. Snapshot, first-frame readiness, reporting warnings, and playback errors are retained independently; buffering and diagnostics come directly from the current snapshot.

The desktop `NativePlayerEngine` calls a narrow Tauri command surface. Rust owns libmpv in-process and exposes only initialize, load, surface geometry, pause, seek, volume, mute, track selection, fullscreen, and stop. There is no generic mpv command bridge and no standalone player process.

On Linux, Rust also serves MPRIS (`org.mpris.MediaPlayer2.fluster`, or `….fluster.instance<pid>` when another Fluster holds the name) from `src-tauri/src/media_controls/` on its own thread (setup never waits for the bus), using the blocking `dbus` crate tao already links and `dbus-crossroads`, so no async runtime is involved. The player event loop publishes the title and snapshot to it; `PlayPause`, `Play`, `Pause`, `Seek`, and `SetPosition` call `MpvController::set_paused` and `seek`, the same methods the commands use, and `Stop` emits `fluster://media-control` `{ action: "stop" }` so the frontend stops through Back and reports Stopped. Next, Previous, Raise, and Quit do nothing, `OpenUri` fails, and there is no Volume property. Without a session bus the service is off and playback is unaffected. macOS Now Playing and Windows SMTC are not implemented.

The Jellyfin server socket also lives in Rust (`src-tauri/src/realtime.rs`), behind two more commands: `realtime_connect { serverUrl, authorization }` and `realtime_disconnect`. The WebView's WebSocket API cannot send an `Authorization` header and a token must never travel in a URL, so Rust opens `wss://host/socket` (or `ws://` where `http://` is allowed: loopback and private-LAN hosts) with the `Authorization: MediaBrowser …` header, validates the server URL with the same host-class policy as playback URLs, answers `ForceKeepAlive` with `KeepAlive` at half the server's timeout (clamped to 2–600 seconds), treats two keepalive periods without any server frame as a dead connection, and reconnects with backoff capped at 30 seconds. It stops after a 401 or 403. If the socket task ever panics, the frontend receives `disconnected` and the task restarts after 30 seconds. Only `fluster://server-event` reaches the frontend, carrying `{ kind: "user-data-changed", itemIds }` or `{ kind: "connection", state }`; every other server message is dropped. The session connects after sign-in and disconnects on sign-out or replacement; a `user-data-changed` event, or a reconnect after a lost connection, refetches the Home rows. Browser development mode uses a no-op connection and has no live refresh.

LAN server discovery is one more command, `discover_servers` (P3-03, approved by the user on 2026-11-07). It takes no arguments and only reads the network. Rust (`src-tauri/src/discovery.rs`) binds one UDP socket to an ephemeral port on `0.0.0.0`, sends Jellyfin's `who is JellyfinServer?` datagram to the IPv4 broadcast address on port 7359, reads replies until 2 seconds have passed (each at most 4 KB), and closes the socket; one search runs at a time. It returns `{ servers, refused, dropped }`: each server is `{ name, id, address, advertisedBy, addressIsSender, conflicting }`, at most 16 distinct (id, address) pairs whose address passes the URL policy (loopback only from a loopback sender), `refused` counts replies whose address was refused, and `dropped` counts allowed replies past the 16-entry limit (Rust keeps reading after the list is full so a later reply can still mark a kept id as conflicting). The desktop sign-in screen offers "Find servers on this network" and shows each server's sender and any conflict; choosing a server fills the server URL and runs the normal `/System/Info/Public` probe, refuses the server unless the probe reports the discovered Id, and then, for plain HTTP to a private-LAN host, asks for the unencrypted-connection confirmation. The Quick Connect and password steps show the server origin. Browser development mode has no discovery and hides the action.

The native window is composed as follows:

```text
Tauri window
├── native libmpv OpenGL surface
│   ├── Linux Wayland: GTK GLArea
│   └── macOS: NSOpenGLView
└── transparent WebView
    ├── opaque application pages
    ├── transparent player rectangle
    └── React controls and diagnostics
```

`NativeVideoSurface` measures its DOM rectangle with `ResizeObserver`, skips unchanged frames, and keeps only the newest geometry while one native update is in flight. The WebView remains interactive above the native surface. Linux reparents WebKitGTK into an overlay layer; macOS inserts the OpenGL view below the WKWebView. Renderer objects and libmpv render contexts stay on their platform UI thread. On Linux, a session's teardown makes the `GLArea` context current, frees the render context, clears the surface and collapses it to 1×1, restores the library background, and queues a redraw of the whole window, in that order (`surface/teardown.rs`).

libmpv starts with configuration and normal mpv input disabled, `vo=libmpv`, and `hwdec=auto`. Startup queries and caches the loaded mpv version and rejects anything older than 0.41 with an AppImage/package hint. Runtime properties such as `hwdec-current`, `hwdec-interop`, hardware pixel format, codec, dimensions, bit depth, video output, GPU context, and dropped frames are authoritative. Ordinary snapshots are coalesced to five updates per second, while control and lifecycle changes remain immediate. A missing hardware decoder becomes `Software — CPU` with a warning and continues using the same original stream.

The browser `HtmlVideoEngine` uses the same React player view for component development, Playwright, and direct-file negotiation debugging. It is not used as a silent fallback when desktop native initialization fails; the desktop displays an in-app renderer error instead.

The Render API is in-process by design. A hard fault in libmpv or a graphics driver can terminate Fluster, so the native renderer remains isolated from the Jellyfin and React layers to keep a future out-of-process engine possible.
