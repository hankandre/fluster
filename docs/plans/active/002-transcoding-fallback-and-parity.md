## Tripwire rules after P10-09 (specified, not implemented)

`tests/integration/tripwire.ts` keeps its three independent job signals (container ffmpeg processes, `/Sessions` `TranscodingInfo`, `TranscodeManager` log lines and `FFmpeg.*` files) and its liveness checks. What changes:

- **Playable samples** (h264, hevc-hdr10, av1, ass, sidecar-srt, multitrack, versions, show-s01e01, show-s01e02, show-s00e01), with the default (no limit) setting: the plan must be `DirectPlay`, every media request a `/Videos/{id}/stream` with exactly one `Static=true` or an external subtitle file, and no job signal may fire. This is today's rule, applied per sample instead of globally.
- **bluray-folder:** the plan must be `DirectStream` or `Transcode` (expected field `expectMethod`), never a `Static=true` request; every media request must be same-origin `master.m3u8`, `main.m3u8`, or `hls1/…` with no credential parameter (any case) and no `EnableTrickplay` other than `false`; the plan must carry a conversion reason; the job must be gone 10 s after the stopped report.
- **forced-limit run:** one playable sample (h264) replayed with `MaxStreamingBitrate` below its bitrate must come back `Transcode` with `ContainerBitrateExceedsLimit` (or `VideoBitrateNotSupported`), the same HLS request rules, and no job after stop.
- **no-conversion user:** a second fixture user with transcoding and remuxing disabled must get `conversion-not-allowed` for the BluRay folder, with no media request and no job.
- **Play method check:** for every conversion, `/Sessions` `PlayState.PlayMethod` and `TranscodingInfo.IsVideoDirect`/`IsAudioDirect` are recorded and must agree with the plan's method (DirectStream means both direct).
- `TRANSCODE_MARKERS` in `tripwire-rules.ts` stays for the playable samples and is replaced by the HLS request rules for conversion samples; the existing sabotage cases (missing `Static`, `static=false&Static=true`, 302 to `master.m3u8`) must still fail for playable samples.
- CI job `tripwire` stays; making it required is a CI change and needs the human (AGENTS.md "Pull requests").

Evidence, mpv 0.41.0 with FFmpeg 9.0.2 (Arch), loopback tests in `src-tauri/src/player/media_auth_wire/hls.rs` and `hls_session.rs`: `hls_nested_opens_send_exactly_the_typed_header` and `hls_validated_session_plays_and_every_server_request_carries_the_header` see exactly one `Authorization: <value>` line on every variant, `EXT-X-MAP`, and segment request mpv makes; `hls_segment_redirects_are_refused_on_nested_opens` shows a 302 on a segment reaches the second origin only when `stream-lavf-o` loses `max_redirects=0` (`followed (expected true): true`) and never with it (`followed (expected false): false`); `hls_file_segments_are_refused_with_and_without_the_whitelist` and `hls_handles_set_the_protocol_whitelist_and_references` show `demuxer-lavf-o=protocol_whitelist=[http,https,tcp,tls]` is set and reaches the nested segment open (mpv log: "Protocol 'file' not on whitelist 'http,https,tcp,tls'"); without it FFmpeg still refuses `file:` with the http protocol's inherited whitelist (`http,https,tls,rtp,tcp,udp,crypto,httpproxy,data`). - 2026-11-07 (P10-01): The served copy keeps only the tags FFmpeg's `hls` demuxer acts on, with every URI absolute and every attribute list rewritten canonically; tags FFmpeg ignores (`EXT-X-I-FRAME-STREAM-INF`, `EXT-X-IMAGE-STREAM-INF`, `EXT-X-SESSION-DATA`, `EXT-X-SESSION-KEY`, LL-HLS and unknown tags) are validated, then left out, so mpv cannot reach a playlist Rust did not fetch. It writes header names in lower case (`authorization: <value>`); the loopback tests assert that exact line for Rust and `Authorization: <value>` for mpv.
- 2026-11-07 (P10-01): With `access-references` on, `sub-add` follows references inside a subtitle body: a scratch run on an HLS handle served an HLS-MIME body and an mpv EDL body as the subtitle and the second origin received one request each with the header (an m3u-MIME URL list did not). - 2026-11-07 (P10-01) For P10-04: `http-header-fields` applies to every open on the handle, so mpv also sends the header to the loopback server (Fluster's own listener on `127.0.0.1`); `docs/security.md` says so. A refused segment redirect makes FFmpeg skip that segment and continue, not fail the file.
- 2026-11-07 (P10-01 review, critical): **HLS loads are confined to FFmpeg's `hls` demuxer.** When the `hls` open failed (segment 0 not probeable), mpv fell back to its playlist demuxer, expanded the loopback master into entries, and played each server segment as a top-level file with references on; a segment body that was an HLS playlist then sent the header to another origin (review probe: 2 requests, 5 `StartFile` events). A controller cannot stop this, because mpv advances the entries itself. Fix: `network::load_validated_hls` loads the master with per-file options `demuxer=lavf,demuxer-lavf-format=hls`; FFmpeg's segment demuxers get its own `nested_io_open`, which refuses every open (`hls.c` FFmpeg 9.0.2 lines 1898-1906, 2510). After `FileLoaded`, `network::allow_subtitle_formats` clears the per-file format before `sub-add` (with it still set, `sub-add` of an SRT failed: added `[]`); `demuxer=lavf` stays for the file. Regression test `hls_failed_hls_open_never_falls_back_to_playlist_entries`: forced, 0 requests to the other origin and 1 `StartFile` in both probe modes; the plain `loadfile` control still leaks (2 requests, 5 `StartFile`).
- 2026-11-07 (P10-01 review): **No HTTP proxy on any handle, static included.** FFmpeg's http protocol uses the `http_proxy` environment variable unless its `http_proxy` option is set (`http.c` FFmpeg 9.0.2 lines 252-257), so the header could go through a proxy. Every handle now sets `stream-lavf-o=max_redirects=0,http_proxy=direct://` (any value not starting with `http://` disables the proxy). This changes the static path too. Test `static_and_hls_handles_never_use_an_http_proxy` sets mpv's `http-proxy` (the same FFmpeg option, applied before `stream-lavf-o`) to a loopback proxy: the proxy gets nothing on static and HLS handles and the server gets the header directly; with `stream-lavf-o=max_redirects=0` only, the proxy is contacted. The environment variable itself is not set in tests, because tests share the process environment. Rust's playlist fetches already set no proxy.
- 2026-11-07 (P10-01 review): The loopback server accepts without blocking, answers each connection on its own thread with a 2 s deadline for the whole request head and at most 16 connections, and `Drop` returns within one 10 ms poll without waiting for open connections. Test `hls_loopback_serves_past_slow_clients_and_drops_promptly` (review probe): four slow clients do not delay a GET past 500 ms, a stalled client is closed before 4 s, and drop takes under 200 ms.
- 2026-11-07 (P10-01 review): `HlsRequest` carries the signed-in server URL; the master and every subtitle must share its origin (`hls_master_urls_follow_the_hls_url_rules`). Rust also refuses any playlist or subtitle body that contains the token value itself (any ASCII case, after percent decoding), on top of the credential-name check (`hls_bodies_echoing_the_token_are_detected_in_any_case_or_encoding`, `hls_session_refuses_unsafe_subtitles_and_token_echoes`).

## Risks

| Risk | Mitigation |
|---|---|
| HLS needs `access-references` on, which widens what the mpv handle opens | Only typed HLS sessions; E1-B: mpv reads only playlists Rust validated (same-origin, credential-free, fail closed on credential names); redirect and cross-origin loopback tests |
| The Rust playlist validator misses a URI form (a new tag, an unusual attribute) | Validate every `URI=` attribute and URI line generically, not by tag allowlist; reject unparsable playlists; fixture playlists from both servers in tests |
| The loopback playlist server is reachable by other local processes | Bind `127.0.0.1` only, random per-session path, serve only validated playlists (no token), close with the session |
| `max_redirects=0` or the header does not reach nested opens in some FFmpeg build | P10-01 loopback tests on the bundled FFmpeg; the AppImage FFmpeg must pass them (release gate) |
| DirectStream vs Transcode classified wrongly from the URL | Tripwire compares with `/Sessions` `TranscodingInfo`; the indicator falls back to "Converting on server" when unsure |
| A conversion keeps running after the user leaves | Stopped report kills jobs; `DELETE /Videos/ActiveEncodings` on new sessions and failed stops; tripwire checks no job after 10 s |
| A codec condition sneaks into the profile and transcodes playable files | Profile test fails on any `CodecProfiles` or `ContainerProfiles` entry; tripwire playable-sample rule |
| Audio or subtitle change while converting needs a new stream | P10-08 renegotiates at the current position; direct play keeps local switching |
| Music queue needs new Tauri commands (I3) | P11-01 decides them with `docs/security.md` and allowlist updates |
| Scope growth slows the desktop daily driver | P10 first; P11 after P4; P12 is two small tasks until P9-01 |

## Surprises & discoveries

- FFmpeg 9.0.2's HLS demuxer already refuses `file:` segments inside an HTTP playlist: the nested open inherits the http protocol's default whitelist. Fluster's explicit `protocol_whitelist=http,https,tcp,tls` narrows it further (no `crypto`, `data`, `udp`, `rtp`, `httpproxy`).
- mpv asks the loopback server for the master twice (stream probe, then the `hls` demuxer) and each segment is requested twice during the open (headless loopback tests); only the segments reach the server.

- `master.m3u8` defaults `enableTrickplay` to `true`, and the server then writes `ApiKey={token}` into the playlist body, whatever the request used for auth (`DynamicHlsController.cs` v10.11.7 line 464; `DynamicHlsHelper.cs` line 652).
- The server disables progressive direct stream for streaming ("direct-stream http streaming is currently broken", `MediaInfoHelper.cs` v10.11.7 lines 249-253), so "remux" always arrives as HLS with stream copy.
- `TranscodeReasons` reaches the client only inside `TranscodingUrl`; the `MediaSourceInfo` property is `[JsonIgnore]`.
- The 12.4 stable OpenAPI (`https://repo.jellyfin.org/files/openapi/jellyfin-openapi-stable.json`, version 12.4.0) lists no `master.m3u8`, `main.m3u8`, segment, or `ActiveEncodings` paths, and SDK 1.0.2 has no client for them, so the gateway calls them with the raw Axios client like the other narrow calls.
- P10-02 findings, recorded on Jellyfin 10.11.7 and 12.4.0 with the decision 0002 profile and flags (`tests/fixtures/jellyfin/*/conversion-*.json`, asserted by `src/lib/jellyfin/conversion-fixtures.test.ts`). Both servers behave the same unless noted.

  Subtitles (`DeliveryMethod`): dvdsub is `Embed` when direct played and `Encode` (with `SubtitleMethod=Encode` in the URL, burned in) when converting on both servers, although 12.4.0 reports `SupportsExternalStream: true` for it (10.11.7 reports false). ASS and sidecar SRT are `External` with a `DeliveryUrl` while converting, as decision 0002 assumed. PGS could not be recorded (no encoder); its External-or-Encode behavior stays **[unverified]**.
- Contradictions with decision 0002 assumptions. (1) With no `TranscodeReasons` in the BluRay URL, the "every reason is a container reason" DirectStream rule is vacuously true; P10-03 needs an explicit rule for an absent parameter, and P10-09 must check `TranscodingInfo.IsVideoDirect`/`IsAudioDirect`. (2) 12.4.0 reports `AudioCodecNotSupported` for AAC sources although `aac` is in the profile's audio list; the cause is unknown (**[unverified]**), and under the ADR rule 5 it would classify a copyable conversion as Transcode. (3) Neither server produced a conversion with container reasons (`ContainerNotSupported`), because the match-all DirectPlayProfile never fails a container; DirectStream arrives only through forced fallback or disc folders. (4) The disc folder is never offered for direct play, but the ISO is, so rule 4's forced fallback is needed for ISO only on these servers. (5) The `TranscodingUrl` carries `ApiKey=` (token), `PlaySessionId`, and `Tag`; it has no `EnableTrickplay` parameter, so P10-03 must add `EnableTrickplay=false` itself. 10.11.7 also puts a leading `?&` in the query and adds `BreakOnNonKeyFrames=False`.
