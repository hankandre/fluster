## Approach

1. **System first, then screens.** Tokens, primitives, and a screenshot harness land before any screen changes, so every screen task is assembly plus review, not invention.
2. **One screen per task**, each shipped behind no flag. The old CSS for a screen is deleted in the same task that replaces it, so `src/styles.css` shrinks to the base layer by the end.
3. **Behaviour stays put unless a task says otherwise.** Existing e2e journeys keep passing. Where a task changes behaviour (one-activation resume), it updates the journey and says so in the PR.
4. **Every visible task is reviewed against screenshots** from the harness (P13-01) at 1440×900 and 1920×1080, plus the TV form from P13-18 onward, using the design checklist below.

All five decisions are settled (DESIGN.md §13): one-press resume, the Atkinson faces (verified OFL 1.1, with tabular figures), Logo and Thumb images, the ambient Home backdrop on a 300 ms dwell, and TV OK skipping a visible intro.

## AGENTS.md rules (proposal text; the applied version is shorter)

Add to "Read first":

- Read `DESIGN.md` before changing anything a user sees.

Add a "Design" section:

- Use tokens from `src/styles/tokens.css`; never hard-code a colour, size, radius, shadow, or duration in feature CSS.
- Build UI from `src/features/shared/ui/`; never use a native select, radio, or checkbox in a feature.
- Never style bare element selectors outside the base layer.
- Give every screen one `h1` that names its content.
- Make every screen work with arrow keys, Enter, and Escape alone.
- Use `--focus` only for focus.
- Never put text on artwork without a scrim.
- Never use `backdrop-filter` in the player.
- Honour `prefers-reduced-motion` in every transition.
- Never show a transport error message to the user; map it to copy.
- Attach screenshots at 1440×900 and 1920×1080 for every visible change.

## Design-review checklist (applied)

Applied as `.claude/skills/change-review/references/design-checklist.md`. `change-review` walks it when a diff touches `src/features/**`, `src/components/**`, or `src/styles/**`.

```markdown
# Design review checklist

Read DESIGN.md and the PR's screenshots first. Answer each question with evidence (file:line or screenshot).

## Hierarchy and flow
- Does the screen have exactly one primary action, and is it the one most people want?
- Is the `h1` the content's name (not the route's)?
- How many activations from Home to playing this? Did it go up?
- Does artwork lead, and is the chrome free of decorative colour?

## Tokens and components
- Any colour, size, radius, shadow, or duration literal in feature CSS?
- Any native select, radio, or checkbox, or a bare element selector?
- Are cards sized by `--poster-w` or `--thumb-w` with an aspect-ratio frame?
- Is `--art-accent` used only for progress, selection bars, and glow (never text under 24 px or focus)?

## Focus and input
- Can every control be reached and used with arrows, Enter, and Escape alone?
- Is focus visible (ring plus lift) and never covered by the nav or a prompt?
- Does Back close the topmost layer and restore focus to where it was?
- Is every hover-revealed control also revealed on focus?
- In the player, does the chrome stay visible while paused, focused, or a panel is open?

## Accessibility
- Text contrast 4.5:1 or more (3:1 for large) and UI contrast 3:1 or more, including text over the brightest art fixture?
- Is state shown by more than colour (icon, text, and ARIA state)?
- Live regions announce once per change, not on every tick?
- `prefers-reduced-motion`: no scale, translate, or looping animation?
- Targets 44 px or more (TV 64 px or more)?

## States
- Are loading (skeleton matching the content), empty, error, and offline designed and shown in screenshots?
- Does error copy come from the copy table, with no raw `Error.message`?

## Honesty and safety
- Is every conversion shown with its reason (`ConversionChip`, Info), and is direct play free of extra indicators?
- Does any new text, tooltip, or diagnostic show a URL, token, ID, or play-session ID?

## TV readiness
- Does the screen work in `data-form="tv"` within title-safe insets with no text under 22 px?
- Does anything depend on hover or pointer position?
```
