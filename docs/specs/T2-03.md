## Goal

Make the core's dependence on its host explicit and narrow. Two changes do this, so that T3-02 can supply Expo's implementations and Hermes runs the same code Node tests run:

- The package compiles against a declared host contract instead of Node's types.
- Time and randomness or hashing come in through two injected ports, `Clock` and `Crypto`.

Behavior does not change: the same timings (3 s and 10 s checks, 10 s progress, 5 s and 3 s deadlines) and the same DeviceId for the same inputs.

### Decision log

- **D1. Ports and adapters.** The ports go in `packages/core/src/ports/`, which `ARCHITECTURE.md` §2 already names. The reference adapters go in `packages/core/src/adapters/`, and only they may touch host timers and crypto (the item 4 allowlist). The existing ports in `domain/` (PlayerEngine, RealtimeConnection) do not move.
- **D2. No defaults.** `Clock` and `Crypto` are required constructor parameters, never defaulted to an adapter. There are three reasons:
  - A default would let the old `vi.useFakeTimers` tests pass without proving injection.
  - Decision 0004 records that the core's SHA-256 came from `expo-crypto` under Hermes. From that, this spec infers (unverified) that WebCrypto `crypto.subtle` is not available there, so a silent WebCrypto default could throw on the TV.
  - DOMAINS rule 4 says only the composition root constructs adapters.

  The dependency-cruiser rule enforces this.
- **D3. String-in hashing.** `Crypto.sha256Hex(text)` takes a string and returns hex. It matches expo-crypto's string digest, so T3-02's adapter needs no `TextEncoder`. (That expo-crypto has a string digest is unverified here; T3-02 checks it against current docs.) UTF-8 encoding lives in the adapter, and `TextEncoder` stays declared because `adapters/web-crypto.ts` uses it.

  A draft `host-globals.d.ts` that compiled the package with `types: []` (exit 0, no `@types/node` in `--listFiles`) declared:
  - the interface and constructor var for `AbortSignal`, `AbortController`, `URLSearchParams`, `URL` and `TextEncoder`. The draft also declared `AbortSignal.timeout` and `AbortSignal.any`, but source uses neither, so leave them out: an undeclared `AbortSignal.timeout` makes any later use a compile error instead of an unseen timer;
  - `interface Blob { readonly size: number; readonly type: string }` (type only);
  - `declare var console: { warn(...data: unknown[]): void }`;
  - the four timer functions, returning `unknown`;
  - `declare var crypto: { readonly subtle: { digest(algorithm: "SHA-256", data: Uint8Array): Promise<ArrayBuffer> }; randomUUID(): string }`.

  The implementer trims each member to what core source uses.
- **D4. Where the host-globals file goes.** `host-globals.d.ts` sits at the package root and is in the package tsconfig only. Under `src/` it would trip `findLintGaps` (an unread file) and could clash with `@types/node` in the root project.
- **D5. Lint scope.** The lint covers core source files, not tests. That matches the existing browser-global rule, and tests need real host APIs: `redact-performance.test.ts` measures with `performance.now`, and `vi.waitFor` polls. Item 2's frozen test ensures instead that the checks and the progress interval are tested with `FakeClock`, and that no core test uses `vi.useFakeTimers`.
- **D6. What else the lint bans.** Zero-argument `new Date()` and `Date()` are banned as well, because they read the wall clock just like `Date.now`. `performance.now` is not banned in source, since nothing uses it and the acceptance does not name it. Add it if the reviewer asks.
- **D7. The gateway's random install id stays.** The gateway keeps generating a random `installId` when none is given, now through `crypto.randomId()`. That keeps the tests' behavior. Persisting the install id is the app's job (T4-05 or T3-02 composition root), as `ARCHITECTURE.md` §3 says.

## Risks and out of scope

Risks:

- **Host-globals drift from `@types/node`.** Declarations that are looser than Node's could hide a misuse. Mitigations: the root project still type-checks the same source with real Node types; T3-02 runs the conformance suite under Hermes; and item 1(c) keeps the file to used names only.
- **`FakeClock.advance` microtask draining.** A drain that is too shallow makes reporter-chain tests flaky or falsely red. Keep the loop bound generous and documented, and test it in `fake-clock.test.ts` with a chain of at least five awaits.
- **`vi.waitFor` under fake timers.** `coordinator.test.ts` calls `vi.waitFor` 34 times. Inside a block that used `vi.useFakeTimers`, each poll also advanced time. Once that block uses `FakeClock`, the polls no longer move the core's time. So a migrated test that relied on the hidden advance needs an explicit `await clock.advance(n)`, with `n` equal to the time the test means, and the swap is not mechanical. Leave `vi.waitFor` in tests that never touched fake timers alone. In migrated blocks, prefer `clock.advance` plus `coordinator.flush()`.
- **Constructor churn.** The gateway's parameter order changes, and T2-04 reshapes it again. A wrong positional argument in a test (for example `installId` landing in `transport`) would be a type error under the root project, so `pnpm typecheck` catches it.
- **Flat-config rule override.** Two ESLint blocks that both set `no-restricted-globals` for one file keep only the last one's options. The item 4 test checks that a browser global is still rejected in `adapters/` and that a timer is rejected in `player/`.
- **Invariants and hard rules touched:**
  - "Keep the core free of platform APIs; take them through ports". This task implements it for time and crypto.
  - "Keep `packages/core/src/domain/` free of …". The domain is untouched, and ports live outside it.
  - The `ARCHITECTURE.md` §3 DeviceId row ("Never generate a new one per launch; the device must derive the same value Node derives"). The pinned vector keeps it.
  - The playstate timing in `ARCHITECTURE.md` (10 s progress continues while paused, keeping a converted session alive; the stop of active encodings bounded at 3 s; checks at 3 s and 10 s). The constants are unchanged, and item 2 tests them.
  - "Never log or display tokens …". The gateway's `console.warn` is unchanged and still redacted.
  - "Never skip, weaken, or delete a test" and "Never change a frozen test". This covers the T2-02 files and the migrated assertions.
  - "Treat every new native module method or event as an architecture change". Not touched, because no native code changes.
  - `docs/security.md` is unchanged.

Out of scope:

- Replacing axios and the SDK, the Transport port, and retyping `trickplayTile`'s `Blob` (T2-04).
- Request timeouts (`timeout:` passed to axios in `gateway.ts`). The transport enforces them, and T2-04 decides whether the Transport port takes a deadline or a Clock.
