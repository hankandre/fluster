## Goal

Close four small gaps in the check that keeps the core platform-free (invariant I8, `DOMAINS.md` dependency rules 1 and 2):

- `core-is-platform-free` becomes an allowlist: a core file, test or source, may import only core code, the core's test fixtures, Node builtins (tests only, as today), and the npm packages the core declares. Today that is `vitest` alone. So `react-*` packages and React Native libraries under other scopes fail too.
- A test drives the rule through a real, symlinked `node_modules/react`. A test pins the core's Vitest environment by importing the config. The lint exits 1 for any violation count.

## Approach

One milestone, one commit after the freeze commit: `build(T2-10): make core-is-platform-free an allowlist and exit 1 on any violation`.

1. In `.dependency-cruiser.cjs`, add the allowlist above `module.exports`:

   ```js
   // The core's declared npm packages (packages/core/package.json). Core files may import no other npm package.
   const CORE_PACKAGES = ["vitest"];
   const ALLOWED = `^packages/core/(src|tests/fixtures)/|(^|node_modules/)(${CORE_PACKAGES.join("|")})(/|$)`;
   ```

   Then set `core-is-platform-free`'s `to` to `{ pathNot: ALLOWED, dependencyTypesNot: ["core"] }`.
   - `dependencyTypesNot: ["core"]` lets core tests keep their Node builtins. Source files still meet `core-has-no-host-builtins`, and the domain still meets `domain-is-pure`.
   - Unresolved names (`unknown`), resolved npm paths, symlinks out of `node_modules` (`undetermined`) and `apps/` or `modules/` paths all miss `ALLOWED`, so all of them fail.
2. In `scripts/lint-boundaries.mjs`, change `process.exit(exitCode)` to `process.exit(exitCode > 0 ? 1 : 0)`. The gap and parse paths already exit 1, and a missing `--root` value exits 2.
3. Update `DOMAINS.md:234` as in Files to touch.
4. Run `pnpm check`. The frozen T2-02 cases must still pass:
   - `core-boundaries.test.ts`: the unresolved `react`, `react-native`, `expo-video` and `@expo/vector-icons` cases still name `core-is-platform-free`; the `left-pad` case in the domain still names `domain-is-pure` (a second violation from this rule does not change that); the Node-builtin cases are unchanged.
   - `core-boundaries-test-files.test.ts` is unchanged too.

### Decision log

- **Hard-coded allowlist, not read from `packages/core/package.json`.** Reading the manifest would let anyone who adds `react` to the core's dependencies also loosen the rule, against the config's "Tighten these rules; never loosen them". Item 1 (d) checks that every declared core package is allowed and that platform packages are not. A new core dependency needs both edits, and the config edit is visible in review.
- **One rule, not a new one.** Frozen tests match the name `core-is-platform-free`. The allowlist is a strict superset of the old denylist: every old path still fails, including `@tanstack/*` and `^(apps|modules)/`.
- **`vitest` is allowed in non-test source too.** That is no platform leak, and the domain still rejects it through `domain-is-pure`. Splitting the list by test and source is out of scope (Risks).
- **`packages/core/tests/fixtures/` is allowed** because four core tests import JSON vectors from there (Facts). The rest of `packages/core/` (including `packages/core/node_modules`) is not allowed.
- **Item 2 has two symlink layouts.** pnpm's layout is the realistic one, but it already fails today, so alone it would be a green run and stop the flow at `tests-green`. The linked-out layout is a real hole that the allowlist closes (Facts), so the run is honestly red.
- **Item 4 uses `node:fs` in non-test files**, a violation of `core-has-no-host-builtins`, a rule this task does not change. So the count of exactly 256 holds before and after item 1.
- **Item 3 is `gate: review`, and the implementer writes its test.** The config already complies, so any faithful test is green on main. The test writer writes tests only for run items (`.claude/agents/test-writer.md:12-13`), so the test is a new, unfrozen file. The reviewer checks it. A gate entry needs a `why` (`scripts/check-flow.mjs` `validateManifest`).
- **A draft of the new rule was run on the 256-file tree.** It still reports exactly 256 errors.
