## Goal

Fluster merges on green, so a check that fails at random costs reruns and teaches agents to distrust a red result (`product-review.md:978`). Find and remove the causes of four known intermittent failures: two Back-key journeys, one TV episode-detail journey, and `net::ERR_NETWORK_CHANGED` in local visual runs. Make `pnpm test:visual:accept` copy only the captures that failed. Make `FLUSTER_E2E_PORT` either stop with a clear sentence or work when the next port is taken. Prove it with 10 local e2e runs in a row and 3 full CI runs in a row.

## Approach

### 1. Reproduce each failure before changing it

- For each named test, run it under load with traces: `FLUSTER_E2E_PORT=<free> pnpm exec playwright test <file>:<line> --repeat-each 30 --workers <cores> --trace retain-on-failure`. Then run the same test inside a full suite run. A test that passes alone and fails under load points to a missing wait. Record each count.
- Run once with `DEBUG=pw:webserver` and look for Vite optimiser messages ("new dependencies optimized", "reloading", "Outdated Optimize Dep") during the run. If they appear, Finding 5 is confirmed: give the fake-HLS server its own `cacheDir`, or pre-bundle the discovered deps (`optimizeDeps.include`), and say which in the PR.
- For `ERR_NETWORK_CHANGED`: trigger a host interface change during `pnpm test:visual` (for example, `docker network create p0-18-probe && docker network rm p0-18-probe` in a loop while the run is going), and confirm the error appears in a trace. Then try fixes in this order and record each result:
  1. A Chromium switch or feature that ignores interface changes, only if the Chromium source for the pinned version confirms it exists (cite the file and line). Add it to `launchOptions.args` in both configs.
  2. Run the browser and the dev server where host interface changes cannot reach them, for example an unprivileged network namespace for local runs. Do this only as an opt-in local wrapper documented in WORKFLOW.md; CI is unchanged.
  3. If neither works, the cause is environmental. Write that, with the reproduction, as "cause confirmed, no fix in the test", log a follow-up in `tasks/backlog.md`, and leave the run as it is. Never add a reload-and-retry in `signIn`.
- Never run `pkill`/`killall`, and never stop a server you did not start. Pick a fresh port instead (`.claude/workflows/task.js:84`).

### 2. Make each test wait for its state

Fit the wait to the proven cause. Expected shapes:

- `openItem` (`back-keys.spec.ts:33`): wait for the detail's own heading, by name (the mock item `m1`'s title from `e2e/support/mock-server.ts`), not any `h1`. If the trace shows the key handler needs more (for example, focus inside `main`), wait for that too.
- Dialog test (`:122`): after `toBeVisible()`, add `await expect(page.getByRole("button", { name: "Cancel" })).toBeFocused()`. Focus moves in the same effect that adds the Escape listener (`dialog.tsx:66-80`). If the trace shows the button focused while Escape still does nothing, the app is at fault: go to Acceptance 6.
- TV episode (`tv/detail.spec.ts:54`): before ArrowDown, wait for the strip's cards (for example, `expect(page.locator(".media-card").first()).toBeVisible()`), scoped to the strip. If a late effect steals focus, wait for the state that ends it (for example, the detail settled, with no "Loading" heading) before the first key press.
- Keep every existing `expect`. Add no `waitForTimeout`. Leave `retries` unchanged.

### 3. FLUSTER_E2E_PORT

- `scripts/e2e-ports.mjs` exports `e2ePorts(value)`, which returns `{ app, fakeHls }` (`fakeHls = app + 1`, default 1420). It throws a sentence for a value that is not an integer from 1024 to 65534. It also exports `async firstTakenPort(ports)`, which tries `net.createServer().listen({ host: "127.0.0.1", port })` on each port and closes it at once.
- `playwright.config.ts` uses top-level await (`package.json` has `"type": "module"`; that Playwright 1.65's config loader accepts top-level await is **unverified**, so confirm it first). It runs the check only in the main process. The guard is an env marker the config sets after a successful check (for example, `FLUSTER_E2E_PORTS_CHECKED=1`), because workers inherit `process.env` (Finding 6) and must not re-probe ports the servers now hold.
- If the second port is taken, the config throws one sentence, for example: `Port 43112 is taken; the e2e run uses FLUSTER_E2E_PORT (43111) and the next port for the fake-HLS server. Set FLUSTER_E2E_PORT to a port whose next port is free.` If the first port is taken, it names that port instead. This is the "stops with a sentence" option of the acceptance. It is chosen over picking free ports because a run's ports stay predictable for logs and parallel worktrees, and CI keeps 1420/1421.
- If top-level await does not work in the config loader, use a synchronous probe (`spawnSync(process.execPath, [probeScript, ...ports])`) and record that in the decision log.
- The visual config uses one port and stays as it is.

### 4. Accept copies only failed captures

- `playwright.visual.config.ts`: `reporter: [["list"], ["json", { outputFile: "visual-captures/results.json" }]]`. The file goes into the existing `visual-captures` artifact, and `global-setup.ts` already clears that directory at the start of each run. It holds test titles, statuses, error text, and attachment paths from mocked runs, with no credentials. Confirm that by reading one report.
- `scripts/visual-accept.mjs` exports a pure `planAccept({ results, captures, baselines })` and a thin CLI. A capture is the test `<size> › <name>`, found by walking the report's suites; check the exact nesting against a real report.
  - **Copy** `<size>/<name>.png` when the test's final status is `unexpected` and its last attempt has an `-actual.png` attachment, which Playwright adds on a mismatch or a missing baseline. Check the attachment name against a real failing report.
  - **Refuse** with exit 1 and no writes when a failed capture has no actual attachment (a timeout or mock drift). List those captures: they are not candidate baselines.
  - **Delete** a baseline only when `"baselines match scenarios"` failed and the report's full test list, including tests that did not run (skipped or interrupted), has no `<size>/<name>` for it. That is the removed-scenario case, which the old `--delete` covered.
  - **Refuse** with exit 1 and no writes when the report shows a cut-short run: top-level `errors`, `maxFailures` reached, a skipped or interrupted test, or a filtered run (`-g`, `--grep`, `--shard`, `--last-failed`, `--only-changed` in `config.argv`). A run that did not run every scenario cannot say which baselines are gone.
  - **Skip** the `"baselines match scenarios"` test in the copy and refuse rules. It is `unexpected` with no actual image whenever a scenario is added or removed, and must not trigger the "failed capture with no actual" refusal.
  - **Leave** every other baseline untouched, including passing and flaky captures whose bytes differ.
  - With no `results.json` in the artifact (an older run), refuse with a sentence. Never fall back to copying everything.
- `scripts/accept-visual-baselines.sh`: usage `pnpm test:visual:accept <run-id> [--dry-run]`. Allow `results.json` in the artifact. With `--dry-run`, print `copy`/`delete` lines and write nothing. Otherwise apply the plan and print `git status --short e2e/visual/baselines` as today. Keep `set -euo pipefail` and the run-id check.
- `scripts/visual-accept.test.ts` uses temp directories and a hand-made report: one failed capture with an actual attachment, one passing capture whose PNG bytes differ from its baseline, one flaky, one timed out, one removed scenario, and a failing `"baselines match scenarios"` with no attachment. It asserts the copy, the untouched files, the refusal, the deletion, that a dry run leaves every file byte-identical, and that an interrupted, errored, `maxFailures`, or filtered run refuses and that a baseline whose test did not run is not deleted.

## Risks and out of scope

**Hard rules and invariants this task touches**

- "Never skip, weaken, or delete a test to pass a check" (AGENTS.md, Tests). Only additive waits. The P13-24 review low about replaced TV assertions (`tasks/backlog.md:215`) is not reopened.
- "Never stub a function to make a build pass."
- "Fix a red check before starting the next milestone"; "Never claim a check passed without showing its output."
- The visual gate (WORKFLOW.md §5; CI `visual` job required through `linux-wayland-beta`, `.github/workflows/ci.yml:68-113,184-200`): "Baselines come only from CI" stays true. The comparison settings (`threshold`, `maxDiffPixels`, `retries`, `failOnFlakyTests`, `updateSnapshots`) do not change. The PR calls out the new report file and the accept change.
- CI changes must be called out in the PR (AGENTS.md, Pull requests). No workflow YAML change is planned. If one becomes needed, it is called out too.
- `assertNoTestEngine` (`vite.config.ts:11-17`) and `pnpm test:no-test-engine` must stay intact if `vite.config.ts` changes: the test engine must never reach a build.
- "Never log, persist, or display tokens, passwords, authenticated URLs, or play-session IDs": the JSON report is uploaded as an artifact. It comes from mocked runs only, but check that no request URL with a token appears in its error text.
- "Never let an agent's process kill another's": stop only processes you started.
- If a race fix touches `src/lib/jellyfin/` or `src/lib/player/`, the gateway and negotiation hard rules apply and `guardian` reviews.

**Risks**

- Top-level await or the env-marker guard may behave differently in Playwright's config loader. Approach §3 has a fallback.
- The JSON report's structure or the attachment names may differ from what is assumed. Build the test fixture from a real report.
- Three green CI runs in a row need reruns of the PR's workflow (`gh run rerun`). If the permission system denies that, report it and use the PR pushes' runs instead.
- 10 local runs take time (about 188 tests each; unverified per-run time). Run them in the background and keep the log.
- `ERR_NETWORK_CHANGED` may have no fix inside the test run. Acceptance 1 allows "unverified/environmental" with what was tried.

**Out of scope**

- Other backlog items, including the P13-24 and P13-31 focus-return lows, the Kept-query caps, and the `rust-audit` flake.
- Changing the gate's comparison settings, or what CI compares.
- Rewriting the other visual scenarios' fixed sleeps, unless they fail in the runs.
