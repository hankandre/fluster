## Goal

Undo the two placeholders that decision Q8 A (`docs/specs/decisions-P13.md`, human, 2026-11-10) left on the detail page:

1. `PersonRow` cast cards show the person's picture from the server, with today's initials disc as the fallback.
2. The detail facts line shows the item's rating when the server has one (`CommunityRating`, `CriticRating`).

No new request is added. `GET /Items/{id}?userId=` already returns the full item with no `fields` parameter (`ARCHITECTURE.md` line 120; `src/lib/jellyfin/gateway.ts` `itemDetail`). The full item includes `People[].Id`, `People[].PrimaryImageTag`, `CommunityRating`, and `CriticRating` (`BaseItemPerson` and `BaseItemDto` in `@jellyfin/sdk`, `node_modules/.pnpm/@jellyfin+sdk*/.../base-item-person.d.ts`, `base-item-dto.d.ts`). The recorded 10.11.7 and 12.4.0 fixtures (`tests/fixtures/jellyfin/*/item-detail-no-fields-multitrack*.json`) carry `People[].Id`. They carry no `PrimaryImageTag` because the synthetic person has no image, and no ratings because the synthetic item has none. The work is in mapping and UI only.

## Open questions (answered 2026-11-17; see the decision log)

- **Q1: Which ratings show, and how they read.** The acceptance says the request returns both community and critic ratings, and that the facts line shows "the rating". `DESIGN.md` §7.9 forbids third-party brand logos (no tomato icon), and §10 asks for plain words.
  - A: Community rating only, as `7.8/10`. The critic rating is mapped but not shown.
  - B (recommended): Both, each only when present, placed after the runtime and before the genres: `2023 · 2 h 3 min · 7.8/10 · 91% critics · Drama · Science Fiction`. It is plain text, needs no glyph, and reads correctly in a screen reader.
  - C: Both with a star glyph, as `★ 7.8 · 91%`. It is more compact, but the bare `91%` is unexplained and screen readers read the glyph as "black star".
- **Q2: Does the series page show the rating?** `DESIGN.md` §7.7 contradicts itself. The general line says the rating joins the facts line. The series variant still says "(no rating)", a Q8 A leftover; the original 2026-11-08 design listed "year range, seasons, and rating" for series (`git show 772b22a:DESIGN.md`). The series page already loads the same `itemDetail` (`src/features/browse/series-view.tsx:32`), so showing it costs no request.
  - A: No. Movies and episodes only; §7.7 says so explicitly.
  - B (recommended): Yes. `seriesFacts` gets the same rating parts after the season count and before the genres, and §7.7's series variant drops "(no rating)".

## Approach

1. **Cast image mapping** (`item-detail.ts`). Keep the existing filter (`Name`, `Type === "Actor"`), the `CAST_LIMIT` of 8, and the order. For each person, set `image` only when both `Id` and `PrimaryImageTag` are non-empty strings: `{ itemId: Id, type: "Primary", tag: PrimaryImageTag }`, plus `blurHash` when `ImageBlurHashes?.Primary?.[tag]` is a string. Persons are items, so `gateway.imageUrl(personId, "Primary", tag, width)` serves `/Items/{personId}/Images/Primary?tag=…`. This is the same tagged, token-free image route as posters (`ARCHITECTURE.md` line 127). Do not add a separate `id` field to `CastMember`: P16-07 adds what it needs.
2. **Rating mapping** (`item-detail.ts`). Set `communityRating` only when `CommunityRating` is a finite number with `0 < x <= 10`, because Jellyfin uses a 0–10 scale and 0 or absent means none. Set `criticRating` only when `CriticRating` is a finite number with `0 <= x <= 100`. Store the raw value; rounding is presentation. Map ratings for every item type: series and episodes carry them too.
3. **Rating parts** (`rating-facts.ts`): `ratingFacts(item: Pick<ItemDetail, "communityRating" | "criticRating">): string[]`. Under Q1 B it returns `` `${communityRating.toFixed(1)}/10` `` (7.83 becomes "7.8/10"; 8 becomes "8.0/10") and `` `${Math.round(criticRating)}% critics` ``, each only when present, in that order. Under A or C, adapt to the chosen format; the tests pin it. `detailFacts` becomes: numbers or year, runtime, `...ratingFacts(item)`, genres. Under Q2 B, `seriesFacts` becomes: year range, season count, `...ratingFacts(item)`, genres. Keep `MAX_GENRES = 2`. An episode with no numbers and only a rating gives "7.8/10".
4. **`PersonRow`** (`person-row.tsx`). `Person` becomes `{ name: string; role?: string; imageSrc?: string }`. Extract a small `PersonDisc({ name, imageSrc })` that keeps `const [failed, setFailed] = useState(false)`, keyed by `imageSrc` from the parent so a new source resets it. It renders the existing `<span className="ui-person-disc" aria-hidden="true">` with the initials text and, when `imageSrc && !failed`, an `<img className="ui-person-image" src={imageSrc} alt="" loading="lazy" decoding="async" onError={() => setFailed(true)} />` inside it. The image paints over the initials when it loads, so initials show while it loads and never as a broken image (`DESIGN.md` §7.5, "Never a broken image"). The name is already visible text, so the image is decorative (`alt=""`). Replace the component comment "The cast as initials cards (Q8 A)" with "The cast as picture cards with initials as the fallback; not interactive (Q8 A)". No new focus stop, no link, and no button.
5. **`DetailBody`**. Map `people={item.cast.map((member) => ({ name: member.name, ...(member.role ? { role: member.role } : {}), ...(member.image ? { imageSrc: imageUrl(member.image, PERSON_IMAGE_WIDTH) } : {}) }))}`. `PERSON_IMAGE_WIDTH = 192` is a request parameter (three times the 64 px disc), not a CSS size. Declare it beside `PersonRow` in `person-row.tsx` and export it through `shared/ui/index.ts`, or as a module constant in `detail-body.tsx`. Either is fine; pick one.
6. **CSS** (`detail.css`). `.ui-person-disc` gains `position: relative; overflow: hidden;`. `.ui-person-image` is `position: absolute; inset: 0; inline-size: 100%; block-size: 100%; object-fit: cover; border-radius: inherit;`. Add no new hard-coded sizes, colours, radii, or durations, and no fade animation (this sidesteps reduced motion). The existing `64px` on the disc predates this task. Leave it and log it as a low in the plan if the design review flags it; do not widen scope.
7. **Mock server.** Give the shared `people` list ids `person-1` through `person-5`. Give `PrimaryImageTag: "tag-person-N"` to persons 1, 2, and 4, so m1 shows images and initials together, and m3 and episodes (slices 0–3) show a mix. `imageFor` maps `person-N` to the existing poster art `pN`, so no new generated art is needed. Add `CriticRating: 91` to m1 (`CommunityRating: 7.8` is already there) and pass `CriticRating` through `movieDto`. If Q2 is B, add `CommunityRating: 8.1` to s1 in `seriesDto`. m2 stays without ratings, so the absent state stays covered.
8. **Docs.** Update `DESIGN.md` §7.7, the `ARCHITECTURE.md` Detail row, and the rework-plan line as listed above.

## Risks and out of scope

**Invariants and hard rules touched (flag in the PR):**
- *Talk to Jellyfin only through `src/lib/jellyfin/gateway.ts`*: there is no new call, mapping stays in `src/lib/jellyfin/item-detail.ts`, and image URLs come from `gateway.imageUrl` through `imageUrlFor`.
- *Build media URLs only in Playback Negotiation*: image URLs are not media URLs, and the existing `imageUrl` precedent covers them. No stream or playlist URL is built.
- *Never put a token in a URL*, and never log or display credentials: tagged image URLs carry no token (`gateway.ts` comment at line 799). Nothing new is logged.
- *Keep `src/domain/` free of React, SDK, Tauri, and HTTP imports*: `catalog.ts` gains type fields only.
- *PlaybackInfo, DeviceProfile, and conversion rules*: untouched. The acceptance requires that no playback request changes, and validation command 3 proves it.
- *Request only the `fields` a view renders* (`ARCHITECTURE.md` line 130): unaffected, because `GET /Items/{id}` takes no `fields`.
- Design rules: tokens only, shared UI only, no native controls, "never a broken image", reduced motion (no animation added), arrow, Enter, and Escape navigation (no new focus stops), and plain copy (§10).
- File size: `person-row.tsx` stays well under 400 lines; `item-detail.ts` (218 lines) and `catalog.ts` (295 lines) stay under it.

**Risks:**
- The server shape is unverified on the dogfood server. The SDK types and Jellyfin's web client read `People[].PrimaryImageTag` from the item response, and the recorded fixtures show `People[].Id` with no `fields`, but no recording here holds a person with an image. Manual check: open a real movie on `FLUSTER_DOGFOOD_SERVER` in `pnpm tauri dev` and confirm the cast images and rating, then list it in the PR's untested gates if it is not done. Do not re-record fixtures in this task.
- Episodes on some servers carry a `CommunityRating` from metadata providers, so episode facts may gain a rating. That is intended (the rating shows "when the server has one").
- Many m1 and episode visual baselines change at once, so review the candidates image by image.
- If a person image request fails (404 or offline), the initials return through `onError`. The unit test covers it.

**Out of scope:**
- Clickable cast cards, people pages, and cast on the series page (P16-07).
- Ratings on Home hero facts (`src/features/home/hero-facts.ts`), cards, or search.
- `OfficialRating` (parental rating, such as PG-13).
- Person-image BlurHash placeholders in the UI: the BlurHash is mapped but not rendered; initials are the placeholder.
- Sorting by rating (already in P13-11).
