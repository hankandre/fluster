## Goal

Record, from the two pinned fixture servers (Jellyfin 10.11.7 and 12.4.0), what the account-language routes actually do, so P17-02, P17-03, and P17-08 build on recorded facts instead of the "unverified" lines in the product review ("What Jellyfin does with a partial `POST /Users/Configuration`, whether 10.11 accepts `OriginalLanguage`, and the shape of `/Localization/Cultures` are **unverified**"). The recordings answer:

1. What a new user's `Configuration` holds on each version, and what `GET /Localization/Cultures` lists.
2. Whether `POST /Users/Configuration` merges a partial body or resets every field it lacks, and what it does with a field it does not know.
3. Whether each version accepts `OriginalLanguage` as the audio language, and what default audio track PlaybackInfo then picks.
4. Which default audio and subtitle tracks PlaybackInfo picks for `PlayDefaultAudioTrack` on and off and for each `SubtitleMode`, and whether a preference of `ger` finds a track tagged `deu`.

A new synthetic sample with many subtitle and several audio languages exists for this. A research note states the findings per route and version beside jellyscale's status for that route, and confirms or corrects issue #178.

## Approach

### 1. Shape

One new recorder, modelled on `record-discovery-fixtures.mjs`: log in, find items by path, run scenes, save scrubbed fixtures through `makeSaver`. It runs the same scenes against both servers in turn. Run it after `pnpm samples:generate && pnpm fixture:up && pnpm fixture:setup`. No `package.json` script is added; the header comment gives the usage line, as the other recorders do.

### 2. The language sample

Path: `tests/samples/staging/Synthetic Languages (2024)/Synthetic Languages (2024).mkv`, with `Synthetic Languages (2024).nfo` beside it (`write_nfo ... movie "Synthetic Languages (2024)"` with no genre or person, so it carries `<lockdata>true</lockdata>` and no online match renames it or adds metadata). Staged, not in `movies/`, so that discovery fixtures (Suggestions, Similar, Persons, Filters2) and the tripwire never see it; the recorder copies the folder into `movies/` for its run (same pattern as the staged `S01E03`).

Build: `pattern 320x180` video with `h264_args`; four sine tones for audio, each AAC stereo 64k; twelve SRT inputs written with `printf` into `$work_dir` (each says its own language label, ASCII text, so a person can tell them apart). Every disposition and language is set explicitly with `-disposition:a:N` / `-disposition:s:N` and `-metadata:s:a:N` / `-metadata:s:s:N`; the untagged track gets no `language` metadata at all.

Audio (ff stream order after video):

| Audio | Language tag | Title | Disposition |
|---|---|---|---|
| a:0 | `eng` | English | default |
| a:1 | `deu` | German | none |
| a:2 | `fra` | French | none |
| a:3 | `jpn` | Japanese | none |

The only German audio is tagged `deu`, so a `ger` preference tests whether the server matches the other spelling.

Subtitles (all `-c:s srt`):

| Sub | Language tag | Title | Disposition |
|---|---|---|---|
| s:0 | `eng` | English | default |
| s:1 | `fra` | French | none |
| s:2 | `fra` | French forced | forced |
| s:3 | `fra` | French SDH | hearing_impaired |
| s:4 | `deu` | German (deu) | none |
| s:5 | `ger` | German (ger) | none |
| s:6 | `spa` | Spanish | none |
| s:7 | `ita` | Italian | none |
| s:8 | `jpn` | Japanese | none |
| s:9 | `por` | Portuguese | none |
| s:10 | `nld` | Dutch | none |
| s:11 | (none) | Untagged | none |

That is 12 text tracks in 8 languages, one flagged default, one untagged, forced and hearing-impaired in French, and German tagged `deu` (first) and `ger` (second). The `deu` track comes first so a `ger` preference reveals the rule: a server that normalizes picks s:4; one that compares strings picks s:5.

Verify block additions: probe the sample in the summary table; then `fail` unless `ffprobe -select_streams s ... codec_name` gives twelve `subrip`; the audio and subtitle `tag:language` lists equal the tables above exactly (the untagged track has no tag); the `disposition` `default`, `forced`, and `hearing_impaired` values equal the tables; the NFO exists. Local check for this spec: ffmpeg n9.0.2 kept `deu` and `ger` distinct in Matroska and showed no tag for an untagged subtitle (scratch run, 2026-11-16). jellyfin-ffmpeg in CI is unverified; see Risks.

### 3. Users, start-up clean-up, and restore

- Admin: `fluster-test` (credentials from `.credentials`), used for `POST /Users/New`, `GET /Users`, `DELETE /Users/{id}`, and `POST /Library/Refresh`.
- Fixture users: `fluster-test`, `fluster-noconv`, `fluster-discovery`. Log each in and snapshot `Configuration` from `GET /Users/Me`. Fail before any change if a fixture user is missing.
- Start-up clean-up (recovers from a killed run): delete any user named `fluster-languages` (admin `GET /Users`, then `DELETE /Users/{id}`); remove `tests/samples/movies/Synthetic Languages (2024)/` if present, refresh, and wait until no item has that path.
- Throwaway user: `fluster-languages`, created by the admin with `POST /Users/New` and a fresh random password held only in memory; then log in as that user. Every scene below uses that user's token, so the requests are a non-admin viewer's.
- Stage: copy the staged folder into `movies/`, `POST /Library/Refresh`, and poll (`waitFor`, as in the discovery recorder) until an item with that path exists and its `MediaSources[0].MediaStreams` holds 1 video, 4 audio, and 12 subtitle streams.
- `cleanup()`, run in `finally` and from `process.once("SIGINT"/"SIGTERM")` handlers (which then `process.exit(1)`), guarded so it runs once: for each fixture user, read `Configuration`, deep-compare with the snapshot, `POST /Users/Configuration` with the snapshot (as that user) if they differ, read again, and record a failure if still different; delete the throwaway user; remove the staged copy, refresh, and wait until the item is gone. Each clean-up step runs even if an earlier one failed; any failure makes the process exit non-zero with a message naming the step (never a token or URL with a token). A run that throws still writes nothing partial: `makeSaver` writes one file at a time, and the recorder writes a scene's fixture only after the scene completes.

### 4. Scenes (per server)

All requests send header auth; none sends a token in the query.

**Scene A, read-only.** `GET /Users/Me` as the new throwaway user, before any write (acceptance 1). `GET /Localization/Cultures`. `GET /jellyscale/v1/track-preferences` with `callStatus`, saved as `{ httpStatus }` (#178 says this answers 404 on Jellyfin; P17-05 detects jellyscale by it).

**Scene B, the configuration sequence** (acceptance 2). Each step is `POST /Users/Configuration` (no `userId` query, so the caller; this is the form P17-03 will send) followed by `GET /Users/Me`; the step records `{ step, request: { method, path, query, body }, status, configuration }`. Use `callStatus` so a refusal is recorded, not thrown.

1. `non-language fields changed`: the new user's whole `Configuration` with `PlayDefaultAudioTrack: false`, `SubtitleMode: "Always"`, `DisplayMissingEpisodes: true`, `HidePlayedInLatest: false`, `RememberAudioSelections: false`, `RememberSubtitleSelections: false`, `EnableNextEpisodeAutoPlay: false`, and both language fields `"eng"`. (If a version's new-user object lacks one of these fields, leave it out and note it in the step name.)
2. `whole object, two language fields changed`: the `Configuration` read after step 1, with `AudioLanguagePreference: "deu"` and `SubtitleLanguagePreference: "fra"`.
3. `only the language fields`: the body `{ AudioLanguagePreference: "spa", SubtitleLanguagePreference: "ita" }` and nothing else.
4. `whole object restored`: the `Configuration` read after step 2, unchanged (puts the account back to a known state; the read-back shows it).
5. `whole object plus an unknown field`: the `Configuration` read after step 4, with `SubtitleLanguagePreference: "spa"` and the unknown field `FlusterUnknownField: "fixture"`. The read-back shows whether `spa` was saved (the body was accepted) and whether `FlusterUnknownField` appears (kept or dropped); a 4xx status with an unchanged read-back means refused.

If a version refuses `POST /Users/Configuration` without `userId` (unverified before recording), the recorder runs the sequence again with `?userId=<throwaway>` and suffixes those step names with `(?userId= form)`, so acceptance 2 still shows merge or reset on that version. Recorded: both versions answered 204 to the no-`userId` form, so no second sequence exists in either fixture.

## Decisions taken in this spec

- **Throwaway user for every change.** The acceptance says "on a throwaway user"; using it for scene C as well keeps the fixture users untouched, so acceptance 6's restore is a safety net, not the main mechanism.
- **Staged sample, not a library file.** A new movie in `movies/` would change discovery fixtures (Suggestions lists 10 movies; Similar and Recommendations count movies) and the tripwire's library. Staging follows the `S01E03` precedent from P16-01.
- **`POST /Users/Configuration` with no `userId`.** It is the 10.9+ path P17-03 will use for the caller; jellyscale's capture found the three forms behave alike on 12.4, which the note may cite but does not rely on.
- **Cells start from the new user's object.** Each scene C cell overlays its fields on the new user's `Configuration`, so a reset or merge found in scene B cannot leak into the defaults table.
- **Probe of `/jellyscale/v1/track-preferences`.** One extra request settles a #178 claim P17-05 depends on; it adds no gateway call.
- **No edit to `ARCHITECTURE.md`.** A contradiction is logged to the backlog for a doc-gardening or P17-03 change.
