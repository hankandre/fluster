## Goal

"File and streams" on a title's page lists every subtitle track on its own line; a film with 52 subtitle tracks fills the screen (owner, dogfood server). After this task the Subtitles entry shows a short list chosen by the viewer's Jellyfin subtitle language, with every track one keypress away:

- **Preferred language matched:** only the chosen version's tracks in that language (forced and hearing-impaired included), then a button "Show all 52 subtitles".
- **No preference, or nothing matches:** the file's default subtitle track if it has one, then "51 more in 32 languages"; with no default, only "52 in 32 languages". The button follows.
- **Everything already listed**, including a version with exactly one subtitle track: that track alone, no button and no count line.

The button sits in its own spatial row, so ArrowDown reaches it from the action bar on desktop and TV alike, and Up leaves the expanded list. The gateway gains the read of the account's `SubtitleLanguagePreference` (which P17-03 and P17-08 reuse) and the read of `GET /Localization/Cultures`, so `ger` and `deu` are one language. Nothing that plays changes.

## Approach

### 1. Gateway

`types.ts`:

```ts
export interface UserConfigurationDto {
  SubtitleLanguagePreference?: string | null;
  [key: string]: unknown;
}
export interface UserDto {
  Configuration?: UserConfigurationDto | null;
}
export interface CultureDto {
  Name?: string;
  DisplayName?: string;
  TwoLetterISOLanguageName?: string;
  ThreeLetterISOLanguageName?: string;
  ThreeLetterISOLanguageNames?: string[];
}
```

`src/lib/jellyfin/account-languages.ts` (pure, no I/O):
- `toAccountLanguages(data: unknown): AccountLanguages`: read `Configuration.SubtitleLanguagePreference`; a string that is non-empty after `trim()` becomes `subtitleLanguage`; anything else (absent key, `""`, `null`, non-object body) gives `{}`. Nothing else is read. P17-08 adds `audioLanguage` here (the fixtures show `AudioLanguagePreference` absent for a new user: treat absent as none).
- `toLanguageCultures(data: unknown): LanguageCulture[]`: a non-array gives `[]`; each entry needs a non-empty `ThreeLetterISOLanguageName` string or is skipped; codes are lowercased; `threeLetterNames` is `ThreeLetterISOLanguageNames` filtered to strings, with the main name added if missing; `twoLetterName` is set only when non-empty; `displayName` from `DisplayName ?? Name`. Entries are kept as the server listed them.

`gateway.ts`, beside `itemDetail`:

```ts
// The account's language settings from GET /Users/Me. Display only: the server picks default tracks itself.
async accountLanguages(signal?: AbortSignal): Promise<AccountLanguages> {
  this.requireSession();
  const { data } = await this.get<UserDto>("/Users/Me", { signal, timeout: CONTROL_REQUEST_TIMEOUT_MS });
  return toAccountLanguages(data);
}

// The server's language table (GET /Localization/Cultures): which codes name the same language.
async languageCultures(signal?: AbortSignal): Promise<LanguageCulture[]> {
  this.requireSession();
  const { data } = await this.get<CultureDto[]>("/Localization/Cultures", { signal, timeout: CONTROL_REQUEST_TIMEOUT_MS });
  return toLanguageCultures(data);
}
```

`SessionGateway` gains both signatures with a one-line comment each. `fakeSessionGateway` gains `accountLanguages: vi.fn().mockResolvedValue({})` and `languageCultures: vi.fn().mockResolvedValue([])`.

Decision: the cultures are read at runtime, not copied into a static table. The acceptance names `/Localization/Cultures` as the source, P17-03 needs the same read for its Pickers, and the two versions list different tables (192 and 494 entries). The read is cached for the session (§4), so it costs one request per account per launch.

### 2. Domain

`src/domain/languages.ts`:

```ts
export interface LanguageCulture {
  displayName: string;
  threeLetterName: string;      // ThreeLetterISOLanguageName, lowercased
  threeLetterNames: string[];   // every three-letter code for it, lowercased (deu, ger)
  twoLetterName?: string;       // lowercased; absent when the server gives ""
}
export interface AccountLanguages {
  subtitleLanguage?: string;
}
// One key per language: the culture's main three-letter name when the code is any of its names, else the
// lowercased code. Undefined for a missing, empty, or "und" tag, which names no language.
export function languageKey(code: string | undefined, cultures: readonly LanguageCulture[] | undefined): string | undefined;
```

Lookup: lowercase and trim the code; return `undefined` for `""` or `und`; find the first culture whose `threeLetterName`, any of `threeLetterNames`, or `twoLetterName` equals it; return its `threeLetterName`, else the code. Build the lookup once per cultures array (a `WeakMap<readonly LanguageCulture[], Map<string, string>>`), since a 52-track list calls it 53 times per render. With `cultures` undefined, the key is the lowercased code (exact spelling).

`src/domain/subtitle-list.ts`:

```ts
export interface ListedSubtitle { index: number; subtitle: SubtitleInfo }  // index into version.subtitles
export type SubtitleListView =
  | { kind: "none" }                                        // no subtitle tracks: "None", as today
  | { kind: "all"; shown: ListedSubtitle[] }                // every track listed: no line, no button
  | { kind: "preferred"; shown: ListedSubtitle[]; total: number }
  | { kind: "summary"; shown: ListedSubtitle[]; remaining: number; remainingLanguages: number; total: number };

export function subtitleListView(
  subtitles: readonly SubtitleInfo[],
  preference: string | undefined,
  cultures: readonly LanguageCulture[] | undefined,
): SubtitleListView;
```

Rules, in order:
1. No tracks: `none`. Exactly one track: `all`, whatever its flags and language (owner, 2026-11-16).
2. `prefKey = languageKey(preference, cultures)`. If defined, `matches` = tracks with `languageKey(track.language) === prefKey`, in file order. If `matches` is non-empty: `all` when it is every track, else `preferred`.
3. Otherwise `shown` = the first track with `isDefault`, if any. If `shown` is every track: `all`. Else `summary` with `remaining = total - shown.length` and `remainingLanguages` = the number of distinct defined keys among the tracks not shown.

Hearing-impaired: `SubtitleInfo` has no hearing-impaired flag today and none is added; such tracks match by language like any other, which is what "included" requires. Labels are unchanged.

## Risks and out of scope

Risks:
- **Visual baselines.** Every detail capture of a title with two or more subtitle tracks changes (§6 list), not only m1's. Accept only through `pnpm test:visual:accept` from CI, and check in the PR that only detail captures changed.
- **Mock drift.** If `/Users/Me` or `/Localization/Cultures` is left out of the mock, every visual scenario fails on the 404 check; serve both always.
- **Shared `hdrSource`.** A builder that mutates `hdrSource` would change m2's page and the player scenarios that use `src-4k`. The spread copy and the fourth `detail-subtitles` test guard it.
- **Spatial row order.** The subtitle row must stay after `EpisodeStrip` in DOM order, or the episode ArrowDown journeys (desktop and TV) would land on it first. `DetailBody` is not reordered.
- **Reading the expanded list by keyboard.** With focus on the expanded list, ArrowUp moves focus to the previous row (scrolling the page up to it), and Home and End are taken by the roving hook (`nextRovingIndex`), so they do not scroll the page. ArrowDown and Page Up/Down still scroll on desktop. Acceptable for a list one press away; noted for the design review.
- **Layout shift.** On a cold cache the summary form shows first, then the preferred form when the account read returns. It is below the first screen at 1440×900, so the first screen does not move; if focus is already on the button when the form changes, the row stays mounted and keeps its item (the button), so focus stays. Waiting for the cultures read too (§4) keeps it to one change.
- **Spelling fallback.** If `/Localization/Cultures` fails, `ger` and `deu` count as two languages and a `ger` preference misses `deu` tracks. Nothing is shown about it; the full list is one press away.
- **Server tag normalisation.** P17-01 shows PlaybackInfo reporting a `ger`-tagged track as `deu`; whether `GET /Items/{id}` does the same is unverified. `languageKey` makes it irrelevant when the cultures read succeeds.
