## Goal

Turn `PlayerEngine` into the engine-neutral seam that Media3 (T8) and libmpv (T13) both implement, and that the player module mirrors one to one (T8-01):

- No desktop-era surface: no surface geometry, fullscreen, volume or mute command, no `mode: "native" | "browser"`, and no mpv name anywhere in the port's types.
- `launch` takes one typed request, a discriminated union of an original file and an HLS session. It carries token-free URLs and the opaque session id from decision 0005, never the header or the token. The coordinator stops reading a header.
- `initialize` returns typed capabilities: which video codecs decode in hardware (and in software), the audio codecs, the HDR types the display supports, and passthrough formats, plus a "cannot tell" state. T2-07 and T8-07 consume this shape.
- The port has a fixed member list, checked by a test against an allowlist, and a fixed event list.
- Engine errors are typed codes. Free text from a player never reaches the coordinator's callers, a thrown error or the session state.

## The port

New file `packages/core/src/domain/player-engine.ts`. It imports nothing, so it is self-contained and can be scanned on its own. `domain/playback.ts` imports the types it uses from it and re-exports every name below, so `import { PlayerEngine } from "../domain/playback"` keeps working (frozen imports, the routing rule in `task.js`). The dependency runs one way, `playback.ts` → `player-engine.ts`, so there is no cycle.

Moved from `playback.ts` unchanged (re-exported there): `MediaTrack`, `HlsMediaKind`, `PlayerTrack`, `VideoRange`, `VideoFacts`.

```ts
// The opaque transport session id (decision 0005). It names a native session registry entry and is not secret.
type SessionRef = string;

interface LaunchCommon {
  sessionId: SessionRef;
  startPositionSeconds: number;
  // The plan's Jellyfin streams. The engine maps its own track ids to these indices.
  tracks: readonly MediaTrack[];
  // Jellyfin stream indices for the first selection. -1 or absent subtitle means off.
  audioStreamIndex?: number;
  subtitleStreamIndex?: number;
}

export type LaunchRequest =
  | (LaunchCommon & { kind: "original"; url: string })
  | (LaunchCommon & { kind: "hls"; masterUrl: string; serverUrl: string; mediaKind: HlsMediaKind });

export const VIDEO_CODECS = ["h264", "hevc", "av1", "vp9", "vp8", "mpeg2video", "mpeg4", "vc1"] as const;
export const AUDIO_CODECS = ["aac", "mp3", "ac3", "eac3", "truehd", "dts", "flac", "alac", "opus", "vorbis", "pcm_s16le", "pcm_s24le"] as const;
export const HDR_TYPES = ["hdr10", "hdr10-plus", "hlg", "dolby-vision"] as const;
export const PASSTHROUGH_FORMATS = ["ac3", "eac3", "eac3-joc", "dts", "dts-hd", "truehd"] as const;

export interface VideoDecoder {
  codec: VideoCodec;
  hardware: boolean;
  // Jellyfin's MediaStream.Profile spelling (for example "Main 10"); absent means any profile.
  profile?: string;
  maxBitDepth?: 8 | 10 | 12;
  maxWidth?: number;
  maxHeight?: number;
}

export type PlayerCapabilities =
  | {
    probe: "complete";
    videoDecoders: readonly VideoDecoder[];
    audioDecoders: readonly AudioCodec[];
    hdr: readonly HdrType[];
    passthrough: readonly PassthroughFormat[];
  }
  // The engine could not read the device: "cannot tell", never "can play" (T8-07).
  | { probe: "failed" };

export const PLAYER_ERROR_CODES = [
  "network",             // the stream could not be fetched: no connection, timeout, dropped connection
  "server-error",        // the server answered an error status, or a redirect the client refused
  "session-ended",       // the launch named a session the native registry does not hold, or the server ended it
  "unsafe-playlist",     // an HLS playlist failed native validation (I2)
  "unsupported-request", // the engine refused the request's kind or shape
  "malformed-media",     // the container or a playlist could not be parsed
  "decoder-unavailable", // no decoder on this device for the stream's format
  "decoder-failed",      // a decoder failed to start or failed while decoding
  "audio-output-failed", // the audio output could not be opened
  "stop-failed",         // the engine did not finish shutting down (the coordinator raises it)
  "unknown",
] as const;
export type PlayerErrorCode = (typeof PLAYER_ERROR_CODES)[number];

export class PlayerEngineError extends Error {
  readonly code: PlayerErrorCode;
  // The message is the fixed copy for the code, never player text.
}

export const PLAYER_EVENT_KINDS = ["loaded", "first-frame", "state", "tracks-changed", "ended", "error"] as const;
export type PlaybackEndReason = "eof" | "stopped" | "error";
export type PlayerEvent =
  | { kind: "loaded"; snapshot: PlaybackSnapshot }
  | { kind: "first-frame" }
  | { kind: "state"; snapshot: PlaybackSnapshot; cause?: "pause" | "seek" | "property" }
  | { kind: "tracks-changed"; snapshot: PlaybackSnapshot }
  | { kind: "ended"; snapshot?: PlaybackSnapshot; reason: PlaybackEndReason }
  | { kind: "error"; code: PlayerErrorCode };

// Six commands and one event subscription. Adding one changes this list, the allowlist test and docs/security.md.
export const PLAYER_ENGINE_METHODS = ["initialize", "subscribe", "launch", "setPaused", "seek", "selectTrack", "stop"] as const;

export interface PlayerEngine {
  initialize(): Promise<PlayerCapabilities>;
  subscribe(listener: (event: PlayerEvent) => void): Promise<() => void>;
  launch(request: LaunchRequest): Promise<void>;
  setPaused(paused: boolean): Promise<void>;
  seek(positionSeconds: number): Promise<void>;
  selectTrack(type: "audio" | "subtitle", playerId?: number): Promise<void>;
  stop(): Promise<void>;
}
```

Issues (none critical or high; the test writer and implementer resolve these). Resolved by the implementer: 1, 2, 3 and 5 in item 2 and item 6 (the frozen tests already cover them); 4 by D12; 6 by D13; 7 in The port; 8 in Facts; 9 in D8; 10 in D5 and item 2. 11 and 12 are notes; the test writer's files type-check against the port as built (`pnpm typecheck` reports only `clock-driven.test.ts`).

1. **Medium. A rejected `subscribe` still carries player text to the caller.** `coordinator.ts:271` awaits `this.player.subscribe(…)` with no catch, so an engine's rejection reaches the caller of `start` as is. Item 6 covers the launch rejection, the error event and the failed stop only, yet the Goal says free text never reaches "a thrown error". Map a `subscribe` rejection the same way as a launch rejection (`PlayerEngineError`, `unknown` unless typed), and add a case to `coordinator-errors.test.ts` (rejection as a string and as an `Error`, asserting no canary text and that `launch` is never called).
2. **Medium. `launchRequest` does not say what an unparseable or relative URL does.** `new URL("/videos/x?api_key=SECRET")` throws a `TypeError` whose `input` property holds the string (probed with Node: keys `code`, `input`). Left uncaught, that error would leave `start` with the URL on it. Require `LaunchRefusedError` for any URL that does not parse, and add a relative URL and a non-URL string to item 2 (c), asserting the error has no `input` and `JSON.stringify` of it has no part of the URL.
3. **Medium. `serverUrl` is passed to the engine but not listed among the checked URLs.** The origin comparison ignores user info, so `https://u:p@media.test` as `serverUrl` would pass and reach the engine. Check `serverUrl` for scheme, user info and credential query names like the others, and add the case to item 2 (c).
4. **Low. Milestone 1 ends with `pnpm typecheck` red by design** (`coordinator.ts` no longer compiles against the new port), against "Fix a red check before starting the next milestone". Merge milestones 1 and 2 into one commit, or move the coordinator's change into milestone 1.
5. **Low. A `PlayerEngineError` from `launch` is rethrown as is, while event codes are validated.** Rebuild it as `new PlayerEngineError(code)` from a code checked against `PLAYER_ERROR_CODES`, so a bad code, an altered message or a `cause` holding native text cannot ride through. Add a case with a cast bogus code.
6. **Low. A typed launch rejection loses its code in the session state.** `failureAction` (`player/session-failure.ts`) keeps only the message, and the spec clears `errorCode` on `failure`.
