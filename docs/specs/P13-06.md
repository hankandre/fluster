## Approach

1. `AppNav({ libraries, hash })` in `shared/ui/app-nav.tsx` is presentational. `libraries` is `{ id: string; name: string }[] | undefined`; `undefined` means pending or failed, and the nav then shows only the fixed entries (no placeholders, no error text). Order: wordmark link named "Fluster" to `#/next/home`, Home, libraries in server order, Search (inline SVG icon with `currentColor` and `aria-hidden`, plus the label), Settings (gear icon link with accessible name "Settings"). Layout follows DESIGN.md §7.1: the wordmark, Home, the libraries, and Search sit left in a scrolling entry list; Settings sits on the right of the bar, outside the scrolling list but inside the same `<nav>`, so it stays in the one roving set (`useRovingFocus` finds `[data-roving-item]` anywhere in its container, `roving-focus.ts:44`) and stays last in DOM and arrow order. Every entry, including the wordmark and the gear, has `min-block-size` and `min-inline-size` of `var(--hit-min)` (44 px desktop, 64 px TV; DESIGN.md §11.3, `tokens.css:63`, `:114`). Every link carries `data-roving-item`. The wordmark never gets `aria-current`.
2. `AppShell({ nav, children })` renders the skip link, `<header className="app-nav">` with `nav`, then `children` inside a plain `<div className="app-content">` held by a ref. The skip link's click handler calls `preventDefault()`, takes `contentRef.current?.querySelector("main")`, sets `tabindex="-1"` when the `main` has no `tabindex` attribute (React does not render `tabIndex` on any of these `main` elements, so it will not overwrite it), and calls `focus()`. With no `main` it does nothing; the `App.test.tsx` matrix guarantees every nav route has one. Use the new class names `app-frame` (outer wrapper), `app-nav`, `app-nav-entry`, `app-content`, and `skip-link`. Do not use `app-shell`: it already styles the player's `<main>` (`src/styles.css:8`, `:39`; `player/index.tsx:192`, `:265`). The header is sticky, with `height: var(--nav-h)`, `z-index: var(--z-nav)`, and a background of `--surface-0-glass` (`--surface-0` at 92%, a token in `tokens.css` because `color-mix` is allowed only under `src/styles/`). No `backdrop-filter` in this task: `tokens.css` and DESIGN.md §8 define no blur token, and DESIGN.md §7.1 ties the blur to content scrolling under the bar over artwork, which arrives with P13-08 (Decision 11).
3. `useRovingFocus(layout, options?: { preferredIndex?: number })`. When `preferredIndex` is defined and differs from the value on the previous render, set `active.current` to it (clamped to the item count) before `sync`. It moves only the Tab stop, never focus. Existing callers pass no options and keep today's behaviour (start at 0, `roving-focus.ts:60`). `AppNav` passes the index of the `aria-current` entry, or Home's index (1) when no entry is current. Libraries load after the first render, so the indexes of Search and Settings shift once; the changed value moves the Tab stop to the right entry.
4. `SignedInChrome({ hash, children })` in `src/features/shell/` calls `useSession()`. With no gateway it returns `children` alone. Otherwise it renders an inner `NavShell({ gateway, hash, children })` (hooks cannot be conditional), which runs `useQuery({ queryKey: ["nav", scopeFor(gateway), "views"], queryFn: ({ signal }) => gateway.userViews(signal), gcTime: 0 })` and renders `<AppShell nav={<AppNav libraries=… hash={hash} />}>{children}</AppShell>`. `gcTime: 0` follows the `src/features/query-scope.ts` convention (as `browse-view.tsx:52` and `series-view.tsx:23` do): on sign-out `NavShell` unmounts and the library names are dropped, so the next user never sees them. Keep the shell at the same element position in `App.tsx` for every nav route, so it stays mounted across hash changes and does not refetch per route. Entering the player unmounts it, so returning from the player refetches `userViews` once; that is accepted.
5. In `App.tsx`, a `chromeFor(hash, native): "nav" | "none"` `switch` implements the matrix. `renderRoute` changes only in the `#/next` case (native renders `NotFoundView`).
6. Content must not hide under the sticky nav (WCAG 2.4.11): set `scroll-padding-top: var(--nav-h)` on the scroll root, and check that `BrowseFrame`'s focused `h1` is not covered.
7. CSS uses tokens only (`css-rules.test.ts` forbids colour literals and bare element selectors). Transitions use `--dur-quick` and `--ease-out`, with no transform or slide; the base layer already zeroes durations under reduced motion. For overflow, set `overflow-x: auto` on the entry list and scroll the focused entry into view with `scrollIntoView({ block: "nearest", inline: "nearest" })` (Decision 4).
8. Use plain anchors with token classes, or `ButtonLink`; no native select, radio, or checkbox.

## Risks and out of scope

- Hard rules and invariants touched:
  - Build new UI only under `src/features/`, from `src/features/shared/ui/`.
  - Use tokens only; never hard-code colours, sizes, radii, or durations.
  - No native select, radio, or checkbox in a feature.
  - Every screen works with arrows, Enter, and Escape alone, and honours reduced motion.
  - Map errors to plain copy; never show a transport error message (the nav hides libraries on error).
  - Talk to Jellyfin only through `src/lib/jellyfin/gateway.ts` (the nav uses `SessionGateway.userViews`; no new request type).
  - Never display authenticated URLs or tokens (the nav shows library names only, no images).
  - Never store tokens in WebView storage, Query caches, or React state (the query caches only library ids and names).
  - Add a focused test with every behaviour change; never skip, weaken, or delete a test (journeys change only how they reach a screen).
  - Screenshots at 1440×900 and 1920×1080 in the PR.
  - No playback, DeviceProfile, PlaybackInfo, HLS, Tauri command, or `ARCHITECTURE.md` invariant changes.
- Risk: a skip link with `href="#content"` would replace the route hash. Use the `preventDefault` handler.
- Risk: the skip link sets `tabindex` on a `main` that a view renders. A later view that renders `tabIndex` itself is left alone (the handler checks the attribute first); a nav route without a `main` fails the `App.test.tsx` matrix.
- Risk: duplicate link names (nav "Home", "Search", "Settings", or a library name, versus content links) break Playwright strict mode. Scope selectors to the nav landmark or to `main`.
- Risk: `BrowseFrame` focuses its `h1` on mount (`browse-view.tsx:19`), so on browse, search, series, and collection routes the next Tab goes into content, not to the skip link. This existing route-change focus rule stays; the Tab order holds from the document start. `nav.spec.ts` starts each keyboard sequence on Home, which does not move focus.
- Risk: e2e and visual mock servers that do not answer `/UserViews` make the nav show no libraries. The specs that need library entries (`browse`, `nav`, visual) already serve it, and `screens.spec.ts` fails on mock 404s, so drift shows up there.
- Risk: the browser-mode label (`styles.css:101`, fixed bottom right) must not cover a nav control. It sits at the bottom, so it should be safe; check in the captures.
- Risk: the `App.test.tsx` seam drives the real `SignInView`; a later sign-in label change breaks it. That is intended coverage, not a stub of the code under test (`compose.ts` is replaced only to inject the fake gateway and the `native` flag).
- Risk: the nav must never overlap the native video surface. The mpv session runs only under `#/next/play/*`, which has no nav.
- Out of scope: hero transparency over Home and the empty Home state (P13-08); Libraries page tiles and toolbar (P13-11); Settings sections and Account (P13-17); sign-in redesign (P13-16); TV tab-row behaviour and Down/Up between nav and rows (P13-07, P13-18); player chrome (P13-13); `/` to focus search and Backspace as Back.
