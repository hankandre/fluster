## Goal

`src/lib/jellyfin/gateway.ts` has six small inconsistencies, each confirmed by reading the code:

1. `playbackInfo` builds `` `/Items/${itemId}/PlaybackInfo` `` with no encoding (line 823). Every other path in the gateway encodes the item id (`encodeURIComponent`, for example lines 686, 695, 708, and `buildStaticStreamUrl` line 157).
2. `mediaSegments` (lines 706-713) does not call `requireSession()`. Every other authenticated call does, so a signed-out gateway sends an unauthenticated request instead of failing locally.
3. `latest()` (lines 398-430) has no production caller (`grep -rn "\.latest()" src e2e tests`, non-test files: no match). Its only uses are tests.
4. The private `get`, `post`, and `delete` wrappers (lines 899-930) are the same try/catch/redirect code three times.
5. `createClient` hard-codes `version: "0.1.0"` (line 63). `package.json:4` is `0.1.0` today, so the value goes stale at the first version bump.
6. `DEVICE_NAME = "Fluster Linux"` (line 54) is sent on every platform, including macOS.

After this task the gateway encodes the PlaybackInfo path, refuses `mediaSegments` when signed out, has no `latest()`, has one request wrapper, and receives its client version and device name from the composition root (`src/app/compose.ts`). The device id, the PlaybackInfo body and query, and the DeviceProfile do not change for any ordinary item id.

## Approach

### Client identity

Add to `gateway.ts` (exported, so `compose.ts` and the tripwire can type their argument):

```ts
// What the server shows for this client in its device list. The composition
// root supplies both; the core reads no build or platform globals.
export interface ClientIdentity {
  version: string;
  deviceName: string;
}
```

The constructor gains a sixth parameter after `streamingLimits`: `private readonly client: ClientIdentity = UNIDENTIFIED_CLIENT`, where `UNIDENTIFIED_CLIENT = { version: "0.0.0", deviceName: "Fluster" }` is a private constant. A default is needed because `transport` is declared with `?`, so TypeScript rejects a required parameter after it (TS1016), and about 55 test call sites construct the gateway with three or fewer arguments. The default is deliberately not a real version, so a production path that forgets the identity is visible on the server, and `compose.test.ts` catches it. P2-08 freezes public signatures, so this constructor change belongs here.

`createClient(deviceId)` becomes `createClient(client, deviceId)` and builds `clientInfo: { name: "Fluster", version: client.version }` and `deviceInfo: { name: client.deviceName, id: deviceId }`. `buildAuthorizationHeader` and `createSdkApi` take the identity and pass it through. Every call site (constructor line 207, `login`, the three Quick Connect calls, `startSession`, `authorizationHeader`, `logout`) passes `this.client`. The constructor body's `createSdkApi(this.client, this.serverUrl, "fluster-unauthenticated")` can use `this.client`, because TypeScript assigns parameter properties before the constructor body runs.

`src/app/client-identity.ts` reads `__APP_VERSION__` and `navigator.userAgent`. It is part of the composition root (`src/app/`), which may import `src/features/settings/diagnostics.ts` (`.dependency-cruiser.cjs` restricts only `src/domain/`, the shell-neutral core, `src/components|features` → gateway, and `src/lib/` → app/features). Reusing `osName` keeps one platform parser.

### The other four fixes

Mechanical, as described under Acceptance 1, 3, 4, and 5. Keep the comment above `playbackInfo` (lines 799-804). Keep the `mediaSegments` comment; it already says calls are authenticated by header.

## Risks and out of scope

### Invariants and hard rules this task touches

- **I1 / hard rules "Send the same PlaybackInfo flags in the request body and the query string" and "Send the Fluster DeviceProfile with every PlaybackInfo request"**: the PlaybackInfo request changes its path. Body and query must stay byte-identical; the existing `toEqual` assertions guard them. Never add codec or container conditions to the DeviceProfile (not touched).
- **I4 / "Never log, persist, or display tokens…"; "Never put a token in a URL"**: the Authorization header's `Device` and `Version` fields change source. The token handling (`startSession`, `buildAuthorizationHeader`) must not move. The identity holds no secret. The redaction canary and error-strip tests keep their coverage through `resumeItems()`.
- **I5 / redirect refusal**: the merged wrapper must keep `isRedirectError` before `redactTransportError`, and `refuseRedirect` on every resolved response (status 0 or 3xx). `gateway-redirects.test.ts` guards it.
- **I8 / "Talk to Jellyfin only through `src/lib/jellyfin/gateway.ts`"**: no new caller of the transport; `client-identity.ts` does not talk to Jellyfin.
- **Shell-neutral core** (`.dependency-cruiser.cjs:23`, `tsconfig.core.json`): `src/lib/jellyfin/` must not read `__APP_VERSION__`, `navigator`, or `import.meta`. `pnpm typecheck:core` and `pnpm lint:boundaries` check it.
- **"Treat every new Tauri command as an architecture change"**: none is added; the device name comes from the user agent, not a native call.
- **Composition root** (DOMAINS.md "Dependency rules" 3): only `src/app/compose.ts` constructs the gateway; the identity is built there.
- **Device id stability** (`ARCHITECTURE.md:98`, "Never generate a new one per launch"): untouched and pinned.

### Risks

- A test key or assertion left at `"/Items/item/one/PlaybackInfo"` makes the fake transport return `undefined`; failures will look like "Jellyfin did not provide a play-session ID". Update all 13 occurrences in `gateway.test.ts` in the same commit.
- WebKitGTK's user agent on Wayland: the `X11; Linux` token is the WebKitGTK default on both X11 and Wayland (unverified on the dogfood desktop; the diagnostics row "OS" in Settings shows `osName` of the same string, so a wrong value would already show there). If it ever lacked `Linux`, the name would be `"Fluster"`, not a host or user name.
- A macOS user who signed in before this change will see the device renamed from "Fluster Linux" to "Fluster macOS" on the server at the next sign-in. Jellyfin keys devices by DeviceId, so it is the same entry renamed, not a second one (Jellyfin's `DeviceManager` behaviour is unverified here; the DeviceId pin is the check this task owns). macOS is not a shipped platform yet (`PRODUCT.md` §Platforms: "Next").
- The `UNIDENTIFIED_CLIENT` default could hide a forgotten argument in a future construction site. `compose.test.ts` covers production; the tripwire passes its own identity.

- Any change to `src-tauri/`, the header format, or Rust header fixtures.
- Using the computer's host name (`code-quality-triage.md:184`).
