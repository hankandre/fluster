- Domain: Server Connection & Identity (the task's `domain`). The change also touches Security & Redaction (the token boundary, redirects, the canary) and every domain that calls the gateway (Catalog, Playback Negotiation, Playstate Reporting), because every request changes how it leaves the core.

## Goal

Make the gateway reach the server only through a `Transport` port shaped as decision 0005 says, so the same core runs over Kotlin's client on the TV (T3-05) and over a reference adapter in Node.

- The gateway stops holding the token. It holds an opaque session id and calls `signIn`, `request` and `endSession`.
- The token, the header builder and `redirect: "manual"` move into one reference adapter, `packages/core/src/adapters/fetch-transport.ts`, which stands in for Kotlin in Node tests and the tripwire.
- axios and `@jellyfin/sdk` leave the repository.
- What the server receives does not change: the same paths, the same query pairs in the same order, the same JSON bodies, the same header value.

## The port

New file `packages/core/src/ports/transport.ts`. It is the core-side mirror of decision 0005's native session surface. Exact shapes are this spec's to set (0005, "The seam": "the exact shapes belong to the task specs").

```ts
// Opaque: made by the transport at sign-in. Not derived from the token; means nothing to the server.
export type SessionId = string;
export type TransportMethod = "GET" | "POST" | "DELETE";
export type QueryPair = readonly [name: string, value: string];

// After sign-in a request names its session. Before sign-in it names the server and the DeviceId
// to put in the tokenless header, and may use only PRE_SIGN_IN_ROUTES.
export type TransportTarget =
  | { readonly session: SessionId }
  | { readonly server: string; readonly deviceId: string };

export interface TransportRequest {
  readonly target: TransportTarget;
  readonly method: TransportMethod;
  readonly path: string;                    // starts with "/", no "?" and no "#"
  readonly query?: readonly QueryPair[];    // decoded pairs, in order; the transport encodes them
  readonly body?: unknown;                  // a JSON value; absent means no body
  readonly timeoutMs: number;
  readonly signal?: AbortSignal;
}

export interface TransportResponse {
  readonly status: number;                  // 200-299 or 400-599; a redirect never comes back as a response
  readonly body: unknown;                   // the parsed JSON, or undefined when empty or not JSON
}

export type SignInCredential =
  | { readonly kind: "password"; readonly username: string; readonly password: string }
  | { readonly kind: "quick-connect"; readonly secret: string };

export interface SignInRequest {
  readonly server: string;
  readonly deviceId: string;
  readonly credential: SignInCredential;
  readonly timeoutMs: number;
  readonly signal?: AbortSignal;
}

export interface SignInResult {
  readonly session: SessionId;
  readonly userId: string;
  readonly userName?: string;
  readonly serverId?: string;
}

export interface Transport {
  signIn(request: SignInRequest): Promise<SignInResult>;
  request(request: TransportRequest): Promise<TransportResponse>;
  // Always ends the session locally. Rejects only to report that the server logout failed.
  endSession(session: SessionId, options: { readonly timeoutMs: number }): Promise<void>;
}

export const PRE_SIGN_IN_ROUTES = [
  "GET /System/Info/Public",
  "GET /QuickConnect/Enabled",
  "POST /QuickConnect/Initiate",
  "GET /QuickConnect/Connect",
] as const;

export type TransportErrorCode =
  | "network" | "timeout" | "redirect" | "cancelled" | "refused" | "unexpected-response" | "status";

// The only error a transport may reject with. The message is fixed text per code: no URL, header or body.
export class TransportError extends Error {
  constructor(readonly code: TransportErrorCode, readonly status?: number);
}
```

Rules of the port, which the reference adapter implements and T3-05's Kotlin adapter must match:

- No header and no absolute URL cross it. `path` is appended to the server URL the session was signed in to (or to `target.server` before sign-in).
- `server` is the gateway's normalized server URL: scheme, host, port and any base path, no trailing slash, no query, no user info (`normalizeServerUrl`). Decision 0005 says "origin"; a reverse-proxy base path such as `https://media.test/jellyfin` must survive (`gateway.test.ts:132-150`), so the port carries the base URL and the origin pin is that URL's origin.
- A 3xx answer or a status of 0 rejects with `TransportError("redirect")`. It is never followed and never returned.
- A 4xx or 5xx answer from `request` resolves with its status; the gateway raises (below). A 4xx or 5xx answer to `signIn` or `endSession` rejects with `TransportError("status", status)`, because their bodies never cross.
- An aborted `signal` rejects with `TransportError("cancelled")`, whose `name` is `"AbortError"` so existing `AbortError` checks keep working. A timeout rejects with `"timeout"`.
- A pre-sign-in target with a route outside `PRE_SIGN_IN_ROUTES`, an unknown session, a path that does not start with `/` or that holds `?` or `#`, rejects with `"refused"` before any request is sent.
- A request whose query holds a credential parameter name (`isCredentialQueryName` in `jellyfin/credential-query.ts`: `ApiKey`, `api_key`, `access_token`, `token`, `X-Emby-Token`, `ApiToken`, `AccessToken`, any case), or whose path or query holds the session's token value, rejects with `"refused"` before it is sent (decision 0005: "any URL with a credential parameter or the token value refused"). The Quick Connect poll's `secret` is not on that list, so `GET /QuickConnect/Connect?secret=` passes; the secret is not the access token (`gateway.ts:335-336`).
- `signIn` returns no token and no response body. A sign-in answer without `AccessToken` or `User.Id` rejects with `"unexpected-response"`.
- Before a response body crosses, the transport replaces every occurrence of the session's token value, as written and percent-encoded, with a fixed marker (decision 0005, "The seam").
- The reference adapter keeps its sessions in an ECMAScript `#private` field, not a TypeScript `private` member (an ordinary property at run time), so a deep walk of the gateway (which holds the transport) that follows own properties, Maps and Sets cannot reach the token.
- `restoreSessions` and the `sessionEnded` event are not on the core port yet: no core code calls them until T4-05, and an uncalled port method cannot be tested here (D2).

### Decision log

- **D1. The port mirrors decision 0005, not axios.** A generic `request` that takes headers would keep the token in the gateway and contradict acceptance item 1 and 0005 ("accepts no header and no absolute URL"). So sign-in is its own method and the token lives behind the port.
- **D2. Three methods now.** `signIn`, `request`, `endSession` are what the gateway calls. `restoreSessions` and `sessionEnded` belong to T4-05 (restore, a confirmed 401) and T3-05; adding them here would be untested surface. The implementer appends a `tasks/backlog.jsonl` line so T4-05's spec adds them to the port and gives the gateway a way to adopt a restored session.
- **D3. Holes in 0005's `request` row, filled here.**
  - The pre-sign-in target carries a DeviceId, because Jellyfin binds a Quick Connect secret to the DeviceId sent with Initiate (`gateway.ts:76-80`), and Initiate, Connect and the sign-in must send the same one.
  - `GET /QuickConnect/Enabled` joins the fixed pre-sign-in paths; the gateway calls it before any session exists (`gateway.ts:315`). `docs/security.md` and decision 0005 (a dated amendment) are updated to say so.
  - The port carries the server's base URL, not only its origin (see "The port").
  - 4xx and 5xx come back from `request` as a status, and the core raises, because the core "parses every response" (0005) and two calls treat 404 as an answer.
  - A body that is empty or not JSON crosses as `undefined`, so the gateway's existing shape checks give their existing plain messages (`unexpected-response`) and no parser text reaches an error.
- **D4. Who encodes.** The gateway gives decoded pairs in order; the transport percent-encodes. Acceptance item 5 says "query strings unchanged", read as the string, so `FetchTransport` reproduces axios's encoding byte for byte (`encodeURIComponent`, with `:`, `$` and `,` left bare and a space written as `+`), and the golden records and compares the raw query string as well as the decoded pairs. The port's contract for other transports stays "decoded pairs in order": the server decodes every encoding to the same pairs, and OkHttp's bytes will differ, which T3-05's wire test treats as decoded pairs.
- **D5. `trickplayTile` is removed.** It needs a binary body, which 0005's `request` does not carry ("What would change this to A: … it starts to need headers, absolute URLs or streaming bodies"), and its only consumer was the desktop player.
