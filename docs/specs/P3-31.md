## Goal

Every native command returns `Result<_, String>` (`src-tauri/src/commands.rs`), so Tauri's `invoke` rejects with a bare string. The app reads only `Error`s. A failed `launch_playback` therefore reaches the error panel as "Something went wrong." (`src/features/player/use-playback-session.ts:92-94`), and `redactError` passes the string through unredacted (`src/lib/redact.ts:44`). This task makes the adapter turn every string rejection into an `Error` that carries the string. Every reader then shares one way to read a failure, and `redactError` redacts strings too. The viewer sees the native reason, filtered by `safeReason`, and no token, authenticated URL, or file path reaches the screen or the session state.

This is the TypeScript half of problem 2 in `docs/plans/proposals/code-quality-triage.md`. P2-11 (typed native errors) is the Rust half and is out of scope.

## Approach

One milestone, one commit (for example `fix(player): show the native player's reason when it fails (P3-31)`).

1. **Adapter.** In `native-player.ts`:
   ```ts
   function toNativeError(error: unknown): unknown {
     return typeof error === "string" ? new Error(error) : error;
   }
   async function call<T>(command: string, args?: Record<string, unknown>): Promise<T> {
     try { return await invoke<T>(command, args); } catch (error) { throw toNativeError(error); }
   }
   ```
   `launch` keeps its `try`/`catch`, checks the prefix on the raw value, and otherwise throws `toNativeError(error)`. The adapter does not redact. The acceptance requires the message to equal the string, and redaction happens downstream: `coordinator.ts:257` for launch, and `errorReason` for everything else. The comment above `UNSAFE_CONVERSION_PREFIX` stays.
2. **Redaction.** `redactError` gets `if (typeof error === "string") return redactText(error);` as its first line. Update the comment above it so it says that strings come back redacted. `redactedErrorMessage` sits next to it. `transport-error.ts:63` calls `redactError` and so also redacts strings now. That is the intended effect, and its behaviour on objects does not change.
3. **One reader.** `errorReason` lives in `safe-reason.ts` because `safeReason` is "the only way a player failure reason reaches the screen". `src/components/` already imports from `src/features/player/`, so the import is allowed. Each caller supplies only its fallback copy. The fallback "Something went wrong." is existing copy, so no new text is added.
4. **State holds the filtered reason.** `failureAction` now stores `safeReason` output, not only `redactText` output, so no address or path is held in state (acceptance 5). The display applies `safeReason` again (`playbackErrorCopy`, `CommandErrorPanel`). `safeReason` is not idempotent in general: a credential pair closed by `)` (for example `(Token="…")`) gives `(Token=[redacted])` on the first pass and `(Token=[redacted]` on the second, because the credential pattern takes the closing bracket. Nothing leaks, and today's `redactText` then `safeReason` does the same, so it is not a regression. It is stable for `[address]`, `[path]`, and the 300-character cap. Tests do not assert exact panel text for strings that end a credential pair with `)`. The existing assertion `findByText(/\[address\]/)` (line 733) still holds.
5. **Empty messages.** An `Error` with an empty message used to put `""` into state, and a falsy `sessionError` showed no panel. It now shows the fallback copy. This is a small visible fix and is intended; the PR names it under user impact (spec-check note 5). The coordinator's failed stop likewise gives its fixed copy, not an empty message, for an `Error` with no text.
6. Run the validation commands, fill in `evidence`, and open the PR. The PR calls out the redaction path (I4) and the fact that no Tauri command changes.

## Risks and out of scope

- **Risk: double filtering.** `safeReason` runs twice on the session error. It is stable for addresses, paths, and the cap but can drop a `)` after a redacted credential (see Approach 4); nothing leaks. `safe-reason.test.ts` asserts `safeReason(safeReason(NASTY_REASON)) === safeReason(NASTY_REASON)` and the same for the capped string.
- **Risk: losing the refusal.** If `launch` converted to `Error` before the prefix check, the unsafe-conversion refusal would turn into a generic failure that shows Rust's text. The unchanged refusal test guards this.
- **Risk: a view that relied on raw `String(error)`.** `NativeVideoSurface` and `PlayerView` now store `safeReason` output, so addresses and paths in surface or command failures show as `[address]` and `[path]` earlier, in state rather than only at display. The visible text is the same, because `CommandErrorPanel` already applied `safeReason`.
- **Risk: Tauri rejection shapes.** Tauri 2's `invoke` rejects with the command's serialized `Err` value. For `Result<_, String>` that is a string, as the triage's problem 2 and the existing `native-player.test.ts` cases record. Whether Tauri rejects argument-deserialization or missing-command failures with a string is unverified; `toNativeError` covers them either way, and other shapes pass through unchanged.
- **Out of scope:**
  - Typed native errors and any Rust change (P2-11).
  - Rejections from `listen` in `subscribe`.
  - Moving `PlayerView.tsx` (P2-09).
  - Splitting `use-playback-session.ts` (P2-13).
  - The error panel's copy and design.
