## Goal

Make every signed-out and signed-in screen usable in a 10-foot form on a 1920×1080 canvas with a D-pad, OK, and Back only:

- a `data-form="tv"` mode that a browser development flag turns on (`?form=tv`). The TV shell sets the same attribute later;
- the DESIGN.md TV tokens and the 5% title-safe insets on every screen, with no rendered text under 22 px;
- arrow-key focus movement that reaches every control, including the nav (a hidden tab row), dialogs, sign-in fields, and the player chrome (Q17 A);
- Escape and Backspace as Back, on both forms;
- the TV-only layouts DESIGN.md already describes: the season's episodes as a horizontal row with the overview under the focused card (§7.6), centred player transport with no volume control (§7.14), and pickers as right-side sheets (§7.10);
- Playwright keyboard-only journeys in the TV form that cover every screen, and TV captures in the screenshot harness.

Desktop behaviour stays the same, with four exceptions that DESIGN.md §9 already requires on both forms: Backspace acts as Back; Escape (or Backspace) on a non-root screen goes back; Up from the first content row reaches the nav; Down from the nav enters the page.

## Approach

### 1. The development flag (item 1)

- `applyFormFlag(search: string, root: HTMLElement): void` in `src/features/shared/tv-form.ts`. If `new URLSearchParams(search).get("form") === "tv"`, set `root.dataset.form = "tv"`. Otherwise do nothing: never delete the attribute, because the TV shell (later) and test init scripts set it themselves.
- Call it from `src/main.tsx` inside `if (import.meta.env.DEV)`. Vite drops the branch from production builds, as it does for the gallery (`App.tsx:20-24`). Do not add it to `scripts/check-no-test-engine.sh`; the flag is harmless in a build, and dropping it is a side effect, not a rule.
- The flag sits in the query string before the hash (`/?form=tv#/next/home`). Hash navigation keeps it, and so do `location.replace("#/next/home")` (`App.tsx:46`) and the sign-in redirects. "Togglable" means: load with the flag for TV, load without it for desktop. There is no in-app switch and no storage.
- `isTvForm()` stays as is (read at call time). Components that render differently in the TV form use `useTvForm()`, so a test that flips the attribute at runtime (as `player.spec.ts:327` does) re-renders them.

### 2. Tokens and title-safe insets (items 1, 3, 5)

- TV block (`tokens.css:139-158`): add `--type-mono: 500 0.9375rem / 1.3 var(--font-mono);`. Leave the remaining values as they are; they already match DESIGN.md §6 and §8.
- Apply `--safe-x` and `--safe-y`. On desktop they are `var(--gutter)` and `0px`, so desktop layout does not move. In the TV form:
  - nav: `padding-block-start: var(--safe-y)`, inline padding `var(--safe-x)` (the nav row stays `--nav-h` tall below the inset);
  - page content: `--gutter` is already `var(--safe-x)` in the TV form, so rows, grids, headers, and the toolbar inherit it. Add `padding-block-end: var(--safe-y)` to `.app-content` and to `main` on routes without the nav;
  - sign-in card, `Notice`, `EmptyState`: centred within the inset;
  - `Dialog` and `Toast`: `inset` uses the safe values;
  - player: top bar at `top: var(--safe-y)`, control row and scrubber above `var(--safe-y)` from the bottom, inline `var(--safe-x)`. `--player-prompt-inset` and `--player-prompt-inset-chrome` add `var(--safe-y)`. Skip, Up Next, the OSD pill, and sheets stay inside the inset;
  - artwork (hero art, ambient backdrop, detail backdrop, player video) keeps bleeding to the edges (§6: "except artwork bleeding to the edges").
- Fix any text below 22 px that `expectNoSmallText` finds by moving it to a token, not by adding a literal.

### 3. Focus model, nav, and initial focus (items 2, 6)

- **Up to the nav (both forms).** In `moveToAdjacentRow` (`roving-focus.ts:62-76`), when `direction === -1` and there is no row above, focus the nav's Tab stop: `document.querySelector('nav[aria-label="Main"] [data-roving-item][tabindex="0"]')`. Return `true` if it moved. The nav lives outside `main`, so the current row search does not change.
- **Up from the search field (both forms).** `search-box.tsx:108-112` handles ArrowUp: with no hints it returns, and with hints it opens the suggestion list. Change it: when the list is open, Up moves within it as today; when the list is closed (with or without hints, since hints stay non-empty after editing), call `moveToAdjacentRow(row, input, -1)` on the field's `data-spatial-row` and `preventDefault()`, which reaches the nav. Down from the closed field opens the list as today. Test in `search-box.test.tsx`.
- **Down from the nav (both forms).** `AppNav` handles ArrowDown: focus the first `[data-spatial-row]` in the page's `main` that has items, at its Tab stop (`[tabindex="0"]`, else its first item). If there is none (for example, Settings, whose section list is a column), fall through to the TV fallback (Approach 5). On desktop the fallback is off, so ArrowDown in the nav does nothing there, as today.
- **TV tab row.** In `AppShell`, in the TV form: `hidden` is true while focus is inside `.app-content`, and false while focus is in the header or on `body`. Replace the TV branch at `app-shell.tsx:39` (which only keeps the nav visible) with a `focusin` listener that drives `hidden` in the TV form. Scroll-driven hiding stays desktop only. The nav keeps `<nav aria-label="Main">` with links and `aria-current="page"`. "Tab row" describes its look and place (§6), not a `role="tablist"`, because the entries are navigation links. The hidden nav must not cover focused content (§9, WCAG 2.4.11): it slides out of view and does not take space.

### 4. Back: Escape and Backspace (items 2, 4)

- **`useBackspaceAsEscape`** (mounted once in `App`). It is a capture-phase `keydown` listener on `document`. On `Backspace` with no modifier, not `isComposing`, not `defaultPrevented`, where the target is not a text field (`TEXT_FIELDS`, `use-escape-key.ts:3`) and not contenteditable, it calls `preventDefault()` and `stopPropagation()`. Then it dispatches `new KeyboardEvent("keydown", { key: "Escape", code: "Escape", bubbles: true, cancelable: true })` on the original target. Every Escape handler then runs unchanged. That covers Dialog (`dialog.tsx:66-95`), Picker (`picker.tsx:166`), PlayerSheet, Settings drill-in (`settings.tsx:123`), the search box, the player keymap (`use-player-keys.ts`), and `useBackKey`. Do not add Backspace to `player-keymap.ts`; the alias reaches it. Range inputs (the scrubber) are not text fields, so Backspace there leaves the player as Escape does.
- **`useBackKey`** (mounted in `NavShell`, so only signed-in screens with the nav). It is a bubble-phase `keydown` listener for `Escape` registered on `window`, so it always runs after every `document` handler (listener order between `NavShell` and page effects is otherwise not deterministic). It skips when `defaultPrevented`, when the target is a text field or editable, or when a modal layer is open (`[role="dialog"][aria-modal="true"], [role="alertdialog"], .ui-picker-list[role="listbox"]`, plus the TV picker sheet's class; use the selectors the primitives render). After it acts, it calls `preventDefault()`, so a later `useEscapeKey` handler skips. `useEscapeKey` gains an `enabled` flag, and Settings calls `preventDefault()` only when it closes a section (`useEscapeKey(handler, { enabled: open })`), so Escape on a root tab with no open section reaches `useBackKey`. Tests: TV, Settings with no section open, Escape focuses the nav entry; desktop, a compact open section, Escape closes it and does not move focus to the nav. Then:
  - **Non-root screens** (item, series, collection, not found): go back. If this tab has navigated inside the app (a module-level flag set on the first in-app `hashchange` after load), call `history.back()`. Otherwise `location.hash = "#/next/home"`. Both forms (§9: "Back or Escape closes the topmost layer … then screen (browser history)").
  - **Root tabs, desktop:** do nothing, so `nav.spec.ts:62-69` holds.
  - **Root tabs, TV:** if focus is not in the nav, focus the nav's current entry. If it already is, do nothing. "Back on Home exits (after a confirmation in the shell)" belongs to the TV shell, which does not exist yet; record that in the PR's untested gates.
- **Sign-in steps** (no nav): in `quick-connect-step.tsx` and `password-step.tsx`, Escape outside a text field (via `useEscapeKey`) does what the step's "Change server" does. Both forms. The server step has no Back. Escape inside the unencrypted dialog still cancels the dialog (the dialog handles it first and prevents default).
- The player keeps its own Escape chain (`use-player-keys.ts`: sheet, then fullscreen, then leave). `useBackKey` is not mounted there.

### 5. TV arrow fallback (item 2)

Roving rows and spatial rows already move focus on most screens. A few places have no arrow path: sign-in fields and buttons, dialog actions, playback notices, the Settings row-to-button path, the library `h1` down to the toolbar, the not-found page, and the series overview's More button. Without Tab, the TV form needs one.

- `useTvArrowFallback` (mounted in `App`, active only while `isTvForm()`). It is a bubble-phase `keydown` listener on `document` for the four arrows. It runs after React's handlers, so any roving list, Picker, slider, or search box that handled the key has already called `preventDefault()`.
- It skips when `defaultPrevented` or a modifier is held. It skips Left and Right when the target is a text field (the caret owns them); Up and Down from a single-line field are handled. It also skips when the target is inside `[data-tv-own-arrows]`, which the player surface sets (Approach 8).
- Scope: the topmost open modal layer (dialog, alertdialog, `.ui-picker-list[role="listbox"]` or the TV picker sheet), else `document`. Candidates: focusable elements (`a[href], button:not([disabled]), input:not([disabled]), [tabindex]:not([tabindex="-1"]), [data-roving-item]`) that are rendered, not `inert`, not inside `aria-hidden="true"`, and not inside the TV-hidden nav (Up into the nav goes through Approach 3 only).
- Choice: among candidates whose centre lies in the arrow's half-plane from the current element's centre, pick the smallest `primaryDistance + 2 × perpendicularDistance` (edge to edge on the primary axis). Ties go to DOM order. Focus it, scroll it into view (`block: "nearest"`), and `preventDefault()`.
- Only one geometric rule exists in the app, and only in the TV form. Desktop keyboard behaviour is untouched.
