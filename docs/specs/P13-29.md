## Goal

Today the Audio and Subtitles lists in the player's `TrackPanel` show one line per track: mpv's title for direct play, or Jellyfin's `DisplayTitle` for a converted session (`src/features/player/chrome/track-options.ts`, `fromPlayer` and `fromSource`). `OptionList` already supports a second line (`description`, `src/features/shared/ui/option-list.tsx:9`), but the panel never sets it. Forced, hearing-impaired, default, and external tracks are not marked, so two English subtitle tracks look the same. The scrubber is an `<input type="range">` with no `aria-valuetext` (`src/features/player/chrome/scrubber.tsx`), so a screen reader reads a raw number of seconds such as "2479". The volume slider (`transport-controls.tsx:136-148`) has the same problem. In the browser development engine the Audio list is empty (`browser-player.ts:141` reports `tracks: []`), and the panel shows only the heading.

After this task:

1. Every track row has the two-line label of `DESIGN.md` §7.10. Direct play and converted sessions use the same format, built from the playback plan's stream facts.
2. The scrubber reads as a time ("41 minutes 19 seconds of 2 hours 3 minutes"), and the volume slider reads as a percentage ("80%").
3. An empty Audio list shows a sentence instead of an empty listbox.

## Approach

### 1. Stream facts on the plan (gateway, domain)

In `createPlaybackPlan`, extend the per-stream object:

```ts
...(track.Title ? { title: track.Title } : {}),
...(typeof track.Channels === "number" && track.Channels > 0 ? { channels: track.Channels } : {}),
...(track.IsDefault ? { isDefault: true } : {}),
...(track.IsForced ? { isForced: true } : {}),
...(track.IsHearingImpaired ? { isHearingImpaired: true } : {}),
```

Absent means false or unknown. `displayTitle`, `codec`, `language`, `external`, and `deliveryUrl` stay as they are. Rust deserializes `MediaTrack` without `deny_unknown_fields` (`src-tauri/src/model.rs:4-17`), so it ignores the new fields.

### 2. One label for every row (`track-label.ts`)

`TrackFacts = { kind: "Audio" | "Subtitle"; language?: string; title?: string; fallbackTitle: string; codec?: string; channels?: number; isDefault: boolean; isForced: boolean; isHearingImpaired: boolean; external: boolean }`.

- `trackFactsFromPlan(track)`: every field from the `MediaTrack`, with `fallbackTitle = track.displayTitle`.
- `trackFactsFromPlayer(track)` (an mpv track with no plan match): `language`, `external`, and `fallbackTitle = track.title`. Every other field is absent or false.

`trackRow(facts)`:

- **Name (line 1).** `DESIGN.md` §7.10 draws the name as the language ("English · TrueHD 7.1"). Let `lang` be `languageName(language)` when the language is set and is not `und`.
  - If `title` is set and contains `lang` (case-insensitive), the name is `title` (for example "English stereo", "English SDH").
  - If both are set and the title does not contain `lang`, the name is `` `${lang} · ${title}` `` (for example "English · Commentary").
  - With only `lang`, the name is `lang`. With only `title`, the name is `title`.
  - With neither, the name is `fallbackTitle` (mpv's title, Jellyfin's `DisplayTitle`, or Rust's "Track N").
  - Jellyfin's `DisplayTitle` is not used as the name when facts exist, because it already joins codec, channels, and "Default" (fixture: "English stereo - AAC - Default"), which would repeat line 2.
- **Detail (line 2).** These parts, joined with " · ", leaving out any that are absent:
  1. Format. For audio, `[codecName(codec), channelLabel(channels)].join(" ")`, for example "TrueHD 7.1", "AAC Stereo", or "AC-3 5.1". For subtitles, `codecName(codec)`, for example "SRT" or "PGS".
  2. "forced", then "hard of hearing", then "default", then "external", each when its flag is true.

  The flag order is this spec's own ("forced · hard of hearing · default · external"); Detail's `subtitleLabel` orders them "external · forced · default", so the order does not match. With no parts at all, `detail` is undefined and the row has one line.

The label text is plain data and never includes `deliveryUrl`, an index, or an ID.

### 3. Rows (`track-options.ts`)

- **Direct play** (`converted` undefined): for each `PlayerTrack` of the kind, find `planTracks?.find(t => t.index === track.jellyfinIndex && t.type === track.type)`. If one matches, use `trackFactsFromPlan`. Otherwise use `trackFactsFromPlayer`. `value` stays `String(playerId)`.
- **Converted**: for each `SourceTrackOption`, find the plan track by `jellyfinIndex` and use `trackFactsFromPlan`. If none matches (should not happen), use `{ fallbackTitle: option.title }`. `value` stays `String(jellyfinIndex)`.
- The `OFF_ROW`, `trackIdOf`, `nextSubtitle`, selection logic, and `ConvertedTracks` shape do not change. `use-player-keys.ts` (the `c` OSD copy) is not changed (see out of scope).

### 4. Empty Audio list (`track-panel.tsx`)

When `audioList.options.length === 0`, render `<p className="player-sheet-empty">` (the class uses `--text-2` and `--type-body` tokens; add it to `player.css` only if no existing class fits) instead of the `OptionList`:

- `snapshot` undefined: "Loading tracks…"
- otherwise: "No audio tracks to choose from."

The sentence is plain text, not a live region, and not focusable. With no audio rows, `PlayerSheet`'s default initial focus finds the subtitle list's tab stop. The Subtitles list always has "Subtitles off", so it never needs the sentence. See open question 1 for the copy.

### 5. Accessible names of two-line rows (`option-list.tsx`)

When `description` is set, the row `<li>` gets `aria-label={`${label}, ${description}`}`. Nothing changes visually. Names become "English, AAC Stereo · default" and "Opening, 0:00". (Implementation note: the first draft used a visually hidden ", " span. jsdom computed "Opening,0:00" and Chromium "English , AAC Stereo · default", so neither matched the intended name. An `aria-label` gives the same exact name in both. The row content is the same two strings, so the label loses nothing.) `Picker` is not changed (out of scope).

### 6. Spoken time and volume

In `player-time.ts`:

- `spokenTime(value)`: floor to whole seconds. Join the non-zero units from "{h} hour(s)", "{m} minute(s)", "{s} second(s)" with spaces, using singular for 1. Zero gives "0 seconds", and a non-finite value gives undefined.
- `spokenDuration(value)`: the same, but with seconds dropped once the value is a minute or more (floor). This matches the example "2 hours 3 minutes".
- `scrubberValueText(position, duration)`: `` `${spokenTime(position)} of ${spokenDuration(duration)}` `` when the duration is known and greater than 0, else `spokenTime(position)`.

The scrubber's input gets `aria-valuetext={scrubberValueText(Math.min(position, max), snapshot?.durationSeconds)}`. `position` already includes the pending `seekValue`, so a Left or Right press is read at the new time. The volume input gets `` aria-valuetext={`${Math.round(value)}%`} `` from the same value it shows. The TV form has no volume slider, so nothing changes there. The `aria-label`s stay "Playback position" and "Volume", so existing selectors keep working.

### 7. Gallery and visual capture

Add the gallery frame and the `88a-ui-gallery-track-panel` scenario (Files to touch), so the populated two-line rows are captured in the browser, where the dev engine reports no tracks and refuses conversions.

- **`MediaTrack` crosses to Rust.** The new fields go to `player_launch` inside the plan. Rust ignores unknown fields (checked above), and `cargo test` in `pnpm check` covers the existing launch tests. If a reviewer reads this as a change to the engine port, it is data only, with no Rust change.
- **Screen reader chatter.** A focused scrubber's `aria-valuetext` changes every second as playback runs. Some screen readers may read value changes on a focused slider. Today the raw number changes just as often, so this is no worse. Not tested on Orca, NVDA, or VoiceOver (untested gate, listed in the PR).
- **`Intl.DisplayNames` in WebKitGTK.** `languageName` relies on it mapping ISO 639-2/B codes ("fre", "ger"). This is verified in Node (`node -e` gave "French", "German") and already relied on by Detail. WebKitGTK is unverified (untested gate).
- **`IsHearingImpaired` on real servers.** It is present (false) in every recorded 10.11.7 and 12.4.0 fixture. Whether the dogfood server sets it true for SDH files is unverified (untested gate in the PR).
- **Name duplication.** A title like "English stereo" plus the detail "AAC Stereo" repeats "stereo". This is accepted: the title is the file author's.
- **Shared primitive change.** The `OptionList` separator also renames chapter rows ("Opening, 0:00"). Tests that match chapters by regex (`/Contact/`, `/^Opening/`) still pass.
