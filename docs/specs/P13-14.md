## Approach

### 1. Decisions

- **D1 (Hide), pending Open question 1, spec assumes option A.** Hide dismisses the card for the rest of this session and cancels autoplay; playback continues. Seeking out of and back into the end window does not bring the card back. At the end of the file, a dismissed countdown does not advance: `onLeave("eof")` goes to the series page (`leaveToSeries(detail.seriesId)`, where today's Cancel went), or to the item when there is no series id. Hide does not stop the session, report anything, or mark the episode played. If the human picks option B instead, `hide` keeps today's `cancel` body (stop, then series page), the reducer gets no `dismissed` state, and the only test changes are the button name.
- **D2 (OK and the card on TV).** Q19 A gives OK one meaning per moment: with Skip credits replaced by Up Next, OK while the chrome is hidden activates the visible Skip, else Play now on a visible card, else nothing. `n` is Play now on every form. Arrows waking the chrome on TV stay with P13-18 (Q17 A).
- **D3 (Skip credits with a next episode).** Q19 A, applied literally: when the next-episode lookup has a result, Outro segments are not offered as Skip at all, also after Hide. Intro segments are unaffected. Before the lookup resolves, an Outro may show Skip; at credits time the lookup has long settled.
- **D4 ("Never takes focus on desktop").** As today (DESIGN.md §7.15 "as today"): Skip never moves focus to itself and is not given focus by any code path, but it stays a normal button in the Tab order so pointer and Tab users can reach it. The existing e2e (`skipIntro.focus()` then Enter) keeps working. In the TV form it is also never focused; OK reaches it through the key handler.
- **D5 (Up Next card focus).** Unchanged: the card never takes focus by itself on either form (§11.5 needs a visible, focusable Hide, which it has). Focus in the card keeps the chrome up through the existing zone attribute.

### 2. `SkipButton`

```tsx
<button type="button" className="skip-button" onClick={() => onSkip(segment.endSeconds)}>
  <SkipForward aria-hidden="true" /> {LABELS[segment.kind]}
</button>
```

Labels stay "Skip intro" and "Skip credits". `PlayerView` computes `const skip = segments && snapshot ? activeSegment(segments, snapshot.positionSeconds) : undefined` and renders `<div className="player-skip" data-chrome-visible={visibility.visible} data-chrome-zone>` around it only when `skip` is set, so the fade-in animation runs on each appearance. Keep `onSkip` going through `execute(() => player.seek(...))` as today.

If Skip has focus when its segment ends (after Enter), the button unmounts and focus falls to `body`; the window key handler still works. Do not add focus management for this.

### 3. Position: moving with the chrome

`.player-skip` and `.player-prompt` are absolutely positioned at `right: var(--gutter)` and `bottom: var(--player-prompt-inset)`, `z-index: var(--z-prompt)`. With `[data-chrome-visible="true"]` the bottom becomes `var(--player-prompt-inset-chrome)`, which clears the control footer (scrubber plus control row plus padding). Animate with `transition: bottom var(--dur-base) var(--ease-out)`; `--dur-base` is `0ms` under reduced motion (`tokens.css:148`), so it jumps. Do not use `transform: translate` (reduced motion forbids translate; keeping one property avoids a second rule). When both exist, Skip and the card never show together for the same Outro (D3); a Skip intro and the card cannot coincide in practice, but if they do, the card stacks above Skip: `.player-prompt` adds `calc(var(--hit-min) + var(--space-3))` to its bottom when `.player-skip` is present (`:has()` is not needed; `PlayerView` sets `data-with-skip` on the prompt wrapper).

Measure `--player-prompt-inset-chrome` against the real footer at 1440×900 and 1920×1080 and set it so the e2e geometry check passes with at least `--space-3` of clearance. When a sheet is open, the prompt stays left of it: `.player-page:has(.player-sheet)` is not used; `PlayerView` sets `data-sheet-open` on both wrappers and CSS adds `var(--player-sheet-w)` to `right`, as `.player-controls[data-sheet-open]` does (`player.css:49`).

Look (§7.15): pill `--radius-pill`, `background: color-mix(in srgb, var(--text-1) 92%, transparent)`, `color: var(--on-light)`, `min-height: var(--hit-min)`, `padding-inline: var(--space-5)`, `font: var(--type-label)`, the shared focus ring, hover fill change over `--dur-quick`. Fade in with a `@keyframes` on opacity over `--dur-base`.

### 4. Keys

Keymap (`player-keymap.ts`, pure):

- `s` → `{ kind: "skip" }`, `n` → `{ kind: "play-next" }`. Uppercase works through the existing lower-casing. Not repeating.
- `Enter` → `{ kind: "ok" }`. The existing `targetKind` rules already return `undefined` for Enter on buttons, links, `summary`, list targets, and text fields, so OK only reaches the handler when focus is on the page, the video, or a slider. Not repeating.

Handler (`use-player-keys.ts`), inside the existing `switch`:

- `skip`: `if (skipTo !== undefined) void execute(() => player.seek(skipTo))`.
- `play-next`: `onPlayNext?.()`.
- `ok`: `if (!isTvForm() || chromeVisible) break;` then skip if `skipTo` is set, else `onPlayNext?.()`.

The handler calls `preventDefault()` for every mapped key before the switch (existing line). For Enter on the page or a slider that is harmless: neither has its own Enter action. A test covers Enter on a slider doing nothing on desktop.

No OSD message for skip or play-next: the seek and the route change are their own feedback, and §7.14's OSD list does not include them.

### 5. `UpNextCard`

Markup:

```tsx
<aside className="up-next-card" aria-label="Up next" data-paused={paused || undefined}
       style={{ "--up-next-seconds": `${totalSeconds}s` } as CSSProperties}>
  {stillSrc || next.image ? <div className="up-next-still" data-fit={poster ? "contain" : "cover"}><CardImage image={next.image} src={stillSrc} /></div> : null}
  <p className="up-next-meta">{next.label ? `Up next · ${next.label}` : "Up next"}</p>
  <p className="up-next-title">{next.title}</p>
  <p className="up-next-countdown">{countdownText(secondsLeft)}</p>
  <span className="visually-hidden" role="status">{announced}</span>
  <div className="up-next-actions">
    <Button variant="primary" icon={<Play aria-hidden="true" />} onClick={onPlayNow}>
      <span className="up-next-fill" aria-hidden="true" />Play now
    </Button>
    <Button variant="quiet" onClick={onHide}>Hide</Button>
  </div>
</aside>
```

- `poster` is `next.image?.itemId !== next.id` (the series Primary fallback); a poster is shown whole, centred on `--surface-2`, like Q27 A in search. `CardImage` already shows the blurhash then the image.
- `countdownText(n)`: "Playing in 1 second", else "Playing in {n} seconds" (§5 wording).
- `upNextAnnouncement(title, n)`: `n > 5` gives "Up next: {title}, playing in 10 seconds" (fixed at `totalSeconds`), `n <= 5` gives "Up next: {title}, playing in 5 seconds". So the text changes once per countdown. `announced` starts as `""` and is set in a `useEffect` on `[upNextAnnouncement(...)]`, so the region exists before its first text and screen readers announce the appearance.
- Fill: `.up-next-fill` is absolutely positioned inside the primary button (the button gets `position: relative; overflow: hidden; isolation: isolate` through `.up-next-actions .ui-button--primary`), `background: color-mix(in srgb, var(--on-light) 14%, transparent)`, `transform-origin: left`, `animation: up-next-fill var(--up-next-seconds) linear forwards` from `scaleX(0)` to `scaleX(1)`; `[data-paused] .up-next-fill { animation-play-state: paused }`. The card mounts when the countdown starts at 10 and unmounts when it ends, so the animation restarts with each countdown. The button text sits above the fill (`z-index` within the button) and keeps `--on-light` contrast 4.5:1 or more over the fill; check it in the review.
- Reduced motion: `@media (prefers-reduced-motion: reduce) { .up-next-fill { display: none } .up-next-countdown { position: static; ... visible } }`; default `.up-next-countdown` uses the visually-hidden pattern and `aria-hidden="true"` is not set (it is not live, so it is read only on demand).
- Look: `width: var(--up-next-w)` (max `calc(100vw - 2 * var(--gutter))`), `background: color-mix(in srgb, var(--surface-1) 96%, transparent)`, `box-shadow: var(--shadow-sheet)`, `border-radius: var(--radius-sheet)`, padding `--space-4`, still at `--radius-art` with `aspect-ratio: 16 / 9`, meta in `--type-meta` and `--text-2`, title in `--type-heading` clamped to two lines, actions in a row with `--space-3` gap. No `backdrop-filter`.

`index.tsx` passes `stillSrc` only when `next.image` is set.
