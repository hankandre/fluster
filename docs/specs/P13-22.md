## Goal

Build the `ChapterList` sheet that DESIGN.md §7.14 deferred. A **Chapters** button in the player's control row opens a right side sheet. It lists every chapter with its name, its start time, and a trickplay picture at the chapter start when the version has trickplay. Enter on a row seeks to that chapter. Escape closes the sheet and returns focus to the button. The button only appears when the item has chapters. The sheet works with arrows, Enter, and Escape alone on desktop and in the TV form, inside the title-safe insets.

## Approach

1. **Data.** `PlayerView` already receives `chapters?: SeekChapter[]` (sorted, positive starts, fallback names "Chapter N" from `toChapters`, `src/lib/jellyfin/item-detail.ts:137`) and `seekPreview?` from `useSeekPreview`. No new prop reaches `PlayerView` from `index.tsx`. Chapters belong to the item and trickplay to the chosen version, and `useSeekPreview` already picks the version by `route.mediaSourceId`.
2. **Sheet.** `ChapterList` wraps `PlayerSheet` with `label="Chapters"` and `title="Chapters"`. Its body is a single `OptionList` with `label="Chapter"`, options `chapters.map((c, i) => ({ value: String(i), label: c.name, description: clock(c.startSeconds), media: picture?.(c.startSeconds, thumbWidth) }))`, and `value = String(index of chapterAt(chapters, positionSeconds))` (undefined before the first chapter). `OptionList` puts the selected row in the tab order, so `PlayerSheet`'s initial focus (the first focusable in the body) lands on the current chapter, and `focus()` scrolls it into view. The check icon and `aria-selected` mark the current chapter as playback moves.
3. **Thumbnail width.** Read `--chapter-thumb-w` once in a layout effect (`getComputedStyle(sheet).getPropertyValue`, parsed to px, the same idea as `ScrubPreview` measuring its frame) and pass it as `frameWidth`, so `thumbnailStyle` scales the tile cell. If measuring is unavailable (jsdom returns empty), fall back to the unscaled cell. A test covers the fallback.
4. **Seek.** `onSeek(index)` → `const target = durationSeconds ? Math.min(start, durationSeconds) : start; execute(() => player.seek(target))`. There is no OSD line, because the sheet itself shows the result. This matches TrackPanel choices, which post no OSD.
5. **After Enter.** Settled (Q1 A): the sheet closes after the seek and focus returns to the Chapters button through `PlayerSheet`'s cleanup. `choose` calls `onSeek` then `onClose`.
6. **Keys.** No new shortcut. DESIGN.md §9 is unchanged. Escape keeps the "sheet, then fullscreen, then player" order. `toggleSheet("chapters")` closes any other sheet, so only one sheet is ever open. A failed session already clears `sheet`.
7. **Disabled state.** Chapters is `disabled={!snapshot}`, like Audio & Subtitles, because a seek needs a snapshot.
8. **TV.** No change to `useTvChromeFocus` or `player-keymap.ts`. The TV `control-end` order is Chapters, Audio & Subtitles, Info (settled, Q2 A).

Risks:

- Focus return after a mouse click: `PlayerSheet` restores focus to the element that was focused when the sheet opened. Chromium focuses a clicked button. WebKit on macOS does not, and WebKitGTK behaviour is unverified. After a mouse click in the desktop app, Escape may therefore leave focus on the player region instead of the button. The acceptance item is met for keyboard and remote, which are the tested paths. This is an untested gate to list in the PR.
- Many chapters (for example 50 or more) load several trickplay tiles at once when the sheet opens. `TileCache` loads each tile once and caches it for the session, which is acceptable. There is no virtualisation.
- A chapter whose start is past the file's duration (bad metadata) is still listed. Seeking clamps it to the duration.
- Untested gates for the PR: Wayland, GPU, and AppImage over real video. A real Jellyfin chapter set on the dogfood server (read the URL from `FLUSTER_DOGFOOD_SERVER`) is not run in CI.
