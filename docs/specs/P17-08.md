## Goal

A title's page (a movie or an episode) gains an audio Picker beside the version Picker when the chosen version has two or more audio tracks. It opens on the track in the account's preferred audio language, lists that language first and the rest by language name, and Play, Resume, and Start over start with the track it shows. The pick is carried to Playback Negotiation as `AudioStreamIndex`, never costs a direct play, and is forgotten when the viewer leaves the page.

What does not change: a play with no pick sends exactly today's requests; the "File and streams" audio list; the player's menus; the DeviceProfile; the source decision rules; the Rust engine and its commands.

### 2. Negotiation: the guard (`src/lib/jellyfin/gateway.ts`)

`PlaybackPlanOptions` gains:

```ts
// Set for a session that started from a viewer's audio pick. An answer that names the audio index is
// used only if it direct plays, or if the same request without the index does not (I1). Never sent.
keepDirectPlay?: boolean;
```

In `createPlaybackPlan`, with `picked = streams.AudioStreamIndex` when `options.keepDirectPlay` is true, a `mediaSourceId` was given, and the index is valid; otherwise `picked` is undefined and the method behaves exactly as today.

`embedded(source, index)` is true when `source.MediaStreams` has a stream with `Type === "Audio"`, `Index === index`, and `IsExternal !== true`.

1. Send the first request as today, with the index. Decide with `selectSource`.
2. If `picked` is undefined: continue as today. One rule for every other caller.
3. If the decision is `force-fallback` (a disc or ISO offered for direct play): continue with rule 4 as today, the index kept in the second request. No guard request; the source converts either way.
4. If the decision is `direct-play` and `embedded(source, picked)`: use it. The plan's `defaultAudioStreamIndex` is `picked`, whatever the answer's `DefaultAudioStreamIndex` says. One request.
5. Otherwise (a conversion, a refusal, or a direct play of a source that has no such embedded track) send **one** more request: the same `MediaSourceId`, flags, limit, and `SubtitleStreamIndex`, without `AudioStreamIndex`, `EnableDirectPlay: true`. Decide it with `selectSource`.
   - Plain answer `direct-play`: use the plain answer, its `PlaySessionId`, and its static URL. `defaultAudioStreamIndex` is `picked` when `embedded(plainSource, picked)`, else the plain answer's own default (the server's default).
   - Else, first answer was a conversion: use the first answer. The conversion carries the pick, and the plan's `defaultAudioStreamIndex` is `picked` whatever the answer's `DefaultAudioStreamIndex` says (decision 10).
   - Else: use the plain answer and continue as today with it (rule 4's forced request, a conversion, or the refusal).
6. There is never a third request for the guard. A failed guard request fails the attempt like any failed PlaybackInfo (redacted, Retry offered). The abort signal is passed to both.

The answer that is not used is dropped; its `PlaySessionId` is never used, logged, or reported, as with rule 4's first answer today. PlaybackInfo with `AutoOpenLiveStream: false` starts no job.

Why a flag and not one rule for every request with an index: renegotiations in sessions with no pick must stay byte-for-byte (fact 9).

### 3. Session: the coordinator owns the pick (`src/lib/player/coordinator.ts`)

- `PlaybackSelection` gains `keepDirectPlay?: boolean`.
- `start(item, choice, pick?: { mediaSourceId: string; audioStreamIndex: number })`. With a pick, `this.selection = { ...pick, keepDirectPlay: true }`; without, `undefined` as today. `beginAttempt` already passes `this.selection` to the gateway, so the first attempt, every retry, and every renegotiation carry it ("Later attempts for the item keep them", `coordinator.ts:72-74`).
- `renegotiate` already merges `{ ...this.selection, ...streams, mediaSourceId }`, so Play original and a limit change keep the pick and the flag. The `fallback` selection also takes `keepDirectPlay` from `this.selection`.
- Retry keeps the track that is playing: track `lastPlayedAudio` beside `lastPlayedTicks` (from `snapshot.audioTrack`, after a first frame). In `restart("retry", …)`, when `this.selection?.keepDirectPlay` and `lastPlayedAudio` is defined, the selection's `audioStreamIndex` becomes `lastPlayedAudio`. Sessions without a pick are unchanged.
- `CoordinatorCallbacks.onAudioPickNotApplied?(): void`. On the `loaded` event of an attempt whose selection has `keepDirectPlay` and an `audioStreamIndex`, call it once when `event.snapshot.audioTrack !== selection.audioStreamIndex`. This one check covers a pick the gateway could not apply, a pick Rust could not map, and a conversion that did not carry it.
- `start` clears `lastPlayedAudio` where it clears `lastPlayedTicks` (`coordinator.ts:111`), before it calls `restart("retry", …)` (`:120`), so a track from an earlier session can never override a new session's pick.
- Session end clears the selection as today (`finishSession`).

`use-playback-session.ts`:
- `PlaybackSessionOptions.audioStreamIndex: number | undefined`, in the effect's dependencies.
- `coordinator.start(item, choice)` with two arguments when there is no pick or no `mediaSourceId`; otherwise `coordinator.start(item, choice, { mediaSourceId, audioStreamIndex })`.
- In `playbackGatewayFor`'s selection branch, take `keepDirectPlay` out of the selection and pass `{ ignoreStreamingLimit, ...streams, ...(keepDirectPlay ? { keepDirectPlay: true } : {}) }`. Without the flag the object is exactly today's, which the existing tests assert with `toEqual`.
- State `audioPickNotApplied`, set by the callback and cleared wherever `setPlan(undefined)` runs, returned from the hook.

`src/features/player/index.tsx` passes `route.audioStreamIndex` and hands `audioPickNotApplied` to `PlayerView`.

### 4. Catalog and the Picker's order (`src/domain/audio-picker.ts`)

```ts

  openingIndex: number;       // the track the Picker shows before any pick

export function audioPickerView(audio: AudioInfo[], options: {
  preference?: string;
  cultures?: readonly LanguageCulture[];
  defaultAudioStreamIndex?: number;

}): AudioPickerView | undefined;   // undefined with fewer than two indexed tracks
```

- `serverStartIndex`: `defaultAudioStreamIndex` when it names a listed track; else the first track flagged default; else the first track.
- Preferred tracks: those whose `languageKey(language, cultures)` equals `languageKey(preference, cultures)`.
- With a preference and at least one preferred track: `elevated` is true; `openingIndex` is `serverStartIndex` when that track is preferred, else the first preferred track in file order; the list is the preferred tracks in file order, then the rest.
- Otherwise `openingIndex` is `serverStartIndex` and nothing is elevated.
- "The rest" (or every track when nothing is elevated): grouped by language key, groups ordered by `languageLabel` with `localeCompare(…, "en")`, file order inside a group, tracks with no language key (missing, empty, `und`) last in file order.

The view passes `languageName` from `src/features/detail/format.ts` as `languageLabel`.

## Decision log

Resolved by the refiner from the task, the code, and the settled answers:

1. **The pick travels in the play route** (`audio=<n>`), not in a hidden store, so the three play links say what they play and a play from Home can never pick it up.
2. **The page's memory is a module variable** cleared by a route change to anywhere but this title's page or its player. `history.state` would bring the pick back after leaving the page, which L8 A rules out.
3. **A held pick restores its version too**, because the version is otherwise reset on Back and the pick belongs to a version.
4. **The guard is scoped by a flag** to sessions that started from a pick, so no existing renegotiation gains a request.
5. **The coordinator owns the pick** in its existing `selection`, so retry, Play original, and limit changes keep it with no second mechanism.
6. **No plan field and no native change.** The plan's existing `defaultAudioStreamIndex` carries the pick to Rust; the "not applied" check compares the loaded snapshot with what was asked.
7. **Order inside a language is file order**; the trigger reads name, then codec and channels unless the name already has the codec.
8. **Q1, answered by the owner on 2026-11-16: option A.** What the Picker shows is what plays. The index is sent whenever the shown track differs from the server's start track, and never otherwise. Play from Home still follows the server. For acceptance 5, a Picker that opens on the preferred-language track counts as the viewer asking for it.
9. **Q2, answered by the owner on 2026-11-16: option A.** One OSD line for `OSD_NOTICE_MS` at the start of the session, like the conversion line: "Couldn't switch to the audio track you picked. Playing the default track." There is no Info row and no toast.

10. **A conversion that carries the pick sets the plan's `defaultAudioStreamIndex` to the pick** (spec check issue 1). The fake-HLS engine (`src/test/e2e-hls-engine.ts`, `carriedTracks`) selects the audio track whose index equals `plan.defaultAudioStreamIndex`, and the mock's `TranscodingUrl` carries no index, so the gateway, not the mock, makes the plan say what was picked. This also keeps the plan right on a real server that answers `DefaultAudioStreamIndex: 1` for a conversion. The mock is not changed for this.
11. **Scope of "a retry keeps the track that is playing" (acceptance 10).** It applies to sessions that started from a pick; a retry in a session with no pick is unchanged and its audio case is in the backlog (item a). The PR states this.
12. **Milestone 1 result (2026-11-16).** Both servers (10.11.7, 12.4.0) keep direct play when the first PlaybackInfo names index 2 on the multi-audio sample, answer `DefaultAudioStreamIndex: 2`, and carry `AudioStreamIndex=2` in a forced conversion's master URL; index 9 falls back to default 1 with direct play kept. The item-detail default follows the account's audio settings on both (1, and 2 under a Spanish preference). The stop rule did not trigger.

Labels and the synopsis line length (five of twelve columns) stay; the bar wraps only when the window is genuinely too narrow. `.detail-text` is now the content width and its other children are capped at five twelfths.
