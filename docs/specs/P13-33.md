## Approach

### 1. Delay the buffering status (D6 B)

`src/features/player/chrome/use-delayed-flag.ts`:

```ts
// True once `value` has stayed true for `delayMs`; false at once when it turns false.
export function useDelayedFlag(value: boolean, delayMs: number): boolean {
  const [elapsed, setElapsed] = useState(false);
  useEffect(() => {
    if (!value) {
      setElapsed(false);
      return;
    }
    const timer = setTimeout(() => setElapsed(true), delayMs);
    return () => clearTimeout(timer);
  }, [value, delayMs]);
  return value && elapsed;
}
```

- `value && elapsed` hides the status in the same render in which buffering ends, and stops a stale `elapsed` from showing a new stall early.
- Each stall starts its own timer, so a 300 ms stall followed by another 300 ms stall shows nothing.

In `PlayerView.tsx`:

```ts
const buffering = useDelayedFlag(chromeShown && Boolean(snapshot?.buffering), BUFFERING_STATUS_DELAY_MS);
...
{chromeShown && <PlayerStatus text={buffering ? "Buffering…" : undefined} />}
```

Call the hook unconditionally, above the `if (sessionError)` early return, so hook order does not change. The input includes `chromeShown` so that a stall that began before the first frame starts its 500 ms from the moment the status could be shown.

Why a JS timer and not a CSS `animation-delay` (as the skeleton does): `PlayerStatus` is the `role="status"` live region. If the text were inserted at once and only faded in later, screen readers would announce every short stall. With the timer, the text node is inserted once, after 500 ms, so the region announces once per long stall and never for a short one (acceptance 6; `DESIGN.md` §11 rule 6). Reduced motion is unaffected: the disc and ring rules stay as they are.

`PlayerStatus`, `PlayerLoading`, the OSD, and the chip are not edited.

### 3. Scrims that guarantee 4.5:1 (DESIGN.md §11 rule 1)

Brightening "Ends at" alone cannot pass acceptance 5: at the height of the time row the current bottom scrim is about 42% black, and even `--text-1` needs about 57% over white art (computed with `src/styles/contrast.ts`'s formula; the measured ratios above agree). The report removes text shadows, but `player.css` has no text shadow, so the failures are real (the P13-30 caveat at `docs/specs/P13-30.md:191` does not apply).

Follow the `--scrim-nav` precedent (a flat band, then a fade; proven by `tokens.test.ts:84`):

```css
/* :root */
--scrim-player-top-h: 200px;
--scrim-player-bottom-h: 260px;
--scrim-player-top: linear-gradient(180deg, rgb(0 0 0 / 0.85) 0%, rgb(0 0 0 / 0.85) 55%, rgb(0 0 0 / 0) 100%);
--scrim-player-bottom: linear-gradient(0deg, rgb(0 0 0 / 0.85) 0%, rgb(0 0 0 / 0.85) 55%, rgb(0 0 0 / 0) 100%);

/* :root[data-form="tv"] */
--scrim-player-top-h: 360px;
--scrim-player-bottom-h: 440px;
```

Why these numbers (layout arithmetic from `player.css` and `tokens.css`; to be confirmed by the captures):

- Alpha 0.85 over pure white gives `rgb(38 38 38)`; `--text-2` on that is about 6.1:1 and `--text-1` about 13:1. `--text-2` needs at least about 0.77. 0.85 matches today's bottom maximum and `--scrim-nav`, so no new alpha is introduced.
- Desktop bottom: text top of the time row ≈ 24 (padding) + 56 (control row, Play disc) + 12 (gap) + 44 (seek row) ≈ 136 px above the bottom edge at most. Band = 55% of 260 = 143 px.
- Desktop top: text bottom ≈ 24 (padding) + 49 (series line plus one-line title) ≈ 73 px; a two-line title reaches about 101 px. Band = 55% of 200 = 110 px.
- TV bottom: 54 (`--safe-y`) + 24 + 84 (`--player-play-disc`) + 12 + 64 (seek row at `--hit-min`) ≈ 238 px. Band = 55% of 440 = 242 px.
- TV top: 54 + 24 + about 79 (24 px meta at 1.35 plus 33 px heading at 1.25), two-line ≈ 198 px. Band = 55% of 360 = 198 px.

If the regenerated report or the TV captures show a run outside the band, raise the matching height (not the alpha) and say so in the PR. Keep the 55% stop the same in both tokens so the proofs stay simple.

Tests in `tokens.test.ts`, modelled on the hero proofs:

- For each of `--scrim-player-top` and `--scrim-player-bottom`: parse the stops (`/rgb\(0 0 0 \/ ([\d.]+)\) ([\d.]+)%/g`), take the band alpha (the alpha of the last stop at or before the band end, equal to the first stop's alpha), and assert `--text-2` on `composite([0,0,0], alpha, [255,255,255])` is ≥ 4.5:1. `--text-2` is the dimmer of the two colours in use, so `--text-1` follows.

Read the TV heights from the `:root[data-form="tv"]` block (add a small `tvBlock` regex beside `rootBlock`).
