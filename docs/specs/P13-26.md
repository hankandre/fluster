## Goal

Add a `Menu` to `src/features/shared/ui/`: a trigger button that opens a list of actions. It is the action counterpart of `Picker` (DESIGN.md §7.10, "the same trigger and anchored list for actions instead of a value"). On desktop the list is anchored to the trigger; in the TV form (`<html data-form="tv">`) it is the same right-side sheet the Picker uses. Arrow keys move, Enter activates and closes, and Escape (or Backspace, which the shell turns into Escape) closes and returns focus to the trigger. The gallery shows its states, and the visual suite captures them at 1440×900, 1920×1080, and 1920×1080 TV. No screen uses the Menu yet; P15-02 and P13-21 add the uses.

## Approach

### 1. API

```ts
export interface MenuItem {
  // React key only; never shown.
  id: string;
  label: string;
  // A second line, as in Picker rows.
  description?: string;
  disabled?: boolean;
  // Set (true or false) only on rows that mark the current choice, such as the active account (DESIGN.md 7.21).
  // Such rows are menuitemradio with aria-checked and show the check. Rows without it are plain menuitem.
  checked?: boolean;
  onSelect(): void;
}

interface MenuProps {
  // The trigger's text (pill) or accessible name (icon), and the menu's name.
  label: string;
  items: MenuItem[];
  // "pill" (default): the Picker pill trigger, label then chevron. "icon": a round icon button (§7.19) showing `icon`,
  // with `label` as its aria-label and no chevron.
  appearance?: "pill" | "icon";
  // Required for appearance "icon"; optional leading icon for "pill".
  icon?: ReactNode;
  disabled?: boolean;
  // Makes the trigger an item of the surrounding roving row (the ActionBar).
  rovingItem?: boolean;
  // False leaves ArrowUp and ArrowDown on the closed trigger to the surrounding column. Enter and Space still open it.
  openOnArrow?: boolean;
}
```

Model the `icon` requirement as a discriminated union, like `ButtonProps` in `button.tsx`: `{ appearance: "icon"; icon: ReactNode }` or `{ appearance?: "pill"; icon?: ReactNode }`. `rovingItem` and `openOnArrow` copy the Picker's props (`picker.tsx:27-32`), because P15-02 puts `More` in the ActionBar beside the version pill, which uses `rovingItem` (`detail-actions.tsx:51`).

Wrapper: the `pill` appearance uses a `ui-picker ui-picker--pill` `div`; the `icon` appearance uses a `div.ui-menu` (new `menu.css`, `display: inline-flex` only) so no Picker layout rule touches the round button, which keeps its §7.19 size. Both carry the blur-close handler.

How the trigger looks follows DESIGN.md §7.10 ("the same trigger"): the `pill` appearance uses the Picker's pill classes (`ui-picker-trigger` inside a `ui-picker ui-picker--pill` wrapper), with an optional leading icon, the label, and a `ChevronDown` (lucide, `aria-hidden`, size 18, as in the Picker). The `icon` appearance uses `buttonClass("icon")` from `button.tsx`. That is the §7.19 icon button that P13-21 needs for the nav's account initial (§7.1). There is no "field" appearance: a menu of actions has no field label.

### 2. Shared placement (`anchored-place.ts`)

Move the Picker's placement effect (`picker.tsx:78-106`) into `useAnchoredPlace(open: boolean, sheet: boolean, trigger: RefObject<HTMLElement | null>, list: RefObject<HTMLElement | null>): CSSProperties` without changing its logic. It keeps the 8 px margin, the 4 px offset, the flip when there is more room above, the 18 rem cap, the 96 px minimum, and the resize and capture-phase scroll listeners. When `sheet` is true it returns `{}` and adds no listeners. Picker calls `useAnchoredPlace(open, tv, trigger, list)` and Menu does the same. The existing Picker tests and the unchanged Picker captures (`81`, `85`, `93`) guard the move.

### 3. Behaviour (ARIA APG menu button pattern)

- **Trigger:** `type="button"`, `id={triggerId}`, `aria-haspopup="menu"`, `aria-expanded={open}`, and `aria-controls={menuId}` only while open. Click toggles. Enter and Space use the native button click, which opens the menu at the first enabled item. With `openOnArrow` (default true), ArrowDown opens at the first enabled item and ArrowUp opens at the last (APG). Both call `preventDefault`. Modifier keys are ignored, as in `picker.tsx:132`. If no item is enabled, the menu does not open.
- **List:** `<ul role="menu" id={menuId} aria-labelledby={triggerId}>` in `createPortal(…, document.body)`. Class `ui-picker-list`, plus `ui-picker-list--sheet` in the TV form. It carries `DIALOG_EXEMPT_ATTRIBUTE`. Rows are `<li tabIndex={-1}>` with role `menuitem`, or `menuitemradio` plus `aria-checked` when `checked !== undefined`. Disabled rows get `aria-disabled="true"`. Rows use class `ui-picker-option`, with `ui-picker-text`, `ui-picker-label`, and `ui-picker-description` inside. The `ui-picker-check` column renders only when at least one item defines `checked`, so the rows of that menu stay aligned. Plain action menus have no check column (§7.10: "rows with no check"). A row with `checked` true shows the `Check` icon (size 18, strokeWidth 2.5, `aria-hidden`), as the Picker does.
- **Focus:** the active index lives in state, and an effect focuses that row while the menu is open (`picker.tsx:108-110`). `onFocus` on a row sets the active index, so a pointer and the keyboard agree.
- **Keys on the list** (one `switch`; modifier keys ignored):
  - `ArrowDown` / `ArrowUp`: next or previous enabled row, stopping at the ends with no wrap, as in the Picker. `preventDefault`.
  - `Home` / `End`: first or last enabled row. `preventDefault`.
  - `ArrowLeft` / `ArrowRight`: `preventDefault` only. There are no submenus, and neither a surrounding roving row nor the TV arrow fallback may act on them.
  - `Enter` / `" "`: `preventDefault`, then `activate(active)`.
  - `Escape`: `preventDefault`, `stopPropagation`, then `close(true)`. That closes only the menu and never a Dialog behind it or the screen (§9).
  - `Tab`: `close(true)` without `preventDefault`. Focus is back on the trigger first, so the default Tab moves on from there (`picker.tsx:172-175`).
  - Default: a single printable character without Shift adds to a typeahead buffer that resets after 700 ms (reuse `TYPEAHEAD_RESET_MS` semantics and the widened `typeaheadIndex` from `picker.tsx`) and moves to the match.
- **`activate(index)`:** do nothing for a missing or disabled row. Otherwise `setOpen(false)`, focus the trigger, then call `item.onSelect()`. The order matters. A `Dialog` the action opens records the trigger as its opener and gives focus back to it on close. An action that navigates or focuses something else keeps that focus, because it runs last.
- **Pointer:** a click on an enabled row activates it. Blur leaves the trigger and the list in the same way as `picker.tsx:190-193`: a focus move outside both closes the menu without returning focus.
- **Clean up:** clear the typeahead timer on unmount, as in `picker.tsx:112-115`.

### 4. TV form

`useTvForm()` picks the sheet class. Keys, roles, and focus return are the same as on desktop (§7.10: "uses the same listbox, keys, and focus return"; for the Menu this means the same `role="menu"`). The sheet has no veil and no title, the same as the Picker sheet. Backspace reaches the Menu as Escape through `useBackspaceAsEscape`, so Back on a remote closes the sheet.

## Risks and out of scope

- **Picker refactor.** Moving the placement effect could change how the Picker list is placed. Mitigation: move the code verbatim, run the existing Picker tests, and compare the Picker captures before and after. If any capture differs, revert to duplicating the effect in `menu.tsx` and note it in the plan's decision log. The Picker's look and behaviour must not change.
- **React portal event bubbling.** Keydown events in the portaled list bubble through React to the trigger's ancestors (such as `ActionBar`'s roving `onKeyDown`). `useRovingFocus` returns early on `defaultPrevented` (`roving-focus.ts:139`), and Menu rows are not `data-roving-item`, so every key the Menu uses calls `preventDefault`. The Picker already relies on this in the ActionBar today.
- **The `checked` row extension.** §7.10 says Menu rows have no check, and §7.21 asks for a check on the active account. The spec reads these together: action rows never show a check, and a row that marks a current choice does, as `menuitemradio`. The design review should confirm this. The P13-21 account switch itself, the nav trigger, and the TV full-screen account grid are out of scope.
- **Disabled rows are skipped by the arrows**, to match the Picker and `OptionList`. APG lets disabled menu items take focus. Matching the Picker keeps one rule across the app. A screen reader still hears a disabled row's state when it reads the list.
