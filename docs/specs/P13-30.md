## Goal

Every synthetic fixture image today is a soft gradient (`scripts/generate-visual-art.mjs`, `paint()` and `palettes`), so the visual captures cannot reveal text that is unreadable over bright, busy artwork. `DESIGN.md` §11 rule 1 says text contrast is 4.5:1 (3:1 for large text), that text over artwork "always sits on a scrim that guarantees this", and to "check it on the brightest art in the fixtures". This task adds one bright, high-contrast, busy synthetic image set, points one fixture title at it (behind an opt-in mock option), captures the six art-heavy surfaces at both desktop sizes, measures the contrast of every visible text run in those captures, and writes the failures to `docs/design/contrast-report.md` and `tasks/backlog.md`. It fixes nothing in the UI.

## Approach

1. **Worst-case art.** Add `worstArt(width, height)` to `generate-visual-art.mjs`, a pure function of `(x, y)` (no `Math.random`, no time; use an integer hash such as a 32-bit xorshift of `x * 73856093 ^ y * 19349663` where randomness-like scatter is wanted). Layers, in order:
   - A bright base: near-white to pale yellow, cyan, and pink bands (each channel 200-255), changing every 40-120 px so the base itself is uneven.
   - Saturated mid-size blocks (24-96 px) in yellow, cyan, and lime, all with relative luminance 0.6 or more.
   - High-contrast detail: 2 px black diagonal hatching on an irregular 14-30 px pitch, plus scattered 4-8 px black and pure-white squares from the hash, covering roughly 3-8% of pixels in total.
   - Fully opaque.
   Write `worst-backdrop` (1920x1080), `worst-poster` (400x600), `worst-still` (1280x720). The thresholds the test enforces (mean luminance 0.6 or more; 1% or more of pixels at 0.05 or less; every 64x64 tile with range 0.5 or more) define "bright, high-contrast, busy"; tune the formula until they pass. Append these three to `files` after the existing entries, so existing files are generated exactly as today.

2. **One fixture item uses it (mock).** Behind `opts.worstCaseArt` only:
   - `imageFor(id, type, opts)`: for `s1`, `Backdrop`/`Thumb` gives `worst-backdrop`, `Primary` gives `worst-poster`; for any `episodes[id]`, `Primary` (and any other type) gives `worst-still`. Logo stays `logo` (s1 has no Logo tag, so the series title renders as text).
   - `/UserItems/Resume` returns `[episodeDto("ep-2"), movieDto("m2", opts)]`, so `pickHero` picks `ep-2` and the hero shows `s1`'s backdrop through `parentBackdrop`.
   - The "fixture item" is the series Harbor Lights with its episodes: one title, shown as an episode on Home, the detail page, the player, and Up Next, and as the series on the series page. Without the flag, every response is identical to today.
   - `export const artDataUrl = (name: string) => \`data:image/png;base64,${art(name).toString("base64")}\``; `frameDataUrl = () => artDataUrl("frame")`.

3. **Six scenarios** in `e2e/visual/worst-art-scenarios.ts`, each `{ desktopOnly: true, contrast: true, opts: { worstCaseArt: true, ... } }` (the acceptance names 1440x900 and 1920x1080 only; `desktopOnly` already selects exactly those two passes). Names start at `100-` to stay clear of the TV `90-97` names:
   - `100-worst-art-home-hero`: `signIn`, wait 1200 ms (as `19a`).
   - `101-worst-art-home-card`: `signIn`, wait 800 ms, focus `getByRole("region", { name: "Continue watching" }).locator("a.media-card").first()` (the `ep-2` thumb card with its title under it), `scrollIntoViewIfNeeded`, wait 900 ms so the ambient layer has followed (as `19b`).
   - `102-worst-art-detail`: `signedInAt(page, "#/next/item/ep-2", 1_000)`.
   - `103-worst-art-series`: `signedInAt(page, "#/next/series/s1", 1_000)`.
   - `104-worst-art-player`: `play(page, "#/next/item/ep-2", "worst-still")` (controls shown by the mouse moves in `play`).
   - `105-worst-art-up-next`: opts also `{ duration: 25, short: true }`; `play(page, "#/next/item/ep-1", "worst-still")`, wait for `getByRole("complementary", { name: "Up next" })`, then move the mouse twice and wait 500 ms (as `55a`, not `55`), so the chrome is shown and the measurement runs inside the 3 s idle window. Decision (spec-check note 1): 55a-style, because waiting for the chrome to hide would measure a different surface. 104 ends 300 ms plus about 150 ms of `settle` after its last mouse move, and the measurement takes under 1 s, so it also finishes well inside 3 s.
   If a locator above does not match the current UI, fix the locator, not the UI, and record it in the evidence.

4. **Measurement flow** (`measureCapture`, called in `screens.spec.ts` right after `writeFileSync` of the capture and before `toMatchSnapshot`, so a missing baseline does not prevent the JSON):
   1. `runs = await collectTextRuns(page)` (Approach 5).
   2. Inject a style tag: `*, *::before, *::after, ::placeholder { -webkit-text-fill-color: transparent !important; text-shadow: none !important; }`. Only the text fill is hidden, so borders, outlines, and shadows that use `currentColor` (a focus ring) keep their pixels (spec-check note 2). Text shadows are removed because WCAG measures text against its background and DESIGN.md §11 rule 1 assigns legibility to scrims, which stay in the picture. Icons that use `currentColor` fills stay.
   3. Screenshot with the same options as the capture (`fullPage` as the scenario, `animations: "disabled"`, `caret: "hide"`, `scale: "css"`). Never write it into `visual-captures/` (the accept script would reject it).
   4. Remove the style tag and call `collectTextRuns` again; if the set of run keys differs from step 1 (for example the player chrome auto-hid between shots), throw, so the state change is visible rather than silently measured. Keep steps 1-3 back to back with no waits; the chrome hides 3 s after the last mouse move.
   5. Decode the background PNG with `decodePng`, assert its width and height equal the viewport (or page) size in CSS px, then for each run compute `measureRun`. Fail the test if `runs.length === 0`.
   6. Write `test-results/contrast/<size>/<name>.json`: `{ capture: "<size>/<name>", runs: [{ text, fontSizePx, fontWeight, required, ratio, lowest, x, y, width, height }] }`, runs sorted by `y`, then `x`. No URLs, no absolute paths, no timestamps.
   The measurement never fails the test on a low ratio; it only reports.

5. **Text runs** (`collectTextRuns`, one `page.evaluate`): walk `document.body` with a `TreeWalker` over text nodes whose trimmed content is non-empty. For each node's parent element:
   - Skip when computed `visibility` is not `visible` or `display` is `none` on it.
   - Effective alpha = alpha of computed `color` x the product of `opacity` up the ancestor chain; skip below 0.05 (hidden chrome fades with opacity).
   - Take `Range.getClientRects()`; intersect each line rect with the viewport (or the full page for `fullPage`) and with every ancestor whose computed `overflow-x` or `overflow-y` is not `visible`, or whose `clip` is not `auto`; drop rects narrower or shorter than 2 px. This removes `.visually-hidden` text.
   - Each surviving line rect is one run: `{ key, text (first 40 chars of the trimmed node text), color [r,g,b], alpha, fontSizePx, fontWeight, rect }`. `key` is the node's index in walk order plus the line index.
   - No occlusion test: the six captures have no modal over the page; record this limitation in the report header.

6. **Ratio** (`scripts/contrast.mjs`):
   - Relative luminance per WCAG 2.2 (sRGB channel `c/255`, linearised with the 0.04045 threshold, weights 0.2126, 0.7152, 0.0722); ratio `(L1 + 0.05) / (L2 + 0.05)` with `L1` the lighter.
   - For each background pixel inside the run's rect (rounded to whole px, clamped to the image): foreground = `composite(color, alpha, bgPixel)`; per-pixel ratio = contrast of that foreground against `bgPixel`.
   - `ratio` (the reported, judged value) is the 5th percentile of the per-pixel ratios, so 95% of the background behind the run meets it; `lowest` is the minimum, shown for context. The 5th percentile keeps one stray pixel (an adjacent edge inside the line box) from deciding the result while still catching any real bright patch. Both rounded to 2 decimals.
   - `requiredRatio(size, weight)` is 3 when `size >= 24`, or when `size >= 18.66 && weight >= 700`; otherwise 4.5 (DESIGN.md §11 rule 1, which is the rule the acceptance cites; the acceptance's 24 px case is included).
   - A run fails when `ratio < required`.
   - `decodePng`: 8-bit, non-interlaced, colour types 2 (RGB) and 6 (RGBA), filters 0-4 (None, Sub, Up, Average, Paeth); concatenate all `IDAT` chunks and `inflateSync`; throw a clear error on anything else. Return `{ width, height, rgba }` (RGB expanded to RGBA).

7. **Report** (`build-contrast-report.mjs`): if `test-results/contrast/` is missing or has no JSON, print `no contrast results; report unchanged` and exit 0 without touching the file. Otherwise write:
   - `# Contrast report` and one paragraph: generated by `pnpm test:visual` from the worst-case artwork captures (P13-30); do not edit by hand; the method (text hidden and shadows removed for the background shot, 5th-percentile ratio, thresholds from DESIGN.md §11 rule 1, no occlusion test).
   - `## Summary`: table `Capture | Text runs | Failures`, one row per capture, sorted by capture.
   - `## Failures`: table `Capture | Text | Size | Needed | Measured | Lowest`, sorted by capture, then position; `|` and backticks in text escaped. If none: `No text run is below its threshold.`
   - Deterministic: no date, no host, no absolute path, so a rerun on the same renderer does not change the file.

8. **Baselines and backlog.** Push the branch; the CI visual job fails on the 12 missing baselines. Run `pnpm test:visual:accept <run-id>`, confirm `git status --short e2e/visual/baselines` lists only the 12 new files, review the captures in the artifact's contact sheet, commit. Generate `docs/design/contrast-report.md` with a local `pnpm test:visual` (the art is identical; glyph rasterisation may move ratios in the second decimal). For each distinct failing element (same text and element across both sizes counts once), append a backlog bullet: what text, which surfaces, measured vs needed at each size, and a size estimate. Where a failure is the player's `--text-3` "Ends at" line, reference P13-33 (`ux-audit.md:405`) rather than filing a duplicate. Fix nothing.

## Risks and out of scope

- Rasterisation differences between the local host and CI can move ratios slightly; the committed report comes from a local run. Uploading the report from CI would need a CI change; out of scope.
- The player chrome hides 3 s after the last mouse move; Approach 4 step 4 turns a state change between the two screenshots into a visible failure instead of a wrong measurement. If it flakes, move the mouse once more inside `measureCapture` before step 1 (it resets the idle timer and keeps the same state) rather than adding retries.
- Generating three busy PNGs adds time to both global setups (deflate of a busy 1920x1080 image); keep `deflateSync` level 9 for consistency, and report the measured setup time in the evidence. If it exceeds about 5 s, lower the level for the worst-case files only.
- A filtered local run (`-g`) that includes only some worst-case scenarios rewrites the report with a subset; run the full `pnpm test:visual` before committing the report.
- Out of scope: fixing any failure (backlog only); non-text contrast (progress, borders, focus ring 3:1); the TV form and phone captures of the worst-case art; occlusion handling; changes to `DESIGN.md`.
