## Goal

Routes are spelled out by hand across the app. On `c0b7061`, 22 non-test files under `src/` contain `#/next` (`grep -rln '#/next' src | grep -v '\.test\.'`): only `src/features/routes.ts` should. The sign-in route is declared as a constant in six views (`home-view.tsx:20`, `player/index.tsx:29`, `browse/library-page.tsx:5`, `browse/series-view.tsx:15`, `detail/item-detail-view.tsx:14`, `search/search-view.tsx:8`), again in `shell/focus-return.ts:33`, as a literal in `settings/account-section.tsx:20`, and as a `case` in `src/app/App.tsx:119,138`. Each of the six views carries its own copy of this effect:

```ts
useEffect(() => {
  if (!gateway) window.location.hash = SIGN_IN_ROUTE;
}, [gateway]);
```

Two placeholder pages from the proof of concept are still routed: `#/next/detail` (`DetailView`, `src/features/detail/index.tsx:3`) and `#/next/player` (`PlayerFeatureView`, `src/features/player/index.tsx:33`).

This task:

1. Makes `src/features/routes.ts` the one module that builds and parses every route, including a single parser for the whole route table.
2. Moves the "no gateway, go to sign-in" redirect into one guard component that `App.tsx` wraps around every route except an explicit list of open routes.
3. Deletes the two placeholder pages and their stub components, so those hashes fall through to Not found.
4. Adds source-scan tests that keep it that way.

No route string, screen, focus behaviour, or Back behaviour changes for a signed-in viewer. The one visible change is the effect of acceptance item 4: a signed-out viewer who types `#/next/settings` is now sent to sign-in. Before, Settings rendered without the Account section. No UI links there while signed out (`grep -n settings src/features/sign-in/*.tsx` has no output), and every e2e and visual Settings scenario signs in first (`e2e/settings.spec.ts:93-108`, `e2e/visual/scenarios.ts:14-24`).

## Approach

1. **Route table in `routes.ts`.** Add these, each declared once:

   ```ts
   export const FEATURE_INDEX_ROUTE = "#/next";
   export const SIGN_IN_ROUTE = "#/next/sign-in";
   export const HOME_ROUTE = "#/next/home";
   export const SEARCH_ROUTE = "#/next/search";
   export const SETTINGS_ROUTE = "#/next/settings";
   export const GALLERY_ROUTE = "#/next/gallery";
   export function searchResultsRoute(term: string): string; // moved verbatim from search-route.ts
   export function isAppHash(hash: string): boolean;          // hash === "#/next" || hash.startsWith("#/next/")
   export function isPlayerHash(hash: string): boolean;       // hash.startsWith(PLAY_PREFIX); the "#/next/player" clause goes
   export type AppRoute =
     | { kind: "feature-index" } | { kind: "sign-in" } | { kind: "gallery" }
     | { kind: "home" } | { kind: "settings" } | { kind: "search"; term?: string }
     | ({ kind: "play" } & PlayRoute)
     | ({ kind: "library" } & LibraryRoute) | ({ kind: "collection" } & CollectionRoute)
     | { kind: "item"; itemId: string } | { kind: "series"; seriesId: string };
   export function parseAppRoute(hash: string): AppRoute | undefined;
   export const OPEN_ROUTE_KINDS = ["feature-index", "sign-in", "gallery"] as const;
   export type GuardedRouteKind = Exclude<AppRoute["kind"], (typeof OPEN_ROUTE_KINDS)[number]>;
   export function isOpenRoute(route: AppRoute): boolean;     // switch on kind, exhaustive never default
   ```

   `parseAppRoute` must return exactly what `App.tsx:134-195` routes today:
   - Exact matches for the six constants (`SEARCH_ROUTE` gives `{ kind: "search" }` with no term).
   - `parsePlayRoute` under `PLAY_PREFIX`.
   - `parseLibraryRoute` and `parseCollectionRoute` when the hash starts with their prefixes. If such a hash fails to parse, the result is `undefined`, not a fall-through.
   - For `item`, `series`, and `search`: today's split, `const [, , section, id, ...extra] = hash.split("/")`. Return `undefined` when `id` is empty or `extra` is non-empty. `decodeURIComponent(id)` in a try, which also yields `undefined`. Do **not** switch `item` to `parseItemRoute`. That would change `#/next/item/m1?x` from item `m1?x` to `m1`, which is a behaviour change outside this task. Log the difference in the backlog (step 8).
   - Anything else gives `undefined`.

   Every literal `#/next…` string in `routes.ts` is declared once. `ITEM_PREFIX`, `PLAY_PREFIX`, `LIBRARY_PREFIX`, and `COLLECTION_PREFIX` stay. Add `SERIES_PREFIX` and `SEARCH_PREFIX` only if the code uses them. `itemRoute`/`seriesRoute` may use the prefix constants. Output must not change.

2. **`SignInGuard`** (`src/features/shell/sign-in-guard.tsx`):

   ```tsx
   // Sends a signed-out viewer to sign-in. The only copy of this redirect (P2-10).
   export function SignInGuard({ hash, children }: { hash: string; children: ReactNode }) {
     const { gateway } = useSession();
     useEffect(() => {
       if (!gateway) window.location.hash = SIGN_IN_ROUTE;
     }, [gateway, hash]);
     return gateway ? <>{children}</> : null;
   }
   ```

   - Keep the push (`window.location.hash =`), not `replace`. That is what the views do today, so history depth and Back are unchanged.
   - `hash` is a dependency because one guard instance stays mounted across guarded routes. Without it, a signed-out move from one guarded hash to another would not redirect. Today each view remounts, so its effect re-runs.
   - Render `null` while signed out. Today the views render an empty `<main>`. Nothing tests that empty frame, and it lasts only until the effect runs.
   - Do not export it from `features/shell/index.ts` unless `App.tsx` imports through the barrel. Match how `App.tsx` imports `useFocusReturn`.

3. **`App.tsx`.**
   - Keep the non-app redirect (`if (!inApp) window.location.replace(HOME_ROUTE)`).
   - Keep `chromeFor` with the same results: `"none"` for `FEATURE_INDEX_ROUTE`, `SIGN_IN_ROUTE`, `GALLERY_ROUTE`, and any `isPlayerHash(hash)`, which includes a malformed `#/next/play/…`; otherwise `"nav"`.

     - `route = parseAppRoute(hash)`.
     - `page = route ? renderRoute(route, hash, visit, services) : <NotFoundView />`.
     - `guarded = route && !isOpenRoute(route) ? <SignInGuard hash={hash}>{page}</SignInGuard> : page`.

     - Not found is never guarded, which matches today: `App.test.tsx:9-30` renders it signed out.
   - `renderRoute` switches on `route.kind` and returns the same elements with the same `key`s:

- **Remounts.** If the guard wraps routes inconsistently, `SearchView` can remount between the bare and term routes, and the field loses focus and text (`e2e/search.spec.ts`). Browse screens could also remount on a sort or filter `replaceRoute`. Approach step 3 fixes the tree shape. The e2e search and library journeys catch a regression.
- **Redirect timing.** A guard that fails to re-run on a hash change would leave a signed-out viewer on a blank guarded page. Covered by the `hash` dependency and Test plan 3.
- **Settings signed out.** It is now guarded (acceptance item 4). The `AccountSection` signed-out branch (`account-section.tsx:7-10`) stays, because Sign out sets the hash before it clears the session. No e2e or visual scenario visits Settings signed out.
- **Test-file edits.** Reviewers may read the `dev-links.test.ts` allowlist change and the `features.test.tsx` deletion as weakening. The spec ties each one to an acceptance item and a stronger replacement. The PR must list them.
- **Search-route import churn.** `search-route.ts` is deleted. Any missed importer fails `tsc -b`.

Out of scope:

- Dropping the `#/next` prefix (`tasks/backlog.md:191`).
- Changing `parseItemRoute` semantics (backlog line from step 8).
- A typed "signed-in gateway" hook.
- Any change to Back, focus return, or the leave-app flow.
- Any change under `e2e/`, `src-tauri/`, `src/domain/`, or `src/lib/`.
