### Decisions (resolved here from the task, the code, and the docs)

1. **`PlayerView.tsx` becomes `player-screen.tsx`, and the export stays `PlayerView`.** `player-view.tsx` would pair with the existing `src/features/player/player-view.test.tsx`, which tests `PlayerRouteView` in `index.tsx` (its import at line 13: `import { PlayerRouteView } from "./index";`), and `player-view.test.tsx` would collide outright. Acceptance 1 forbids the collision and does not ask to rename existing files. Keeping the identifier keeps every test body, `Parameters<typeof PlayerView>`, and the comments that name `PlayerView` (`playable-item.ts:4`, `use-playback-session.ts:319`, `use-seek-preview.tsx:12`) accurate and unchanged. A file whose name differs from its export already exists here (`index.tsx` exports `PlayerRouteView`).
2. **`player-keymap.ts` goes to `src/features/player/`, not `chrome/`.** Acceptance 1 says "under src/features/player/"; the root keeps it beside `player-screen.tsx` and makes `file-size.test.ts` keep its explicit two-entry list rather than finding the keymap through the chrome directory walk.
3. **Three new rules rather than one.** A single `to: ^src/components/` rule misses a file nobody imports. The three rules cover every cruised module.
4. **The probe is manual, not a committed test.** A committed fixture under `src/components/` would trip the rule it tests, and running dependency-cruiser on a temporary directory needs a copy of `tsconfig.app.json` and the TypeScript 6 loader. The probe output goes in `evidence`.
