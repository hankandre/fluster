## Goal

Record, from the two pinned fixture servers (Jellyfin 10.11.7 and 12.4.0), what every discovery route Fluster will use actually returns, so P16-02, P16-04 to P16-09 build on recorded facts instead of the "unverified" claims in the discovery proposal. The recordings answer four product-shaping questions: can Resume and Next Up be merged and sorted by last play (Q2), can the server leave out old items by date and what happens when a caught-up series gains an episode (Q4/Q14), what does a zero-position `UserData` write do (the withdrawn P16-03), and how does each version report an item's collections (the §2.2 sequel rule). The synthetic sample set gains the metadata and extra files these routes need; a research note states the findings per route and version beside Jellyscale's status for that route.

### 3. Discovery scenes (`record-discovery-fixtures.mjs`)

Use the `fluster-discovery` user for every scene, so the state the scenes set never mixes with `fluster-test` (which the tripwire plays as and leaves positions on). At the start of each scene, reset that user's data on every movie and episode: `DELETE /UserPlayedItems/{id}`, then `POST /UserItems/{id}/UserData` with `PlaybackPositionTicks: 0`, and unfavourite with `DELETE /UserFavoriteItems/{id}`. Use fixed dates so reruns give the same answers: `OLD = 2026-01-05T12:00:00Z`, `RECENT_1 = 2026-06-01T12:00:00Z`, `RECENT_2 = 2026-06-02T12:00:00Z`, `RECENT_3 = 2026-06-03T12:00:00Z`, `CUTOFF_MID = 2026-03-01T00:00:00Z`, `CUTOFF_EARLY = 2025-12-01T00:00:00Z`. Set a position as `PlaybackPositionTicks` at 40% of `RunTimeTicks`.

Set played state and dates with `POST /UserItems/{id}/UserData` (`UpdateUserItemDataDto` has `LastPlayedDate`, `Played`, `PlayCount`, `PlaybackPositionTicks`; SDK `update-user-item-data-dto.d.ts:30-50`). Whether each server honours a client-supplied `LastPlayedDate` is **unverified**. The recorder reads the item back after each write and fails loudly if the date did not stick. If a version ignores it, fall back for that version to `POST /UserPlayedItems/{id}?datePlayed=` for played state and to real `POST /Sessions/Playing` + `/Sessions/Playing/Stopped` reports for positions, in the wanted order with a few seconds between them, use cutoffs relative to the recording time, and say so in the doc.

Wait for the library before scenes: `POST /Library/Refresh`, then poll (2 s, at most 180 s) until the five NFO items list their genres, the Extras film's `LocalTrailers` and `SpecialFeatures` are non-empty, and "Synthetic Collection" exists.

- **Scene A, static routes.** Mark the H.264 movie played at `RECENT_1` and favourite it (so `/Movies/Recommendations` has inputs). Record the routes in the fixture list rows A1 to A11.
- **Scene B, ordering.** Multitrack in progress at `RECENT_1`; ASS in progress at `RECENT_2`; S01E01 played at `RECENT_3`; S01E02 in progress at `RECENT_3` plus one hour (`2026-06-03T13:00:00Z`). Record Resume, Next Up with `enableResumable=true`, and with `enableResumable=false`. Both Next Up calls use `enableRewatching=false`, like the gateway (`gateway.ts:443`).
- **Scene C, ageing.** Multitrack in progress at `OLD`; ASS in progress at `RECENT_2`; S01E01 played at `OLD`. Record Resume; Next Up with no cutoff, with `nextUpDateCutoff=CUTOFF_MID`, and with `CUTOFF_EARLY`.
- **Scene C2, a new episode after the cutoff.** S01E01 and S01E02 played at `OLD` (caught up). Record Next Up with no cutoff (expected empty). Copy `staging/Synthetic Show S01E03.mkv` into `shows/Synthetic Show/Season 01/`, refresh, poll until the episode is indexed, then record Next Up with no cutoff and with `CUTOFF_MID`. In a `finally`, delete the copied file, refresh, and poll until the episode is gone, so no other recorder or the tripwire sees it. - **Scene D, zero-position reset.** Step list: (1) the never-played Multitrack film in progress at `RECENT_1`: read `GET /Items/{id}?userId=` and Resume; (2) `POST /UserItems/{id}/UserData` `{ PlaybackPositionTicks: 0 }`: save status and response; (3) read the item and Resume again. - **Scene E, collections.** Record `GET /Items/{H264 id}/Collections?userId=` (member) and `GET /Items/{Multitrack id}/Collections?userId=` (non-member) with `callStatus`. The collection: the recorder looks for a `BoxSet` named "Synthetic Collection" (`GET /Items?includeItemTypes=BoxSet&recursive=true&userId=`). If the NFO `<set>` did not create one (Jellyfin keeps collections in its config folder, not the media folder, and whether `<set>` alone creates one is **unverified**), it creates it with `POST /Collections?name=Synthetic Collection&ids=<H264>,<AV1>` using the admin `fluster-test` token, then continues. The doc records which way each version got its collection.

At the end of the run, reset `fluster-discovery`'s data as at the start of a scene.

## Risks and out of scope

Risks:

- **A server ignores a client-supplied `LastPlayedDate`.** Then the scenes cannot pin dates. The fallback in Approach §3 (real playback reports, relative cutoffs) still answers the questions; the doc records it.
- **NFOs are read only on a fresh scan.** A long-lived server may need `fixture:down` and a clean setup (Approach §8).
- **The staged episode is left in the library** if the recorder is killed mid-scene C2. The `finally` removes it; the README's staging note tells a person how to clean up by hand. Neither the tripwire nor the other recorder lists `S01E03`, so a leftover file changes no other fixture, but it would change later Next Up recordings.
- **The CI tripwire job generates samples inside the Jellyfin image.** The NFO and new-film steps must use only bash, `printf`, and the image's ffmpeg. A typo there turns the whole CI tripwire red.
- **The refactor of `record-fixtures.mjs`** could change existing fixture output. It is a move of unchanged code; the reviewer diffs the moved functions.
- **Metadata providers on a networked container** could add data. `lockdata` guards the NFO items; the Extras film's trailer and featurette carry no NFO, and their names in fixtures are whatever the server derives from the file name.

Out of scope:

- Any gateway method, type in `types.ts`, PlaybackInfo request, media URL, or UI (acceptance item 8). P16-02 and P16-04 to P16-08 add those.
- Re-recording existing PlaybackInfo, conversion, or item-detail fixtures.
- Adding the new film to the tripwire's sample list.
- Playing trailers or extras (P16-08), and any decision on a remove button (P16-03 withdrawn).
- Q16 (adding P16-02 to P4-01's `depends_on`); that waits for the owner.
- Calling any route on the dogfood server or on Jellyscale.
