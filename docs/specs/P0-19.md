## Findings from the probe

A read-only Node probe ran the current patterns and the candidate patterns below (Node from `.node-version`, 2026-11-15).

- Every form in acceptance 1 and 2 passes the current filters unchanged, so each new test fails today. Example: `safeReason("GET http://[fe80::1]:8096/web/index.html failed")` gives `GET [address]]:8096/web/index.html failed`.
- **The current `ADDRESS` pattern in `safe-reason.ts` is quadratic.** `\b[a-z][a-z0-9+.-]*:\/\/` restarts at every word boundary and scans to the end each time. On `"x-".repeat(n/2)` it took 227 ms at 25 k characters, 883 ms at 50 k, and 3585 ms at 100 k. `"a.".repeat(n/2)` behaves the same. A 1 MB input would take minutes. The existing performance test covers only `redactText`, so nothing catches this today.
- The current credential pattern in `redact.ts` is linear but slow on `"x-"` input: about 100 ms per pass at 1 MB. A second pass for the space form would double that, so the space form must join the existing pass.
- With the candidate patterns, the worst case of 28 adversarial 1 MB inputs was about 130 ms for `redactText` and about 230 ms for `safeReason` when the credential match ran as two passes; the single-pass form measured 97-128 ms for the credential step.

## Approach

### 1. Move `safeReason` and `errorReason` into `src/lib/`

Acceptance 3 makes the coordinator call `errorReason`. The coordinator is shell-neutral core, and `.dependency-cruiser.cjs` forbids it from importing `src/features/`. So the implementation moves to `src/lib/safe-reason.ts`, which imports only `./redact`. The feature file stays as a one-line re-export, so the path in acceptance 2 still names the function, and no UI importer changes. Keep the comment "The only way a player failure reason reaches the screen" with the implementation.

### 2. `redactText`: credentials after a space

Change only `redactCredentialPairs`. Keep it to one credential pass plus one authorization pass.

- A key followed by whitespace is a credential pair only when the value contains a digit or is at least 20 characters long. That keeps "The token expired", "Invalid token", and "token was rejected" intact and catches Jellyfin tokens and play-session ids (32 hex characters).
- Use a lookahead for that test, not a replacer function. A replacer would consume `token token abc123` as key `token`, value `token`, and skip the real value.
- `Authorization` followed by whitespace and a scheme name redacts the rest of the line, as `Authorization:` does today. "Authorization failed" stays.

Candidate patterns, checked by the probe against every existing `errorTexts()` entry and the new forms:

```ts
const KEY = String.raw`(?:[\w-]{0,40}?(?:api[_-]?key|access[_-]?token|token|password|secret|playsessionid)|pw)`;
const VALUE = String.raw`[^&\s",}]`;
const AUTHORIZATION = /(authorization"?(?:\s*[:=]\s*|\s+(?=(?:MediaBrowser|Emby|Bearer|Basic|Digest)\b)))[^\n]*/gi;
const CREDENTIAL = new RegExp(
  String.raw`(\b${KEY}"?(?:\s*[:=]\s*|\s+(?="?(?:${VALUE}*\d|${VALUE}{20}))))"?${VALUE}+"?`,
  "gi",
);
// value.replace(AUTHORIZATION, "$1[redacted]").replace(CREDENTIAL, "$1[redacted]")
```

Probe output: `PlaySessionId abc123` gives `PlaySessionId [redacted]`; `X-Emby-Token abc123` gives `X-Emby-Token [redacted]`; `Authorization MediaBrowser Token abc123` gives `Authorization [redacted]`; `token "abc123"` gives `token [redacted]`; `token token abc123` gives `token token [redacted]`.

The implementer may shape the patterns differently if every test in the Test plan passes. Build the patterns once at module scope.

### 3. `safeReason`: addresses and paths

Order of replacement: `redactText`, then `ADDRESS`, `UNC_PATH`, `WINDOWS_PATH`, `HOME_PATH`, `HOST_PORT`, `POSIX_PATH`. `WINDOWS_PATH` must run before `HOST_PORT` and `POSIX_PATH`.

```ts
const ADDRESS = /(?<![a-z0-9+.-])[a-z][a-z0-9+.-]*:\/\/(?:[^\s"')\[\]]*\[[^\]\s]*\])?[^\s"')\]]*/gi;
const UNC_PATH = /\\\\[^\s"'),;]+/g;
const WINDOWS_PATH = /\b[A-Za-z]:[\\/][^\s"'),;]*/g;
const HOME_PATH = /~\/[^\s"'),;]*/g; // unchanged
const HOST_PORT = /(?<![\w.-])(?:\[[0-9a-f:.%]+\]|\d{1,3}(?:\.\d{1,3}){3}|localhost|(?:[a-z0-9-]+\.)+[a-z]{2,}|[a-z][a-z0-9-]*(?=:\d{4,5}\b)):\d{1,5}\b/gi;
const POSIX_PATH = /(?<![\w:.\]\/])\/+[^\s/"'),;]+(?:\/[^\s/"'),;]*)*/g;
```

- **IPv6 URL.** `ADDRESS` now accepts one bracketed host, with or without user info before it, so the port and route go with it. The lookbehind replaces `\b`; this is the fix for the quadratic scan.
- **Bare host:port.** A host is a bracketed IPv6 literal, a dotted IPv4 address, `localhost`, a dotted name whose last label is two or more letters, or a single label followed by a four- or five-digit port. The result is `[address]`. Digits-only text such as `12:30`, `16:9`, and `01:02:03` is not a host. `status:500`, `code:404`, `line:12`, `Stream #0:1`, and `v0.41.0:5` stay (probe).
- **Single-segment path.** `POSIX_PATH` no longer needs a second segment. The lookbehind still keeps `OpenGL/EGL`, `and/or`, `n/a`, `1/2`, and a lone ` / `.
- **Windows path with forward slashes.** `WINDOWS_PATH` accepts `\` or `/` after the drive colon.
- **UNC path.** `\\server\share\file` becomes `[path]`. `//server/share/file` becomes `[path]` through the leading `\/+` in `POSIX_PATH`; today it leaves a stray `/`.

`MAX_LENGTH`, the trim, and the ellipsis do not change.

### 4. The two coordinator sites

- Line 304 (the engine's error event): `{ ...event, message: errorReason(event.message, "Something went wrong.") }`.
- Line 336 (a failed stop after "ended"): `message: errorReason(error, "The player did not finish shutting down.")`, the fix the review names.
- Line 13: import `errorReason` from `../safe-reason`; drop `redactText` and `redactedErrorMessage` from the `../redact` import if nothing else in the file uses them (`redactError` on line 266 stays).

The fallback on line 304 follows P3-31 Approach 3: each `errorReason` caller supplies existing copy, and "Something went wrong." is the copy `PlayerView.tsx:134` and `use-playback-session.ts:90` already use for a player failure with no text. One behaviour changes: an error event with a blank message used to leave `session.error` as `""`, which the player view treats as no error; it now shows "Something went wrong." No engine sends a blank message today except, possibly, the dev-only browser engine (`browser-player.ts:85`, an `Error` with an empty message). A test covers it.

The screen applies `safeReason` again in `playbackErrorCopy`. The filter is stable on its own output for these forms: `[address]`, `[path]`, and `[redacted]` match none of the new patterns (probe: `safeReason(safeReason(NASTY_REASON)) === safeReason(NASTY_REASON)`).

### Decisions made in this spec

1. `safeReason` and `errorReason` move to `src/lib/safe-reason.ts` with a re-export left in the feature folder, because the boundary lint forbids the coordinator from importing `src/features/`.
2. A space-separated value counts as a credential only with a digit or 20 or more characters. Without that rule, acceptance 5 cannot hold.
3. A single-label host needs a four- or five-digit port. Without that rule, `status:500` and `line:12` would become `[address]`.
4. The 1 MB tests use their own bound of 1000 ms per call. Acceptance 6 allows adding a bound. The measured worst case is 97-230 ms in plain Node, so the existing 250 ms would flake under jsdom and on CI, while a quadratic pattern takes minutes at 1 MB and still fails. The existing 200 k test keeps 250 ms.
5. The error event's fallback is "Something went wrong." (Approach 4).

Issues:

1. **Medium.** The performance Test plan says an explicit timeout makes a quadratic regression "fail fast instead of hanging the run". By the spec's own figures (3585 ms at 100 k characters), the red-first run of the `safeReason` test on `origin/main` takes about six minutes for each of the `"x-"` and `"a."` inputs. Fix: show the red state at a reduced size (for example 50 k characters against a proportionally scaled bound), or put a small-size guard assertion before the 1 MB call so a quadratic pattern fails in under a second. Keep the 1 MB assertion as acceptance 6 requires.
2. **Low.** An IPv6 URL that also carries a credential query leaves a stray bracket: `safeReason("https://[::1]:8096/x?api_key=SECRET")` gives `[address]]` (probe). The optional bracket group is used by the host, so the tail stops at the `]` of `[redacted]`. Nothing leaks, and `origin/main` already does this for any URL with a redacted query.
