## Goal

Make the browser TV form (`<html data-form="tv">`) do what `DESIGN.md` §6, §7.5, §7.14, and §9 now say for D13 to D16, and narrow Backspace to the TV form:

1. TV type tokens give 28 px body text and nothing under 24 px; poster and thumb widths (six posters across) stay.
2. Back on Home, with focus already on the tab row, leaves the app the way the platform requires, through one per-platform exit rule: without a question on Android TV and in the browser TV form; after a "Leave Fluster?" confirmation on Tizen.
3. On a TV card where Enter plays, holding OK opens details; a short press still plays; Menu still opens details.
4. In the TV player, a press of Left or Right on the scrubber moves 10 s; holding scrubs in growing steps with the preview following and the picture held (paused); OK commits; Back returns to where playback was and playback carries on.
5. Up or Down shows the controls without pausing (already delivered by P13-18; this task proves it with a journey and does not rebuild it).
6. Backspace outside text fields is Back only in the TV form. On desktop it does nothing outside text fields; Escape and the Back button remain (owner, 2026-11-13).

Desktop behaviour does not change anywhere except item 6.

### 2. Leaving from Home (D14 B; owner Q1 A)

`src/features/shell/leave-app.ts`:

- `export type TvPlatform = "browser" | "android-tv" | "tizen";` and `export type ExitRule = "leave" | "confirm";`.
- `export function exitRule(platform: TvPlatform): ExitRule` with a `switch`: `"android-tv"` → `"leave"` (Android TV guidelines: do not gate exit); `"browser"` → `"leave"` (the browser TV form follows Android TV); `"tizen"` → `"confirm"` (Samsung's rules ask for a confirmation; ux-audit T3).
- `export function currentTvPlatform(): TvPlatform` reads `document.documentElement.dataset.tvPlatform` at call time (like `isTvForm()`, never cached): `"android-tv"` and `"tizen"` map to themselves, anything else (including absent) is `"browser"`. A future TV shell sets the attribute; tests set it directly (unit) or through `page.addInitScript` (e2e). No URL flag sets it, so in the browser the confirm path is reachable only by a test or a shell.
- `export const LEAVE_APP_EVENT = "fluster:leave-app";` and `export function leaveApp(): void` that dispatches `new Event(LEAVE_APP_EVENT)` on `window`. The browser cannot close a tab it did not open, so the event is the browser's whole effect; the TV shell will listen for it and finish the activity. No `window.close()`.

`src/features/shell/use-back-key.ts`:

- Signature becomes `useBackKey(onConfirmLeave?: () => void): void`. Keep the callback in a ref updated each render, so the effect still registers once with `[]` deps. The only caller is `NavShell` (`signed-in-chrome.tsx:18`); existing tests that call `useBackKey()` keep working.
- Root-tab TV branch: today "if focus is in the nav, return". Change to: if focus is in the nav and `currentNavEntry(hash)` is Home (`hash === HOME_HASH`), `preventDefault()` and `switch (exitRule(currentTvPlatform()))`: `"leave"` → `leaveApp()`; `"confirm"` → `onConfirmLeave.current?.()`. Other root tabs keep P13-18 behaviour (nothing). Back from content on any root tab still focuses the tab row first, so Home takes two presses from the content. The text-field and `MODAL_LAYER` guards stay first, so a Back while the Leave dialog is open never reaches this branch.

`src/features/shell/leave-app-dialog.tsx` (new):

- `export function LeaveAppDialog({ open, onStay, onLeave }: { open: boolean; onStay(): void; onLeave(): void })` renders the shared `Dialog` with `role="alertdialog"` (the `Dialog` comment: "A confirm that interrupts the user is an alertdialog"), `title="Leave Fluster?"`, no body, `onClose={onStay}`, `initialFocus` pointing at Stay, and `actions` in the `Dialog` order "primary last": `<Button variant="secondary">Stay</Button>` then `<Button variant="primary">Leave</Button>`. Copy and roles are the owner's answer: Leave primary, Stay focused, Back closes it.
- Back closes it: `Dialog` already handles Escape (panel `onKeyDown` and the document listener both `preventDefault()` and call `onClose`), and Backspace arrives as Escape in the TV form. Because the Escape is prevented and the dialog matches `MODAL_LAYER`, `useBackKey` ignores it, so closing does not leave. `Dialog` restores focus to the opener (the Home tab entry), so a second Back reopens the dialog, as the platform rule expects.
- Left and Right move between Stay and Leave through `useTvArrowFallback`, which already scopes to the topmost dialog (DESIGN.md §6 line 183).

`src/features/shell/signed-in-chrome.tsx`, `NavShell`:

- `const [confirmingLeave, setConfirmingLeave] = useState(false);` and `useBackKey(() => setConfirmingLeave(true));`.
- Render `<LeaveAppDialog open={confirmingLeave} onStay={() => setConfirmingLeave(false)} onLeave={() => { setConfirmingLeave(false); leaveApp(); }} />` beside `AppShell` (it portals into `document.body`, so placement in the tree only scopes its state to the signed-in shell).

### 3. Hold OK for details (D15 B)

- `src/features/shared/hold-key.ts`: `export const HOLD_MS = 500;` and `export function isHeld(downAt: number, now: number): boolean` (`now - downAt >= HOLD_MS`). 500 ms is a starting value to tune in the dogfood week (Android's long-press timeout is in that range; unverified for current Android TV builds). The scrub uses the same constant.
- `src/features/shared/ui/use-hold-ok.ts`: `useHoldOk(detailsHref: string | undefined)` returns `{ onKeyDown, onKeyUp, onBlur }` for an anchor, active only when `isTvForm()` and `detailsHref` is set; otherwise every handler returns without touching the event (desktop unchanged).
  - `keydown` Enter, no modifier: `preventDefault()` (suppresses the native link activation). If `event.repeat` or a timer is already running, return. Else start a `HOLD_MS` timer.
  - Timer fires: set `location.hash = detailsHref`; install a capture-phase `document` listener that `preventDefault()`s and `stopPropagation()`s every Enter `keydown` until the next Enter `keyup`, then removes itself. This stops a remote's auto-repeat from pressing Play on the detail page.
  - `keyup` Enter: if the timer is still running, clear it and call `event.currentTarget.click()`, which runs the existing `onClick` (`onActivate`) and the link's navigation: the single press plays, now on release.
  - `blur`: clear the timer (no activation).
  - Compose with the existing `ContextMenu` and `i` handler in each component (call both from one `onKeyDown`).
- Use it in `MediaCard` (when `href` and `detailsHref`), `EpisodeRow` (TV form; `detailsHref` is always set), and the hero primary (when `moreInfoHref`), the same three places where Menu opens details (DESIGN.md §9 row "Card, hero primary, TV episode card"). Cards with no `detailsHref` are unchanged.

### 4. TV scrub (D16 B; owner Q2 A)

- `src/features/player/chrome/scrub-step.ts` (pure):
  - `export const SCRUB_TICK_MS = 200;`
  - `export function scrubStep(heldMs: number, durationSeconds: number): number`: 10 s under 1 s held, 20 s under 2 s, 60 s under 4 s, then 120 s; capped at `max(10, durationSeconds / 50)`. Starting values to tune on a real remote.
  - `export function scrubTarget(from: number, step: number, direction: 1 | -1, durationSeconds: number): number` clamps to `[0, durationSeconds]`.
- `src/features/player/chrome/use-tv-scrub.ts`: a hook the `Scrubber` uses only in the TV form. State: the pending position (the Scrubber's existing `seekValue`), `scrubbing`, the held key, the hold timer, and the tick interval.
  - Left or Right `keydown`, not repeat, no modifier: if not `scrubbing`, step the pending position ±10 s and start the `HOLD_MS` timer; if `scrubbing`, step the pending position ±10 s and restart the timer (a press while scrubbing moves the pending point without committing). `preventDefault()`.
  - A repeat `keydown` while the timer or tick is running: `preventDefault()` and ignore. A repeat `keydown` with nothing tracked (the key went down on the player region, which woke the chrome onto the scrubber): start tracking from now with no step, so holding an arrow from hidden chrome still starts a scrub `HOLD_MS` later (owner Q2 A: the waking press itself does not move the time).
  - Timer fires with the key still down: set `scrubbing`, call `onScrubHold(true)`, start the tick; each tick moves the pending position by `scrubStep(elapsed, duration)` in the key's direction. The `ScrubPreview` follows, because it renders at the pending position while the scrubber is focused.
  - `keyup` of the held arrow: stop the timer and tick. If not `scrubbing`, commit (`onSeek(pending)`, today's press behaviour). If `scrubbing`, keep the pending position and wait.
  - Enter while `scrubbing`: `onSeek(pending)`, then `onScrubHold(false)`; clear state. `preventDefault()` and `stopPropagation()` so the player's `ok` action does not also run.
  - Escape while `scrubbing` (Backspace arrives as Escape in the TV form): drop the pending position, `onScrubHold(false)`; no seek. `preventDefault()` and `stopPropagation()` so `usePlayerKeys` (a `window` bubble listener, `use-player-keys.ts:152`) does not leave the player.
  - Blur while `scrubbing`: cancel as Escape does.
  - Without `scrubbing`, Enter and Escape pass through untouched.
  - Clear timers on unmount.
- `Scrubber` gains an optional `onScrubHold?(held: boolean): void` prop and calls `useTvScrub` when `useTvForm()` is true; the desktop key path is unchanged.
- `PlayerView`: pass `onScrubHold`. On `true`: remember `wasPlaying = Boolean(snapshot && !snapshot.paused)` in a ref and, if playing, `execute(() => player.setPaused(true))`. On `false`: if `wasPlaying`, `execute(() => player.setPaused(false))`. The commit's `onSeek` runs first, so playback resumes at the new point; a cancel resumes at the old one. Pausing pins the chrome (`useChromeVisibility` keeps it up while paused).
- The picture is held by pausing because seeking per tick would cost a seek per tick on converted sessions. The pause and resume are reported to Jellyfin like any pause.
