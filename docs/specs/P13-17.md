## Goal

Rebuild Settings (`#/next/settings`) from shared primitives as the Settings shell of DESIGN.md §7.18:

- a vertical section list with four sections (Playback, Subtitles, Account, About & diagnostics);
- every row a `SettingsRow`, with the streaming limits as `Picker`s that keep the same values and storage;
- toasts for invisible changes and for sign-out;
- a redacted Copy diagnostics.

Today (`origin/main`):

- `src/features/settings/settings-view.tsx` (68 lines) shows the limits as two native `<select>`s. The file is on the native-control allowlist (`src/features/native-controls.test.ts:9-11`).
- A bare `<button>Sign out</button>` (`src/features/sign-out-button.tsx`) sits at the bottom of Settings and on the browser-only feature index (`src/features/index.tsx:1,16`).
- There is no Account, Subtitles, or About section, no unbuilt rows, and no user initial in the nav (`src/features/shared/ui/app-nav.tsx:111-113`).

After this task:

- Settings has one `h1` "Settings". On medium and larger windows, a vertical tablist on the left selects the section shown on the right. On compact windows (under 720 px), a list of sections drills into each one.
- Playback holds the two limit `Picker`s (same choices, values, and `fluster.streamingLimits` record) and a disabled "Audio passthrough" row. Changing a limit shows a toast.
- Subtitles holds one sentence.
- Account shows the server name, the address in Mono, the user, a disabled "Stay signed in" row, and Sign out, which ends with a "Signed out" toast.
- About & diagnostics shows the version, the player and libmpv version, the renderer, and the Jellyfin server version, plus Copy diagnostics (seven fields, redacted).
- The nav shows the user's initial after the gear, as a label only.

## Approach

### 1. Primitives (`src/features/shared/ui/settings.tsx`)

`SettingsPage({ label, sections, value, onChange, children })`:

- `sections` is `SettingsSectionItem[]` (`{ id: string; label: string }`). `value` is the selected id. `children` is the selected section's panel.

On medium and larger windows (`useCompact()` false):

- The layout is a two-column grid: the list (`inline-size: var(--settings-nav-w)`) and the panel (`max-inline-size: var(--settings-panel-max)`).
- The list:
  - It is `role="tablist"` with `aria-orientation="vertical"` and `aria-label={label}`.
  - It uses `useRovingFocus("column")`, so it is one Tab stop, on the selected tab.
  - ArrowUp, ArrowDown, Home, and End move focus and select (automatic activation, as in `SegmentedTabs`).
  - Each tab is a `button` with `role="tab"`, `id`, `aria-selected`, and `aria-controls`.
  - The selected tab is `--text-1`, with a 2 px `--art-accent` bar on its inline-start side. The others are `--text-2`.
- The panel is `role="tabpanel"`, with `aria-labelledby` set to the tab.
- ArrowRight on a tab focuses the panel's current roving stop (`[data-roving-item][tabindex="0"]` inside the panel, so the clipboard-fallback `<pre tabIndex={0}>` never matches). If there is none, as in Subtitles, nothing happens.
- ArrowLeft inside the panel focuses the selected tab. It does nothing when the target is a text field (`TEXT_FIELDS` from `use-escape-key.ts`) or a listbox is open.
- Escape does nothing here, so `e2e/nav.spec.ts:61-68` stays green.

On compact windows (`useCompact()` true, `(max-width: 719px)`):

- With no section open, it shows a roving column of `button`s, one per section, each with a trailing `ChevronRight`. Enter or a click opens the section.
- With a section open, it shows a quiet `Button` "Back to settings" with a `ChevronLeft` icon, then the panel. On opening, focus moves to the panel's `h2` (`tabIndex={-1}`).
- Escape (`useEscapeKey`, which skips text fields and handled events) and the back button return to the list and focus that section's button.
- Whether a section is open is local state in `SettingsPage`. `value` still names the section, and opening one calls `onChange`.

`SettingsSection({ id, title, intro?, children })`:

- It renders an `h2` (`--type-heading`, `tabIndex={-1}`) and an optional intro (`--type-body`, 62ch).
- The rows container uses `useRovingFocus("column")` over `[data-roving-item]`. Up and Down move between row controls, and the section is one Tab stop.
- Rows sit on `--surface-1` with `--line` separators.

`SettingsRow({ label, description?, value?, children?, unavailable? })`:

- It is a `div` with `min-block-size: var(--settings-row-h)`.
  - Left: the label (`--type-label`, `--text-1`) and the description (`--type-body`, `--text-2`, with an id from `useId`).
  - Right: `value` (read-only text) or `children` (the control).
- The `useSettingsRow()` context returns `{ descriptionId }`. Pickers pass it as `describedBy`, and buttons as `aria-describedby`.
- **Whole-row hit target** (§7.18):
  - The row is `position: relative`.
  - The control gets `::after { content: ""; position: absolute; inset: 0; }` through `.settings-row-control > :is(button, .ui-picker > button)`.
  - The row draws the focus ring with `:has(:focus-visible)`. Where `:has()` is missing, the control's own ring is the fallback.
  - There is no JavaScript click forwarding.
  - Check that the Picker list still anchors to the trigger.
- When `unavailable` is set to a task id (`"P5-03"` or `"P3-02"`), the row renders:
  - `data-unbuilt={id}` and `aria-disabled="true"`;
  - the description "Not available yet.";
  - no control and no focusable element;
  - the label colour from Approach 8.
- Controls inside rows carry `data-roving-item`. Pass `rovingItem` and `openOnArrow={false}` to `Picker`, so Up and Down move between rows and Enter or Space opens the list.

### 2. Page (`settings-view.tsx`)

```tsx
<main className="settings-page">
  <h1>Settings</h1>
  <SettingsPage label="Settings sections" sections={SECTIONS} value={section} onChange={setSection}>
    {panelFor(section)}
  </SettingsPage>
</main>
```
