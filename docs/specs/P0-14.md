## Findings from the code (what the fix starts from)

All commands below were run on 2026-11-13 at `8a041f9` (the worktree's base, same as the main checkout).

1. **Today's output.** `pnpm lint:boundaries` prints `✔ no dependency violations found (0 modules, 0 dependencies cruised)`, then the `missing-tsc-transpiler` warning, and exits 0.
2. **Why.** dependency-cruiser 18.7.2 declares `supportedTranspilers.typescript: ">=2.0.0 <7.0.0"` (`node_modules/.pnpm/dependency-cruiser@18.7.2/node_modules/dependency-cruiser/src/meta.cjs:14`). 3. **The warning is machine-readable.** With `--output-type json`, `summary.totalCruised` is `0` and `summary.environment.issues` is `[{ name: "missing-tsc-transpiler", severity: "warn", ... }]` (`src/analyze/summarize/index.mjs:74-82`, `verify-environment.mjs:73-89`). dependency-cruiser's exit code counts only rule errors, so the warning never fails the run.

5. **A resolve redirect works (prototype, not committed).** A `node:module` `registerHooks` resolve hook, loaded with `node --import`, that short-circuits `typescript` and `typescript/<sub>` to a TypeScript < 7 directory made the unchanged CLI and config report `✔ no dependency violations found (260 modules, 902 dependencies cruised)` with no environment issue. ## Approach

Milestones in order. Commit each with a Conventional Commit subject naming P0-14, for example `fix(lint): fail the boundary lint when it checks no module (P0-14)`.

### 1. Guard first, and capture today's failure

1. Write `findLintGaps(result, sourceFiles)` in `scripts/lint-boundaries.mjs`. Input: the parsed dependency-cruiser JSON result and the list of non-test `.ts`/`.tsx` paths under `src/` (POSIX, repo-relative, same form as `modules[].source`). Output: an array of message strings, empty when the run is sound. A missing `summary.environment` or `environment.issues` counts as no issues. It checks, in this order:
   - `result.summary.totalCruised === 0` → `ERROR lint:boundaries checked 0 modules, so no import rule ran.`
   - each `result.summary.environment.issues[]` → `ERROR lint:boundaries: dependency-cruiser reported <name>.`
   - each source file not in `result.modules[].source` → `ERROR lint:boundaries did not read <path>.` (cap the list at 20, then "and N more").
   - If there is any message, append one fix line: `Fix: run pnpm install so the typescript-6 dev dependency is present. dependency-cruiser 18.7.2 needs TypeScript below 7 and loads it through scripts/depcruise-typescript-6.mjs. Do not loosen .dependency-cruiser.cjs. See docs/specs/P0-14.md.`
2. Main, run only when `process.argv[1]` resolves to the wrapper file (not `import.meta.main`, whose value under Vitest is unverified), so importing the module from the test runs nothing; a test imports it in a child process and proves no cruise ran:
   - Enumerate the source files by walking `src/` with `node:fs` (`readdirSync` with `recursive: true`), keeping `.ts`/`.tsx` and dropping paths that match the config's test regex `\.test\.tsx?$|^src/test/`. Keep `.d.ts` (`src/vite-env.d.ts` is cruised today). Do not add a glob dependency.
   - Spawn `process.execPath` with `["--import", "./scripts/depcruise-typescript-6.mjs", "node_modules/dependency-cruiser/bin/dependency-cruiser.mjs", "src", "--config", ".dependency-cruiser.cjs", "--output-type", "json"]`, `cwd` the repo root (derive it from `import.meta.url`), stdout captured, stderr inherited. Use `spawnSync` with a `maxBuffer` large enough for the JSON (start at 64 MiB). Using the CLI keeps all of dependency-cruiser's option handling (tsconfig, resolve options, `doNotFollow`, `exclude`); do not re-implement it with the `cruise()` API.
   - If stdout does not parse as JSON, print `ERROR lint:boundaries: dependency-cruiser did not produce a result (exit <code>).` and exit 1. A non-zero child exit with valid JSON is normal: it is the count of rule errors.
   - Run `findLintGaps`. If it returns messages, print them to stderr and exit 1, before any formatting.
   - Otherwise `const { format } = await import("dependency-cruiser")`, `await` `format(result, { outputType: "err-long" })` (it is async), then write its `output` to stdout, print the one-line summary from Acceptance 4, and exit with `exitCode` from `format` (non-zero when a rule fails). `format` needs no compiler, so it can run in the wrapper's own process without the hook.
3. Point `package.json` `lint:boundaries` at the wrapper. Write `scripts/depcruise-typescript-6.mjs` as a no-op for now, or pass `--import` only after step 2; either way **run `pnpm lint:boundaries` now, on TypeScript 7 alone**, and paste the failing output and exit code. This is Acceptance 1 (b).
4. Add the Vitest tests (Test plan 1) and the `vitest.config.ts` include.

Milestone 1 leaves the lint red on purpose. Do not commit it alone: per `AGENTS.md` "Fix a red check before starting the next milestone", commit milestones 1 and 2 together once milestone 2 is green, with the failing output from step 3 already recorded for the evidence.

### 2. Give dependency-cruiser TypeScript 6 (attempt A)

1. `pnpm add -D typescript-6@npm:typescript@6.0.3` (check the resulting `package.json` line reads exactly `"typescript-6": "npm:typescript@6.0.3"`; fix to the exact pin if pnpm wrote a range).
2. **Check the bin before anything else.** `pnpm exec tsc --version` must print `Version 7.0.2`, and `node_modules/.bin/tsc` must reference `typescript/bin/tsc`. If it reports 6.0.3 or references `typescript-6`, attempt A has failed; record it in the Decision log and go to step 3, B. Do not work around it by renaming scripts or calling `tsc` by path.
3. Write the hook in `scripts/depcruise-typescript-6.mjs` with `registerHooks` from `node:module`:
   - At load, find the alias directory with `createRequire(<repo root>/package.json).resolve("typescript-6/package.json")`, and read its `main` (`./lib/typescript.js` for 6.0.3).
   - In `resolve(specifier, context, nextResolve)`: if `specifier === "typescript"`, return `{ url: pathToFileURL(<dir>/<main>).href, shortCircuit: true }`; if it starts with `"typescript/"`, return the file URL of `<dir>/<rest>`; otherwise `return nextResolve(specifier, context)`. Return the short-circuit form; `nextResolve` with a file URL fails on the `require` path (Finding 5).
   - Redirect regardless of the importer. The hook is loaded only into the lint's child process, and in that process only dependency-cruiser asks for `typescript`. That keeps the hook short and avoids matching store paths.
   - Add a two-line header comment: what it does, and "remove with the `typescript-6` alias when dependency-cruiser supports the app's TypeScript (P0-14)". No longer justification.
4. Run `pnpm lint:boundaries`. Expect the summary line with about 260 modules and `223/223` source files (the count rises if files were added since `8a041f9`), and no environment issue.
5. Run `pnpm check` and `pnpm audit --audit-level moderate`. Both must pass.

## Risks and out of scope

- **Bin clash (Finding 6).** Mitigated by the stop-and-check in Approach 2.2 and fallback B. A later `pnpm install` could in theory flip the link; the evidence records the pnpm version that was checked (11.3.0, `packageManager` in `package.json`).

- **TypeScript 6 parsing `tsconfig.app.json`.** The prototype used 5.7.3; 6.0.3 is **unverified** with this tsconfig. The options in it (`moduleResolution: "Bundler"`, `target: "ES2022"`, `jsx: "react-jsx"`, `types`) are all valid in TypeScript 6 to the refiner's knowledge, but a deprecation diagnostic would surface as an environment issue or a crash, both of which the guard catches.
- **Dependabot and the alias.** Whether Dependabot keys an npm alias by the alias name (`typescript-6`) is **unverified**. If its first PR against the alias proposes 7.x anyway, close it and log the finding in `tasks/backlog.md`.
- **Violations found on `main`** may land in files other agents are editing (P13-22, P13-23, P13-24, P13-34). Defer those per Acceptance 6 rather than editing a claimed milestone.
- **Out of scope:** running `typecheck:core`, `typecheck:integration`, and `test:no-test-engine` in CI (P0-15); a hooks lint and unused-code flags (P0-16); upgrading dependency-cruiser to a beta; new rules or tighter rules in `.dependency-cruiser.cjs`; type-checking `scripts/` (no tsconfig covers it today; the new `.mjs` files follow the repo's existing `scripts/*.mjs` pattern).
