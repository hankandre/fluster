## Goal

`pnpm check` runs three guards that CI never runs: `test:no-test-engine`, `typecheck:integration`, and `typecheck:core` (`package.json:27` against `.github/workflows/ci.yml:54-61` on `origin/main` `02eaa5c`). This task adds the three steps to CI's frontend job and adds a test that fails whenever `pnpm check` gains a non-Rust step that the frontend job does not run.

### 0. Update the branch

### 1. Parity test, red first (`test(ci): fail when pnpm check runs a step CI does not (P0-15)`)

In `scripts/ci-check-parity.test.ts`:

1. `checkSteps(checkScript: string): string[]`: split on `" && "`, trim each part. Throw `Error("ERROR ci parity: pnpm check must be steps joined by ' && '; cannot read: <part>")` if any part contains `;`, `||`, `|`, or a newline, or does not start with `pnpm ` or `cargo `. Return all steps.
2. `nonRustSteps(steps)`: drop steps that start with `cargo `.
3. `frontendRunSteps(ciYaml: string): string[]`: split into lines; find the line exactly `  frontend:` (two-space indent, as every job key in `ci.yml`); throw if absent. Collect following lines until the next line matching `/^  \S/` (next job) or end. From those, take lines matching `/^\s+(?:- )?run:\s*(.+)$/`; if the captured value starts with `|` or `>` throw `"ERROR ci parity: the frontend job has a multi-line run step; this test reads single-line run steps only"`. Strip a trailing ` # comment` only if it starts with ` #`; trim. Return in order. A run value that itself contains ` #` is cut and then fails as a missing step (loud, not silent); a fixture test documents this. This is a narrow text reader, not a YAML parser; the throws make any shape it cannot read fail loudly instead of passing.
4. `findParityGaps(check: string[], ci: string[]): string[]`: one message per missing step, `ERROR ci parity: pnpm check runs '<step>' but CI's frontend job does not. Add '- run: <step>' to the frontend job in .github/workflows/ci.yml in pnpm check's order.` Then, if none is missing, check order: the indices in `ci` of the check steps must be increasing; if not, one message `ERROR ci parity: CI's frontend job runs pnpm check's steps in a different order: <ci order>; pnpm check order: <check order>.`
5. Real-file tests: read `package.json` and `.github/workflows/ci.yml` with `readFileSync` from paths built with `fileURLToPath(new URL("../…", import.meta.url))`. Assert `findParityGaps(nonRustSteps(checkSteps(pkg.scripts.check)), frontendRunSteps(yaml))` equals `[]` (use `toEqual([])` so the failure prints the messages). Separately assert the Acceptance 1 order: `ci[ci.indexOf("pnpm build") + 1] === "pnpm test:no-test-engine"`, and `indexOf` of `test:no-test-engine` < `typecheck:integration` < `typecheck:core` < `test:e2e`, and that every one of those five is present (`indexOf !== -1`).
6. Fixture tests as listed in Acceptance row 2 (a).

Run `pnpm test scripts/ci-check-parity.test.ts` before step 2: the real-file test must fail with the three missing-step messages. Paste the output into evidence. Commit the test together with step 2 (a red commit would fail `pnpm check`); the red run is evidence, not a commit.

## Risks and out of scope

- **Text reader instead of a YAML parser.** It reads only single-line `run:` steps and two-space job keys. Mitigated by throwing on any shape it cannot read, so a future reshape of `ci.yml` (a multi-line `run`, a renamed job) fails the test loudly and someone updates the reader. Adding a YAML dependency is out of scope (supply-chain cost for one test).
- **Exact string match.** A CI step written differently (for example `pnpm run typecheck:core` or extra flags) is reported as missing. Accepted: it keeps the two lists literally in sync, and the message says what to add.
- **Environment differences in CI.** `typecheck:*` use the repo's `tsc` 7.0.2 after `pnpm install --frozen-lockfile`; `test:no-test-engine` needs `dist/`, which the preceding `pnpm build` creates. `release-appimage.yml:40-42` already runs build then `test:no-test-engine` on `ubuntu-22.04`. Low risk; if a step fails in CI, fix the cause.
- **CI time**: two `tsc -p` runs plus a grep, seconds (D1: "the cost is CI seconds").
- **Throwaway commit history**: rebase merge keeps the throwaway and revert commits on `main`, as with P0-14 (`1a3af96`, `1a0edaa`). The PR says so.
- **Out of scope**: running the Rust step of `pnpm check` in the frontend job (it runs in `rust-checks`); a parity check for the Rust step against `rust-checks` (append to `tasks/backlog.md` only if the implementer judges it worth a task); D2 to D6 (hooks lint, macOS `cargo check`, and so on: P0-16 and backlog); changing `pnpm check` or `release-appimage.yml`; fixing `src/app/compose.ts:15` importing the e2e engine (backlog line 187; CI now guards its output).
