## Goal

Make search a designed screen that goes straight to what the user picked. Today:

- The page `h1` is the route name "Search", followed by a small labelled text field (`.search-box`, `max-width: 32rem`, `src/styles.css:114`).
- Suggestions are text only: "Arrival (2016) Movie" (`search-box.tsx:11-14`, `:131`).
- Choosing a movie or episode suggestion runs a text search for its name instead of opening it (`search-box.tsx:63-73`, audit P1; the comment cites P3-08, which is done).
- Results are three grids under plain `h2`s ("Movies", "Series", "Episodes"), with a native "Load more" button and `RowError` ("Could not load …", native `button.text-button`) (`search-results.tsx:12-16`, `:37`, `:46-51`).
- The empty page is a label and a field; no results is the plain sentence `No results for "{term}".` (audit P1).
- Arrow keys cannot leave the field, and Up and Down do not cross result groups (rework-plan line 145).
- `/` does nothing (DESIGN.md §9 lists it as "New in P13").

After this task:

- A large `SearchField` (DESIGN.md §7.13: `--type-title` text, 64 px tall, search icon, clear button) takes focus when the page opens. The combobox semantics stay exactly as they are (role, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-autocomplete="list"`, the listbox, `aria-selected`, the "N suggestions available" status, the accessible name "Search movies, series, and episodes").
- Each suggestion is a `SearchSuggestion` row: a 40 px poster, the title, and a meta line with the year and the type ("2016 · Show"). Episodes show the series and number instead of the year.
- Choosing a movie or episode suggestion opens its detail (`#/next/item/{id}`). A series suggestion opens the series (`#/next/series/{id}`). One activation, no intermediate search.
- Results stay on Enter (Q13 A). They render as grouped horizontal `MediaRow`s titled "Movies", "Shows", and "Episodes" (Q14 A, "Not asked"). One page of 40 loads first, and a "Load more" button sits at the end of the results section. Episode result cards open the episode's detail (Q9 A).
- Designed states: start ("Search your libraries"), loading (row skeletons), no results (`No matches for "{term}"`), error (`InlineError` "Couldn't load search results." with Retry), and a failed next page ("Couldn't load more results." with Retry). Copy comes from DESIGN.md §10.
- Arrow keys alone work: Down from the field (with no suggestion list) moves into the first result row, Up and Down move between rows and Load more, and Up from the first row returns to the field.
- Pressing `/` outside a text field focuses the search field. On any other signed-in screen it opens Search with the field focused.

## Approach

### 1. Page frame (`search-view.tsx`)

`SearchView({ term: routeTerm })`:

- `const term = routeTerm?.trim() || undefined;` (kept: a blank term is the start page).
- Reads `useSession()` and sets the hash to `#/next/sign-in` without a gateway, as `HomeView` does (`home-view.tsx:25-27`).
- Renders `<main className="search-page">` with `<h1 className="visually-hidden">Search</h1>` (the Home precedent, decisions Q2 A: a collection screen, not one item; §11.6 one `h1`). The `h1` is not focused (Approach 3 focuses the field instead).
- Inside: `<SearchBox gateway initialTerm={term ?? ""} />`, then `term ? <SearchResults gateway term /> : <SearchStart />`.
- `SearchView` must not remount between `#/next/search` and `#/next/search/{term}`. Both routes already render `<SearchView>` at the same position under `SignedInChrome` (`src/app/App.tsx:109-110`, `:151-152`), so the field keeps focus and its text after Enter. Do not add a `key` that includes the term.

CSS (`src/features/search/search.css`): `.search-page` is `position: relative; z-index: var(--z-content); padding-block: var(--space-6) var(--space-8)`. The `SearchBox` form (renamed from `.search-box` to `.search-form`, so the old global rule can go) and the states use `padding-inline: var(--gutter)`; `.search-form` is `position: relative` so the suggestion list anchors to it. `.search-results` is a flex column with `gap: var(--space-7)` and `padding-inline: var(--gutter)`, like `.home-rows` (`home.css:9-14`), so rows bleed the same way.

### 2. Hint mapping (`cards.ts`, `catalog.ts`)

`toSearchHints` keeps dropping hints without `Id`, `Name`, or a known kind. For a kept hint:

- `image`: `{ itemId: hint.Id, type: "Primary", tag: hint.PrimaryImageTag }` when `typeof hint.PrimaryImageTag === "string" && hint.PrimaryImageTag.length > 0`. Hints carry no BlurHash (the SDK `SearchHint` has no `ImageBlurHashes`), so there is no `blurHash`.
- `seasonNumber` from `ParentIndexNumber` and `episodeNumber` from `IndexNumber`, only for `kind === "Episode"`, each only when not null.

The image URL is built by the existing `gateway.imageUrl` through `imageUrlFor(gateway)` (`card-view.ts:13`). It holds only the item id, image type, tag, width, quality, and format, no credential (`gateway.ts:665-673`). It is not a media URL, so Playback Negotiation is not involved.

Width: `SUGGESTION_IMAGE_WIDTH = 120` in `search-box.tsx` (2× the TV art width of 60 px, 3× desktop).

### 3. Field and combobox (`SearchField`, `search-box.tsx`)

`SearchField` props: `id`, `label`, `value`, `listId`, `expanded`, `activeDescendant?`, `inputRef`, `onChange(value)`, `onKeyDown`, `onBlur`, `onClear()`.

Markup:

```tsx
<div className="ui-search-field" data-spatial-row="">
  <label htmlFor={id} className="ui-search-field-label">{label}</label>
  <div className="ui-search-field-control">
    <Search className="ui-search-field-icon" aria-hidden="true" />
    <input id={id} ref={inputRef} type="text" role="combobox" autoComplete="off" spellCheck={false}
      aria-autocomplete="list" aria-expanded={expanded} aria-controls={listId}
      aria-activedescendant={activeDescendant} data-search-field="" data-roving-item="" ... />
    {value ? <Button variant="icon" aria-label="Clear search" onClick={onClear}><X aria-hidden="true" /></Button> : null}
  </div>
</div>
```

- `data-spatial-row` on the wrapper and `data-roving-item` on the input let `moveToAdjacentRow` reach the input from the first result row (Up). Do not attach `useRovingFocus`'s `onKeyDown` to this wrapper: it would take Left and Right from the text caret.
- Style: the control is `min-height: var(--search-field-h)`, `--surface-2` fill, `1px solid var(--line-strong)` border, `--radius-control`, `padding-inline: var(--space-4)`; the input text is `font: var(--type-title)`, `--text-1`, transparent background, no border; the label is `--type-label`, `--text-2`, above the control (§7.19). The icon is `width` and `height: var(--space-5)` in CSS (no literal size). The ring shows on the control with `:focus-within` when the input is `:focus-visible` (use `.ui-search-field-control:has(input:focus-visible)` with `box-shadow: var(--focus-ring)`), and in forced colours the ring uses `Highlight` like the base rule. The block is at most `var(--measure)` wide (`--measure` resolves against the body font of the wrapper).
- `type="text"` stays (not `search`), so WebKit adds no second clear control.

`SearchBox` keeps today's state and rules: `text`, `debounced` (250 ms), `edited`, `open`, `active`, `MIN_TERM_LENGTH = 2`, the query key `["search", scope, "hints", debounced]` with `gcTime: 0` and `retry: false`, and the abort through the query signal. Changes:

- Focus on open: `useEffect(() => inputRef.current?.focus(), [initialTerm])`. The field takes focus when the page mounts and when the route term changes from outside (Back and Forward between result pages). After Enter, focus is already in the field.
- `choose(hint)`: `setOpen(false); setActive(-1);` then a `switch (hint.kind)`: `"Movie"` and `"Episode"` → `goTo(itemRoute(hint.id))`; `"Series"` → `goTo(seriesRoute(hint.id))`. Import `itemRoute` and `seriesRoute` from `../routes`; `search-route.ts` keeps `SEARCH_ROUTE` and `searchResultsRoute` and stops re-exporting `seriesRoute` once nothing imports it from there.
- `onKeyDown`:
  - `ArrowDown`: when `hints.length > 0`, as today. Otherwise, call `moveToAdjacentRow(wrapper, input, 1)` (wrapper = `input.closest("[data-spatial-row]")`) and `preventDefault()` when it moved.
  - `ArrowUp`: as today (no spatial move up; the nav is reached with Shift+Tab, and Up into the nav is P13-18).
  - `Escape`: when `expanded`, close the list as today. When the list is closed and `text` is not empty, clear it (as `onClear`) and `preventDefault()`. This is the optional Escape behaviour of the ARIA APG combobox pattern. An empty field leaves Escape alone, so `e2e/nav.spec.ts` "Escape leaves #/next/search where it is" still holds.
  - `Enter`: as today.
- `onClear`: `setText(""); setEdited(true); setOpen(false); setActive(-1); inputRef.current?.focus();`. The route does not change: results for the last submitted term stay under the field until the next Enter.
- The listbox `ul` keeps its `id`, `role="listbox"`, `aria-label="Suggestions"`, and `hidden={!expanded}`; it gets `className="ui-suggestions"`. Options render through `SearchSuggestion`. The status paragraph is unchanged.

### 4. Suggestions (`SearchSuggestion`, `search-hint-label.ts`)

`search-hint-label.ts` (pure, no React):

- `kindLabel(kind)`: `"Movie"` → "Movie", `"Series"` → "Show", `"Episode"` → "Episode" (§10 "Movies, shows, and episodes"; the group is "Shows").
- `suggestionMeta(hint)`: parts joined with " · ".
  - Movie and Series: `[year?, kindLabel]`, so "2016 · Movie", "2012 · Show", or "Show".
  - Episode: `[seriesName?, "S{s} · E{e}" when both numbers, kindLabel]`, so "Harbor Lights · S1 · E2 · Episode". The year is left out for episodes: the series and number identify an episode, and today's label shows the series, not a year (`search-box.tsx:12`).
- `suggestionLabel(hint)`: `[name, ...metaParts].join(", ")`, so "Arrival, 2016, Movie" and "The Keeper's Log, Harbor Lights, S1 · E2, Episode".

`SearchSuggestion({ id, title, meta, label, image, variant, selected, onChoose })`:

```tsx
<li id={id} role="option" aria-selected={selected} aria-label={label} className="ui-suggestion"
    onMouseDown={(event) => event.preventDefault()} onClick={onChoose}>
  <span className="ui-suggestion-art" data-variant={variant} aria-hidden="true">
    <CardImage image={undefined} src={image} />
  </span>
  <span className="ui-suggestion-text" aria-hidden="true">
    <span className="ui-suggestion-title">{title}</span>
    <span className="ui-suggestion-meta">{meta}</span>
  </span>
</li>
```

- `variant` is `"poster"` for movies and series and `"still"` for episodes; see Open question 1 for the episode frame. ### 7. The `/` shortcut (`use-search-shortcut.ts`)

```ts
export function useSearchShortcut(): void
```

- One `document` `keydown` listener added in an effect and removed on unmount.
- Acts only when `event.key === "/"`, `!event.defaultPrevented`, `!event.isComposing`, and no Ctrl, Meta, or Alt (Shift is allowed: some layouts need it for `/`).
- Ignores targets that match `TEXT_FIELDS` or are content-editable (reuse `TEXT_FIELDS` from `use-escape-key.ts`), and targets inside `[role="dialog"]`, `[role="listbox"]`, or `[role="menu"]` (an open Picker or Dialog keeps its keys).

- `NavShell` is the only caller, so the shortcut is live on every signed-in page with the nav and nowhere else (not the player, sign-in, or gallery: `App.tsx` `chromeFor`).
