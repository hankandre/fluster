## Goal

Run Jellyscale as a third pinned fixture server next to Jellyfin 10.11.7 and 12.4.0, with the same generated samples and the same two commands (`pnpm fixture:up`, `pnpm fixture:setup`), locally and in CI. Record Jellyscale's answers to the core's main calls as contract fixtures. Keep a test that lists every endpoint the core calls, says whether the pinned Jellyscale answers it, and names the Jellyscale issue for each gap.

This task makes the server and the evidence. T2-09 then runs the tripwire against it, T3-05 runs the wire test against it, and T10-03 does the full compatibility pass.

## Approach

### Milestone 1: the server starts from the pinned commit and lists the samples

Compose services:

```yaml
x-jellyscale-commit: b920b193cd6f7835dec70198477a07216118b34d   # the one pin; every other mention must agree

services:
  # ...the two Jellyfin services as today...
  jellyscale-db:
    image: postgres:18.7-alpine3.24@sha256:ff64c9e3bdf8e2120107d3559de8db314e8305f7e38c5105903c6295876738ff
    environment:
      POSTGRES_HOST_AUTH_METHOD: trust   # not published; no password exists
    healthcheck: { test: [CMD, pg_isready, -U, postgres], interval: 2s, retries: 30 }

  jellyscale:
    image: octave-jellyscale:b920b193cd6f
    build:
      context: https://github.com/jellyscale-org/jellyscale.git#b920b193cd6f7835dec70198477a07216118b34d
      target: server
      args: { REVISION: b920b193cd6f7835dec70198477a07216118b34d }
    command: ["--roles=all", "--config=/config/jellyscale.json"]
    env_file: [{ path: ./.jellyscale.env, required: false }]
    environment:
      JELLYSCALE_DATABASE_URL: postgres://postgres@jellyscale-db:5432/postgres?sslmode=disable
    volumes:
      - ../samples:/media:ro
      - ./jellyscale-config.json:/config/jellyscale.json:ro
    ports: ["127.0.0.1:18098:8096"]
    depends_on: { jellyscale-db: { condition: service_healthy } }
    healthcheck: { test: [CMD, wget, -q, -O, /dev/null, "http://127.0.0.1:8096/readyz"], interval: 2s, retries: 60 }
```

- The Postgres digest is the one Docker Hub lists for `18.7-alpine3.24`, updated 2026-11-18. The implementer checks it again with `docker buildx imagetools inspect` before committing.
- `required: false` lets `fixture:down` run without the file. A missing file makes Jellyscale refuse to start (`adminUser needs JELLYSCALE_ADMIN_PASSWORD`), so `up --wait` fails loudly. `fixture-up.sh` always writes the file first.
- The Jellyfin services keep their tag pins, as today.

Run `bash tests/integration/fixture-up.sh`, time the build, and sign in by hand. Record:

- that Compose built from the commit fragment;
- the build time, cold and cached;
- which samples Jellyscale lists as Movie and Episode: the versions film, the BluRay folder, the ISO, the extras film and its trailer, the special;
- whether the samples (made by the CI runner's uid, mode 644) are readable by the container's uid 1000.

Write these into `packages/core/tests/fixtures/jellyscale/README.md`.

Stop conditions, reported to the coordinator, not worked around:

- If Compose refuses the commit fragment, use the fallback: `fixture-up.sh` reads `x-jellyscale-commit` from the compose file and runs `docker buildx build 'https://github.com/jellyscale-org/jellyscale.git#<sha>' --target server --build-arg REVISION=<sha> -t octave-jellyscale:<12 hex>` when the image is missing. The service then drops `build:` and sets `pull_policy: never`. The item 2 test reads the pin from `x-jellyscale-commit` in both designs, so it passes either way. Record the choice in the decision log.
- If a cold build makes the CI `tripwire` job exceed 30 minutes, stop and report. Do not raise the timeout without the owner.
- If the samples cannot be read in the container, stop. Changing sample permissions touches `generate-samples.sh` and CI.

### Milestone 2: setup and the secret check

The new Jellyscale branch in `setup-servers.sh` runs after the Jellyfin loop. It has its own small `jellyscale` function so the Jellyfin code stays as it is.

1. Wait for `GET /readyz` to answer 200 (60 tries, 2 s apart).
2. Read the password from `.jellyscale.env` with `grep`/`cut`, never `source`. If the file is missing, print that `pnpm fixture:up` makes it and exit 1.
3. Sign in as `octave-test` with the body on stdin, using the same `authenticate` function. It fails with a clear message if there is no `AccessToken`. A database from before the env file was regenerated gives 401; then print "run pnpm fixture:down, then pnpm fixture:up".
4. Wait for the scan, for up to 120 s:
   - Poll `GET /Items?Recursive=true&IncludeItemTypes=Movie,Episode,Series` with the header file.
   - Continue once the `Synthetic H264` film, the `Synthetic Show` series and at least one episode are found (Jellyscale leaves `SeriesName` null on episodes, so an episode cannot be matched to its show by name) and `TotalRecordCount` has not changed for 3 polls 2 s apart.
   - Log the counts. Fail with the counts when time runs out.
   - The count is not fixed, because the opt-in conversion samples change it.
5. Write the three `jellyscale_*` keys with the same atomic `grep -v` / `mv` / `chmod 600` pattern as `save_credentials`.
6. Log `user octave-restricted and octave-discovery skipped: Jellyscale has no user API (backlog)`.

`check-no-secret.mjs` is a pass-through filter. After stdin ends, it loads the `_password` values from `.credentials` and the `JELLYSCALE_ADMIN_PASSWORD` value from `.jellyscale.env`, then checks the buffered output. It must buffer: setup writes the file during the run, so the values are known only at the end. It prints the output, then exits 1 naming the leaking key if a value appears. It takes the two file paths from `OCTAVE_FIXTURE_DIR` (default `tests/integration/`) so the unit test can feed it temporary files.

### Milestone 3: recorder, fixtures and endpoint inventory

The recorder, `record-jellyscale-fixtures.ts`, is run by hand and committed with its output, as the other recorders are.

1. Read `.credentials` (`readCredentials`).
2. Sign in raw with `callStatus` for `signin-octave-test.json`: that raw answer is the one recorded, because `FetchTransport.signIn` hands the gateway only a session id, not the body. The raw token it holds is the one `makeScrubber` and the final grep use. Then build `JellyfinGateway(url, webCrypto, recordingTransport, "octave-fixtures")` and call `gateway.login` through the recording transport, a second sign-in, so the gateway holds a transport session (`FetchTransport.request` refuses any session it did not create, `fetch-transport.ts:115-118`). `recordingTransport` wraps `FetchTransport` and copies each `request`'s `{status, body}` into a map keyed by scene. `FetchTransport#strip` already replaces the gateway session's token with `REDACTED` in those bodies, so `makeScrubber` is still needed for the host, ids and play sessions.
3. Run these scenes:
   - `userViews()` for `userviews.json`.
   - `latestInLibrary(<Movies view id>)` and `latestInLibrary(<Shows view id>)` for `latest-movies.json` and `latest-shows.json`.
   - Set a position on the H264 film with `POST /UserItems/{id}/UserData` and `{PlaybackPositionTicks: 30000000}` (implemented on Jellyscale), then `resumeItems()`, for `resume-in-progress.json`.

The inventory test, `jellyscale-endpoints.test.ts`, builds the core's endpoint list from three sources and takes their union:
