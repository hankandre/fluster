## Goal

Make a library read like a library. Today the page `h1` is the route name "Browse", and the library name is a small `h2` (`src/features/browse/browse-view.tsx:30`, `:68`). Sort is two native selects and filters are three native checkboxes, one of which renders as a 32 px white square (`library-grid.tsx:78-101`; audit.md Top 6, "Browse and library grid"). Paging is a plain "Load more" button (`library-grid.tsx:117`). A developer link "Back to libraries" leads to a Libraries tile page (`#/next/browse`) that duplicates the nav. A collection is titled "Collection" (`collection-view.tsx:7`).

After this task:

- The library name (or the collection name) is the `h1`, in `--type-title`, and takes focus when the page opens.
- Under it, a sticky `BrowseToolbar` (DESIGN.md §7.12): one Sort `Picker` with eight spelled-out choices (Q12 B), three filter `ToggleChip`s (Unwatched, Favorites, In progress), and the item count on the right ("248 items"). It sticks under the nav and follows the nav when it hides.
- The poster grid loads the next page automatically when its end nears the viewport. A focusable "Load more" button stays as the keyboard and screen-reader fallback, and "N more items loaded" is still announced.
- Loading, empty, filtered-empty, error, and not-found states use the shared primitives and the DESIGN.md §10 copy.
- The Libraries page (`#/next/browse`) is removed (Q11 A). The nav keeps scrolling and gains an edge fade where it overflows.
- Focus resting 300 ms on a movie card prefetches its detail, as on Home (DESIGN.md §9; rework-plan.md line 169).
- Home's "Latest in {library}" rows end with a "See all" tile, the last item of the row and not a card, that opens the library sorted "Newest added first" (Q5 A, open question 1 answer C; rework-plan.md line 153).

## Approach

### 1. Page frame and states (`browse-view.tsx`, `collection-view.tsx`)

- Signed out: keep today's redirect to `#/next/sign-in`.
- `BrowseView({ libraryId })` reads `userViews` with today's key `["browse", scope, "views"]` and `gcTime: 0`. It renders `<LibraryContent key={libraryId} …>` so moving between libraries in the nav remounts it: sort, filters, and paging reset ("Not asked": not remembered between visits) and the `h1` takes focus again.
- `<main className="library-page">`:
  - Views pending: an `h1` holding a visually hidden "Library" and a `Skeleton shape="line" width="var(--skeleton-title-w)"`, the toolbar skeleton, and the grid skeleton. `aria-busy="true"` on the grid section.
  - Views error: a visually hidden `h1` "Library", then `InlineError spatial message="Couldn't load your libraries." onRetry={refetch}`.
  - Library id not in the list: `Notice` with title "This library isn't available", body "It may have been removed, or this account can't see it.", and a "Go home" `ButtonLink` to `#/next/home`. The `h1` is the Notice title (as `ItemGoneNotice` does) and takes focus.
  - Found: `h1` = `library.name`, `--type-title`, focused by `useHeadingFocus(true)` once rendered. Then `LibraryGrid`.
- Item types: keep `itemTypesFor` (`boxsets` gives `["BoxSet"]`, else `["Movie", "Series"]`).
- `CollectionView({ collectionId })`: the same frame. The name comes from `useQuery({ queryKey: detailKey(gateway, collectionId), queryFn: gateway.itemDetail })`, so a dwell prefetch or a later detail visit can share it. Pending: the skeleton `h1` as above, and the grid loads in parallel. `ItemNotFoundError`: the existing `ItemGoneNotice` from `src/features/detail/detail-states.tsx`, and no grid. Any other error: a visually hidden `h1` "Collection" plus `InlineError spatial message="Couldn't load this collection's name." onRetry`, and the grid still shows (the name is not needed to browse). `itemTypes` stays `["Movie", "Series"]`.

### 2. Sort model (`library-sort.ts`, Q12 B)

One `Picker`, each field and direction spelled out, in this order:

| id | Label | `sortBy` | `sortOrder` |
|---|---|---|---|
| `name-asc` (default) | Name A to Z | `SortName` | `Ascending` |
| `name-desc` | Name Z to A | `SortName` | `Descending` |
| `added-desc` | Newest added first | `DateCreated` | `Descending` |
| `added-asc` | Oldest added first | `DateCreated` | `Ascending` |
| `released-desc` | Newest release first | `PremiereDate` | `Descending` |
| `released-asc` | Oldest release first | `PremiereDate` | `Ascending` |
| `rating-desc` | Highest rated first | `CommunityRating` | `Descending` |
| `rating-asc` | Lowest rated first | `CommunityRating` | `Ascending` |

`parseLibrarySort(value)` returns the id for a known string and `undefined` otherwise; M4 uses it for `?sort=`. The `BrowseSortBy` and `BrowseSortOrder` domain types are unchanged.

### 3. `BrowseToolbar` (shared) and its state (`library-grid.tsx`)

- Markup: `<div role="toolbar" aria-label="Sort and filter" className="ui-toolbar" data-spatial-row>` with `useRovingFocus("row", { spatial: true })`. Inside: the `Picker` (`label="Sort"`, `hideLabel`, `appearance="pill"`, `rovingItem`), then `<div role="group" aria-label="Filters">` with three `ToggleChip`s carrying `data-roving-item`, then `<p className="ui-toolbar-count">` when `count` is set.
- The Picker trigger keeps its own Up and Down (open the list), so from the trigger Down opens the menu; from a chip, Down moves spatially into the grid. This matches the detail action bar's version picker.
- Layout: one flex line with `gap: var(--space-3)`; the count takes `margin-inline-start: auto`, `--type-meta`, `--text-2`, `font-variant-numeric: tabular-nums`. On compact windows the line wraps: Sort and the count on the first line, the chips on the second.
- The count is plain text, not a live region. Sort and filter changes are announced by the controls' own state (`aria-pressed`, the trigger's name); loads keep the existing status text.
- State in `LibraryGrid`: `sortId` (default `name-asc`, initial value from a prop in M4) and `filters: BrowseFilter[]`. The query key is `["browse", scope, "items", parentId, itemTypes, sortBy, sortOrder, filters]`, so any change starts again at page one (today's behaviour). The toolbar stays mounted while the new first page loads, so focus stays on the control the user changed.
- Count text: `itemCountLabel(n)` uses `Intl.NumberFormat()` and "item" or "items". It shows the first page's `totalCount`; no count while the first page is pending or when the server sent none.

### 4. Gateway: first-page count

`libraryItems` sends `enableTotalRecordCount: true` only when `startIndex === 0`, which ARCHITECTURE.md §3 and the jellyfin-api skill allow ("unless paging needs counts"). The count reflects the active filters, because the server counts the same query. Later pages send `false` as today. No new endpoint, field, or auth change.

### 5. Sticky toolbar under a hiding nav

- `.library-page .ui-toolbar-wrap { position: sticky; inset-block-start: var(--sticky-top); z-index: var(--z-content); background: var(--surface-0); }` with `transition: inset-block-start var(--dur-base) var(--ease-out)`, the same duration and curve as the nav's slide, so the toolbar moves up with the nav. Reduced motion sets the durations to 0 (tokens).
- `--sticky-top` lives in `shell.css` (Files to touch). `AppShell` already sets `data-hidden` on `.app-nav`, and `.app-content` is its sibling, so no new state or prop is needed. The TV form never hides the nav (`app-shell.tsx:39`).
- Focus is never obscured (DESIGN.md §9, WCAG 2.4.11): `LibraryPage` measures the toolbar with a `ResizeObserver` and sets `--toolbar-h` on `<main>`; grid cards get `scroll-margin-block-start: calc(var(--toolbar-h) + var(--space-3))`, on top of the root `scroll-padding-top: var(--nav-h)`.

### 6. Automatic paging (`use-auto-paging.ts`)

- `useAutoPaging({ enabled, onLoad })` returns a ref for a sentinel `<div aria-hidden="true">` placed after the grid. `enabled` is `hasNextPage && !isFetchingNextPage && !isError && cards.length > 0`.
- One `IntersectionObserver` with `rootMargin: "0px 0px 100% 0px"` tracks whether the sentinel is near. An effect runs `onLoad()` when near and enabled; because `enabled` flips back to true after each page, a sentinel that is still near loads the next page too.
- No `IntersectionObserver` (jsdom without a stub): no automatic paging; the button still works.
- `loadMore()` is today's function. It also remembers whether `document.activeElement` was the Load more button when it started; when the page lands and that is still true, it focuses the first new card (index `before`), so focus never falls to `body` when the button disappears.
- Load more: `<div data-spatial-row>` with `useRovingFocus("row", { spatial: true })` around `<Button variant="secondary" data-roving-item disabled={isFetchingNextPage}>`, text "Load more", or "Loading…" while fetching (`aria-busy` on the section as today).
- The grid `ul` gets `data-spatial-row` and `useRovingFocus("grid", { spatial: true })`, so Up from its first row reaches the toolbar and Down from its last row reaches Load more.

### 7. States and copy (`library-grid.tsx`)

| State | What shows |
|---|---|
| First page pending | 12 `Skeleton`s with `width="var(--poster-w)"` and `aspectRatio="2 / 3"` in a `.media-grid[data-variant="poster"]` list marked `aria-hidden`, plus a visually hidden "Loading" in the busy section |
| First page error | `InlineError spatial message="Couldn't load {label}." onRetry={refetch}` (DESIGN.md §10 "Row error") |
| Empty, no filters | `EmptyState icon={Film} title="Nothing in this library yet"` with body "Add media in Jellyfin, then come back." (new §10 row, echoing "Home, empty") |
| Empty, filters on | `EmptyState icon={FilterX} title="Nothing matches these filters"` with a `Button` "Clear filters" in a single-item spatial row (DESIGN.md §10). Clear empties `filters` and focuses the "Unwatched" chip |
| Next page error | Cards stay; `InlineError spatial message="Couldn't load more items." onRetry={fetchNextPage}` |

`{label}` is the library name, or "this collection" on a collection page. No transport message is ever shown.

### 8. Nav edge fade (Q11 A, `app-nav.tsx`, `shell.css`)

- `AppNav` measures `.app-nav-list` (`scrollLeft`, `clientWidth`, `scrollWidth`) on mount, on scroll, on resize (`ResizeObserver`), and when `libraries` changes, and sets `data-overflow` to `none`, `start`, `end`, or `both` (1 px tolerance, as `MediaRow.measure`).
- CSS masks the overflowing side(s) with `mask-image` and `-webkit-mask-image`: `linear-gradient(to right, transparent, var(--surface-0) var(--nav-fade-w), var(--surface-0) calc(100% - var(--nav-fade-w)), transparent)`, with the transparent stop only on overflowing sides. The mask uses alpha only; `--surface-0` is an opaque token, so no colour literal is needed (`css-rules.test.ts`). `data-overflow="none"` sets `mask-image: none`.
- While overflowing, `scroll-padding-inline` becomes `var(--nav-fade-w)`, so a focused or current entry scrolls clear of the fade. `AppNav`'s current-entry effect already reads `scrollPaddingLeft`.
- No animation; nothing changes under reduced motion. Forced colours keep the entries (a mask does not hide focus outlines inside the clear area).

### 9. Detail prefetch on dwell

`LibraryGrid` passes an `onFocus` on the grid that finds the focused card's index and calls `useFocusDwell(300)` (from `src/features/home/use-focus-dwell.ts`). After the dwell, a `Movie` card's detail is prefetched with `queryClient.prefetchQuery({ queryKey: detailKey(gateway, id), queryFn, staleTime: 30_000, gcTime: 30_000 })`, the same values as Home (`home-view.tsx:20`, `:62`).
