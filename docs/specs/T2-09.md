## Approach

### Shapes

```ts
// tripwire-expectations.ts
export type ServerKind = "jellyfin" | "jellyscale";
export const SERVERS = [
  { name: "jellyfin-10-11", label: "10.11", kind: "jellyfin" },
  { name: "jellyfin-12", label: "12.4", kind: "jellyfin" },
  { name: "jellyscale", label: "Jellyscale", kind: "jellyscale" },
] as const;
export type CapabilitySetName = "full" | "no-h264" | "no-hevc" | "no-av1";
export const CAPABILITY_SETS: Record<CapabilitySetName, { lacks?: "h264" | "hevc" | "av1"; samples: "all" | readonly string[] }>;
export function capabilitiesOf(name: CapabilitySetName): "full" | { probe: "complete"; … };
export const JELLYSCALE_FORCED_CONVERSION: Expectation; // the refusal; T10-08 makes it a conversion
export function expectationFor(server: ServerName, set: CapabilitySetName, sample: string): Expectation;
export function runPlan(optIn: boolean): { server; set; sample; expect }[];
```

`name` is the compose service and the `.credentials` prefix (`jellyscale_url` already exists). Each sample gains `videoCodec` (`h264`, `hevc`, `av1`, or none for the disc and the ISO), so "lacks this sample's codec" is data, not a name match.

### Capability sets and the matrix

- `full` is the value `"full"`: every sample, as today.
- `no-h264`, `no-hevc`, `no-av1` are complete lists: every `VIDEO_CODECS` value but one, every `AUDIO_CODECS` value, no decoder limits, no passthrough. Each runs two samples on every server:
  - the sample with the missing codec (`h264`, `hevc-hdr10`, `av1`): a conversion with the client reason on Jellyfin, the refusal on Jellyscale;
  - a control with another codec (`hevc-hdr10` under `no-h264`, `h264` under the other two): direct play with exactly one PlaybackInfo request. It shows the set converts only what it cannot play.
- That is 6 extra rows per server. On Jellyfin 3 of them convert, at about 20 s each (3 s before the play-method check, 1.5 s hold, 10 s after the stop). Estimated cost: about 1 min per Jellyfin server and about 30 s on Jellyscale, plus about 1 min 30 s for Jellyscale's `full` run. The `pnpm test:tripwire` step should go from about 4 min to about 8 min, and the job from about 10 min 30 s to about 15 min. This is an estimate from the two timings in Facts.
- Each capability set gets its own signed-in gateway (its own install id), as each user and limit does today.

### What a row checks

- **`direct-play`**: as today, plus the wire rule. One PlaybackInfo request, counted from the wire record.
- **`conversion`** without a client reason: as today.
- **`conversion` with `clientReason`** (`checkClientConversion`):
  - the plan is HLS and carries `clientConversionReason === "DeviceCannotPlay"`;
  - `conversionIndicator(plan).chip` is exactly `Converting on server: this device cannot play the original` (`decisions-T2-07.md`; the string is written in the tripwire, not imported, so the oracle stays independent);
  - the wire record holds exactly two `POST /Items/{id}/PlaybackInfo` for the sample, and the second has `EnableDirectPlay=false` and `AllowVideoStreamCopy=false` in its query. The recorder keeps the JSON body's flag names and values for PlaybackInfo requests only, so the rule also compares body with query;
  - the confirmed method is `Transcode`, `/Sessions` agrees (`checkSessionAgreement`), and no job remains 10 s after the stopped report (`checkJobGone`).
- **`refused`**: the exact reason, no media request, and the full job oracle for the row's window. For `device-cannot-play`, exactly two PlaybackInfo requests.
- **`not-run`**: `checkPrecondition` only.
- `planWithAudioPick` stops replacing the gateway's `post` and counts from the wire record.

### The wire record

- `installWireRecorder(secrets)` replaces `globalThis.fetch` once, before any gateway exists, and returns `{ records, restore }`. The transport adapter, the monitor and `playerFetch` all go through it.
- One record per request: `method`, `origin`, `path`, the query names (and, for PlaybackInfo only, the query pairs and the body's top-level boolean flags), `hasAuthorization`, `scheme`, `hasToken`, `urlHoldsSecret`, `redirectMode`, `status`. It never stores a header value, a query value outside PlaybackInfo's flags, or a body.
- `checkWireRequests(records, serverOrigin)` fails on: an empty record; a missing header; a scheme other than `MediaBrowser`; no `Token=` on any route except `GET /System/Info/Public` and `POST /Users/AuthenticateByName`; a credential query name (`isCredentialName`); `urlHoldsSecret`; an origin other than the server's; a redirect mode other than `manual`; a 3xx status.
- It runs for all three servers. Item 6 names Jellyscale; the rule is the same hard rule everywhere, and Jellyfin's static route simply does not enforce it.
- `docker compose exec` is not an HTTP request and is not in the record.
