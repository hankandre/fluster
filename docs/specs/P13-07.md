Task: `tasks/prd.json` P13-07 (phase P13, depends on P13-03, P13-04, and P13-05, all done). Plan row: `docs/design/rework-plan.md`, the P13-07 row of the task table. ## Goal

Replace the one-size `Card` and the home-only `MediaRow` (`src/features/home/media-row.tsx`) with the presentational `MediaCard` and `MediaRow` from DESIGN.md §7.4 and §7.5, under `src/features/shared/ui/`:

- `MediaCard` has four variants (`poster`, `thumb`, `episode`, `library`). Each card is sized by `--poster-w` or `--thumb-w` with an aspect-ratio frame. Cards carry marks, a progress bar tinted by their own art, and the time left.
- `MediaRow` has edge bleed, pointer paging, spatial Up and Down between rows, edge-aware scrolling, variant skeletons, and an `InlineError` state.

This fixes audit Top 2 (16:9 cards overlap their neighbours, and episode art covers episode text) on every screen that shows cards: Home, the library grid, the collection grid, the series episode list, search results, and the libraries page. It also closes these audit rows: Home P1 "Progress … nothing visible says how long is left", Home P1 "Loading shows six portrait skeletons", Home P1 "Continue Watching mixes 2:3 posters and 16:9 thumbs", Home P2 "two rings", Browse P2 "no watched marks", and keyboard gaps 2, 3, and 5 (`docs/design/audit.md`).

## Approach

1. **`MediaCard`** (`shared/ui/media-card.tsx`) is presentational. Props:

   ```ts
   export type MediaCardVariant = "poster" | "thumb" | "episode" | "library";
   export interface MediaCardProps {
     variant: MediaCardVariant;
     title: string;
     subtitle?: string;            // poster: year; thumb: subtitle; library: none
     href?: string;                // a link when present, otherwise <article>, as today (media-row.tsx:89-92)
     image?: { src?: string; blurHash?: string }; // src already built by gateway.imageUrl; blurHash-only in the gallery
     remainingTicks?: number;      // with progress
     progress?: number;            // 0..1
     played?: boolean;
     unplayedCount?: number;
   }
   ```

   Markup: the root `a.media-card` (or `article.media-card`) carries `data-media-card`, `data-variant`, `data-roving-item` (links only, as today), and `aria-label`. Inside it sit `.media-card-frame` (aspect-ratio frame with `CardImage`, marks, and progress) and, for `poster`, `thumb`, and `library`, the text block. The text block holds the title on one line and a meta line. The meta line is a flex row: the subtitle truncates with an ellipsis, and the time left does not shrink. The `episode` variant has no text under the art (DESIGN.md §7.5). All visible text, marks, and progress are `aria-hidden`. `MediaCard` renders `<CardImage image={image} src={image?.src} fallbackTitle={title} />`: the blurHash placeholder comes from `image.blurHash` and the `<img>` from `image.src`. Missing image (no `image`, or no `src` and no `blurHash`) or failed load (`data-state="error"`): `CardImage` shows `--surface-2` with the `fallbackTitle` centred in `--type-label`, and never a broken image. With a `blurHash` and no `src` (gallery), the placeholder shows and stays in `loading`. Marks sit at the top right of the frame in a 24 px disc (`var(--space-5)`) on `--veil`: a lucide `Check` when `played`, otherwise the count when `unplayedCount > 0` ("99+" above 99, `--type-meta`, tabular figures). Progress shows only when `progress` is defined. It is a `var(--space-1)` (4 px) track of `--track` at the bottom of the frame, and its fill is `--art-accent` set inline from `artTint(image?.blurHash).accent`.
2. **`MediaRow`** (`shared/ui/media-row.tsx`) is presentational. Props: `title?: string`, `label?: string` (the accessible name when there is no title), `variant`, `status: "pending" | "error" | "ready"`, `items?: (MediaCardProps & { id: string })[]`, `onRetry?`, and `errorMessage?`. It renders `<section aria-labelledby|aria-label aria-busy>`, then the `h2` (`--type-heading`). Pending shows a line `Skeleton` when there is no title. Below the heading it shows the content:
   - Pending: a `ul` of 8 poster or 5 thumb `Skeleton` cards (`width: var(--poster-w)` or `var(--thumb-w)`, matching aspect ratio, each `li` with `data-testid="card-skeleton"`), with `aria-hidden`. The `Skeleton` primitive already delays by 150 ms and drops its sweep under reduced motion (`feedback.css:53-82`, `base.css:138-147`).
   - Error: `InlineError` with `errorMessage` or "Couldn't load {title}." and Retry.
   - Ready: a `ul.media-row-list` with `data-spatial-row`, using `useRovingFocus("row", { spatial: true })`.

   An empty ready list renders nothing; the connected `HomeRow` returns `null` for an empty success, as today (`media-row.tsx:24`). Edge bleed: the list has `margin-inline: calc(-1 * var(--gutter))`, `padding-inline: var(--gutter)`, `scroll-padding-inline: var(--gutter)`, `overflow-x: auto`, and `padding-block: var(--space-5)`, so the lift and ring are not clipped. `overflow-x: auto` makes `overflow-y` compute to `auto`, so the list clips vertically too; the TV numbers are in Risks. Each card's `onFocus` calls `scrollIntoView({ block: "nearest", inline: "nearest" })`.

   Pointer paging (Decision 3): two `Button variant="icon"` controls, "Previous" and "Next", sit at the row's edges inside `@media (hover: hover) and (pointer: fine)`. They show on row `:hover` and `:focus-within`, and only when the list can scroll that way; the row tracks `scrollLeft` with `onScroll` and a `ResizeObserver`. Each scrolls by `clientWidth` minus 2 × gutter, with `behavior: "smooth"`, or `"auto"` under reduced motion. They have `tabIndex={-1}` and `aria-hidden="true"`, because arrow keys already page for keyboard and screen-reader users.
3. **Spatial rows** (`roving-focus.ts`). Add the pure `nearestByCentre(centreX: number, boxes: { left: number; width: number }[]): number | undefined`. Extend the options to `{ preferredIndex?: number; spatial?: boolean }`. In `onKeyDown`, when `nextRovingIndex` returns `undefined` and the key is ArrowUp or ArrowDown with `spatial` on, the hook:
   1. Takes `closest("main") ?? document`.
   2. Lists the `[data-spatial-row]` elements in DOM order and steps from the current container, skipping containers with no `[data-roving-item]`.
   3. Picks the target with `nearestByCentre` on `getBoundingClientRect()`, calls `preventDefault`, and focuses it. The target container's own `onFocus` moves its Tab stop.

   `nextRovingIndex` and the existing layouts keep their behaviour. Callers that pass no `spatial` are unchanged.
4. **Focus treatment** (DESIGN.md §7.5, §9; audit Home P2 "two rings"). `media.css` holds one rule set inside `@layer focus`, the layer that `base.css:152` declares last. In it, `.media-card:focus-visible` sets `outline: none` and `box-shadow: none`. Its specificity (0,2,0) beats the base `:focus-visible` rule (`base.css:153-163`), including the forced-colours `outline-color: Highlight`, so the link draws no ring in any mode. Clearing only `box-shadow` would leave the link's transparent outline, which forced colours paints as a second `Highlight` ring. Then `.media-card:focus-visible .media-card-frame` gets `box-shadow: var(--focus-ring), var(--shadow-lift)`, `outline: 3px solid transparent`, and `transform: var(--lift)`. Under forced colours, the frame's `outline-color` is `Highlight`. The ring is drawn on the frame only, so it is never removed. The title goes from `--text-2` to `--text-1` on focus. Hover gets `--shadow-lift` and the title colour without scale or ring ("half strength"). The transition is `transform` and `box-shadow` over `--dur-quick` and `--ease-out`. `--lift` is `none` under reduced motion (`tokens.css`), so no scale remains there.
5. **Image per variant** (`card-view.ts`, `cardImageFor`; import the domain type as `import type { MediaCard as CatalogCard }` to avoid the clash with the UI component). `poster`: `card.image`. `thumb`: `card.thumb`, else `card.backdrop`, else `card.image` (DESIGN.md §7.5 order; P13-05 already makes `thumb` fall back to the parent's). `episode`: the episode's own Primary (`card.image` when `image.itemId === card.id`), else `thumb`, else `backdrop`, else `image`. `library`: `LibraryView.image`. Widths for `gateway.imageUrl` are 400 for `poster` and 768 for the 16:9 variants (2× the wide tokens, 200 px and 384 px). They replace `CARD_IMAGE_WIDTH = 320` (`card-image.tsx:5`). `toMediaCardProps` maps the rest straight across. `href` comes from `cardRoute(card)` (`routes.ts`), unchanged: thumb cards still open details, because one-press resume is P13-08 (DESIGN.md §13.1). Library cards link to `#/next/browse/{id}`, as the text links do today (`browse-view.tsx:61`).
6. **Mapper** (`src/lib/jellyfin/cards.ts`). In `toMediaCard`:
   - Set `remainingTicks = RunTimeTicks - PlaybackPositionTicks` (minimum 0) whenever `progress` is set (`watchedFraction`, `cards.ts:60-65`).
   - Set `backdrop` from the item's own `BackdropImageTags[0]` with its BlurHash, independent of `image`.
   - Set `played: true` only when `UserData.Played` is true.
   - Set `unplayedCount` only for `Type === "Series"` with `UserData.UnplayedItemCount > 0`.

   In `toHomeLibraries`, set `image` from `ImageTags.Primary` with its BlurHash. Omitting a field when it is false or absent keeps the existing `toEqual` expectations for other items valid. No request parameter changes: `/UserItems/Resume`, `/Items`, and `/Shows/*/Episodes` already send `enableUserData: true` (`gateway.ts:432`, `:488`, `:531`, `:559`). The `/Shows/NextUp`, `/Items/Latest`, and `/UserViews` calls rely on server defaults for `UserData` and `ImageTags` (unverified; Risks).
7. `media.css` starts with `@layer reset, tokens, base, components, features, focus;` like `controls.css:1` and `feedback.css:1`, so its `@layer focus` block stays last. CSS uses tokens only (`src/styles/css-rules.test.ts`). The new rules go in `src/features/shared/ui/media.css` under `@layer components`, except the focus block in item 4. There are no literal colours, sizes, radii, or durations and no bare element selectors. The `episode` list item uses `display: flex; flex-wrap: wrap; gap: var(--space-4)`, with the text column at `flex: 1 1 20ch; min-inline-size: 0`, so it wraps under the art in narrow windows without a media query.

## Risks and out of scope

- Hard rules and invariants touched:
  - Build new UI only under `src/features/`, from `src/features/shared/ui/` (`MediaCard` and `MediaRow` live there and stay presentational, like `AppNav`).

  - Every screen works with arrows, Enter, and Escape alone, and honours reduced motion (spatial rows; `--lift: none`; `scroll-behavior` auto).
  - Focus is visible and never obscured (WCAG 2.4.11; DESIGN.md §9): rows keep the focused card `--gutter` from the edge, and `scroll-padding-top: var(--nav-h)` from P13-06 keeps it clear of the nav vertically.
  - State is never colour alone: the played check and count also appear in the accessible name.
  - Map errors to plain copy (`InlineError`, "Couldn't load {row}.").
  - Talk to Jellyfin only through `src/lib/jellyfin/gateway.ts`; image URLs come only from `gateway.imageUrl`, built by the connected callers. No request change, no new Tauri command, and no token in a URL (the e2e `/Images/` check at `home.spec.ts:80` stays).
  - Keep `src/domain/` free of React, SDK, Tauri, and HTTP imports (only type fields are added).
  - Add a focused test with every behaviour change; never skip, weaken, or delete a test.
  - No playback, DeviceProfile, PlaybackInfo, HLS, or `ARCHITECTURE.md` invariant change.
- Risk: `/Shows/NextUp` and `/Items/Latest` do not send `enableUserData` (`gateway.ts:442-473`), and `/UserViews` sends no image parameters. This spec assumes Jellyfin returns `UserData` and `ImageTags` by default there (unverified).
