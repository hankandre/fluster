## Approach

### 1. Home data (`home-data.ts`)

`useHomeData(gateway)` returns `{ resume, nextUp, views, latest }`.

- `resume`, `nextUp`, and `views` are `useQuery` results with today's keys: `["home", scope, "resume" | "next-up" | "views"]`, `gcTime: 0`.
- `latest` is an array of `{ view, query }` from `useQueries` over `views.data`, with key `["home", scope, "latest", view.id]` and `gcTime: 0`.

This keeps the behaviour that `home-view.test.tsx` "starts every row query before any of them resolves" asserts. It also lets the rows, the hero, and the empty state read the same results without a second observer.

`HomeRow({ title, variant, query, gateway, playable })` maps the result to `MediaRow`. When `playable` is true (Continue watching and Next up), items use `toPlayCardProps`. Latest rows keep `toMediaRowItems(…, "poster", …)`.

Row titles: "Continue watching", "Next up", "Latest in {view.name}". Error copy stays `Couldn't load {title}.` (§10).

### 2. Picking the hero (`hero-pick.ts`)

```ts
type Source<T> = { status: "pending" | "error" | "success"; data?: T };
type HeroPick =
  | { status: "pending" }
  | { status: "none" }
  | { status: "ready"; card: CatalogCard };
function pickHero(
  resume: Source<CatalogCard[]>,
  nextUp: Source<CatalogCard[]>,
  views: Source<unknown[]>,
  latest: Source<CatalogCard[]>[],
): HeroPick;
```

It walks the sources in this order:

1. `resume`, then `nextUp`. A pending source returns `pending`. A successful source returns the first card whose `kind` is `Movie` or `Episode`. An error or no eligible card moves on.
2. `views`. Pending returns `pending`. An error returns `none`.
3. Each `latest` entry in order. Pending returns `pending`. Success returns the first card whose `kind` is `Movie`, `Episode`, or `Series`. Otherwise it moves on.
4. If nothing matched, it returns `none`.

`BoxSet` and `Other` are never heroes, because there is nothing to play.

A refetch keeps `status: "success"`, so the hero does not flicker on a realtime refresh.

### 3. `Hero` (presentational, `shared/ui/hero.tsx`)

Props:

- `title: string`
- `logo?: { src: string }`
- `art?: { src: string; blurHash?: string }`
- `facts?: string`
- `overview?: string`
- `detailPending?: boolean`
- `primary?: { label: string; href: string; onActivate(event): void }`
- `moreInfoHref?: string`
- `pending?: boolean`

Markup:

- `<section className="hero" aria-labelledby={titleId}>` with inline `--art-accent`, `--art-glow`, and `--art-shade` from `artTint(art?.blurHash)` (§3.2).
- `div.hero-art`: a BlurHash placeholder (`blurhashToDataUrl`, as `AmbientLayer` does) and `<img alt="" decoding="async">`. Over it sit the `--scrim-hero`, `--scrim-floor`, and an `--art-glow` radial (the same stack as `.ambient-layers::before`), plus `--scrim-nav` across the top `calc(var(--nav-h) * 2)`. `--scrim-nav` is the top layer of the art stack: `.hero-art::before` holds the floor, hero scrim, and glow (`z-index: 1`), and `.hero-art::after` holds `--scrim-nav` (`z-index: 2`). A test in `tokens.test.ts` asserts that order, so the Approach 8 nav proof also holds over the glow.
- `div.hero-text`:
  - `h2.hero-title`: the Logo `img` (`alt={title}`, `onError` falls back to text), or the text in `--type-hero` with `--tracking-hero`, at most two lines.
  - `p.hero-facts` in `--type-meta`.
  - `p.hero-overview` in `--type-body-lg`, clamped to two lines, `max-inline-size: var(--measure)`.
  - `div.hero-actions`.
- The actions are a `useRovingFocus("row", { spatial: true })` list with `data-spatial-row`. Its items are a `ButtonLink variant="primary"` and a `ButtonLink variant="secondary"` "More info", each with `data-roving-item`. This makes Up from the first row reach the hero and Down from the hero reach the first row, with arrow keys alone (§9; principle 4).
- While `detailPending` is true, the facts and overview show two `Skeleton shape="line"` blocks.
- `pending` renders the same frame with Skeleton blocks for the title, the facts, and two buttons, and sets `aria-busy`.
- When `primary` is absent (a series whose first episode could not be found), "More info" takes `variant="primary"`.
- All hero text uses `--text-1`, because `--text-2` fails 4.5:1 over the brightest art at the column edge (Approach 8).
- It calls `useNavOverHero()` while mounted.

Layout (`hero.css`, tokens only):

- `block-size: var(--hero-h)`. The hero pulls up under the sticky nav with `margin-block-start: calc(-1 * var(--nav-h))` and bleeds to both edges.
- The text sits in the left 5 of 12 columns: `inline-size: min(calc((100% - 2 * var(--gutter)) * 5 / 12), …)` from `padding-inline-start: var(--gutter)`. It is bottom-aligned, `--space-8` from the floor (§6). Gaps use `--space-*`.
- The Logo is limited to `--hero-logo-max-w` by `--hero-logo-max-h`, with `object-fit: contain` and `object-position: left bottom`.
- Compact (`max-width: 719px`): the art keeps a 16:9 box and the text block follows below it on `--surface-0`. At 390 px the formula height (219 px) cannot hold the text. This mirrors the §7.7 compact stacking.

### 4. One-press cards (`media-card.tsx`, `card-view.ts`)

When `href` and `onActivate` are set, the anchor's `onClick` calls `onActivate(event)`. The adapter's `onActivate` follows the `PlayLink` rule (`play-actions.tsx:49`). A plain primary click does `preventDefault()` and then `openPlayer(route)`. A modified click keeps the browser default.

When `detailsHref` is set:

- `onKeyDown`: `i` (no Ctrl, Meta, or Alt) or `ContextMenu` → `preventDefault()`, then `window.location.hash = detailsHref`.
- `onContextMenu` → `preventDefault()`, then the same navigation.
- `aria-keyshortcuts="i"` and `aria-describedby={describedBy}`.

`HomeView` renders one `<p id={hintId} className="visually-hidden">Enter plays. Press i for details.</p>`, and play cards point at it. The accessible names do not change, so existing e2e names stay valid.

`toPlayCardProps` returns plain `thumb` props for a card whose `cardRoute` is undefined (unknown kind). Such a card stays a non-interactive article, as today.

`Enter` on a link already fires `click`, so one code path handles both. TV `Menu` mapping is for P13-18.

### 5. Ambient follow (`MediaRow.onItemFocus`, `use-focus-dwell.ts`)

`MediaRow.onFocus` finds the focused card's index in `items` and calls `onItemFocus?.(items[index].id)`.

`useFocusDwell(ms)` returns `schedule(fn)`. It clears any pending timer and starts a new one. It clears the timer on unmount.

`HomeView` builds a map from id to card over all loaded rows. On dwell it sets `ambient = { key: \`${card.id}/${art?.tag ?? "none"}\`, art }` with `art = heroArtFor(card)`. Before any focus, the ambient shows the hero card's art; with no hero, `"none"`.

`AmbientBackdrop` receives:

- `imageKey`
- `src = art ? gateway.imageUrl(art.itemId, art.type, art.tag, backdropWidth()) : undefined`
- `blurHash`
- `strength={0.35}`

Hover does not schedule anything, because hover never moves focus (§9).

### 6. Nav over the hero and on scroll (`app-shell.tsx`, `shell.css`)

`AppShell` holds `overHero` (a count, set through a context that `useNavOverHero()` increments on mount and decrements on unmount) and `scrollState`. A passive `scroll` listener on `window`, throttled with `requestAnimationFrame`, computes:

- `surface = overHero > 0 && scrollY <= 0 ? "clear" : "glass"`.
- `hidden`:
  - Set it to true when the page scrolls down by 8 px or more past `scrollY > 2 × nav height`.
  - Set it to false on any upward scroll of 8 px or more, or when `scrollY <= nav height`.
  - Never set it while `document.activeElement` is inside the header, and clear it on `focusin` in the header.
  - Never hide in the TV form (`document.documentElement.dataset.form === "tv"`; P13-18 owns TV nav behaviour).

The header gets `data-surface` and `data-hidden`.

CSS:

- `[data-surface="glass"]`: `background: var(--surface-0-glass); backdrop-filter: blur(var(--blur-nav)); border-block-end: 1px solid var(--line)`. This is today's look plus the blur, which is the only allowed blur (§5).
- `[data-surface="clear"]`: `background: transparent; border-color: transparent`.
- `[data-hidden="true"]`: `transform: translateY(-100%)`.
- `transition` on `transform`, `background-color`, and `border-color` over `--dur-base` `--ease-out`.
- Under `prefers-reduced-motion: reduce`, no transition. The nav still hides and returns, because that is a function, not an animation (§5).

The player and sign-in have no shell, so they are unaffected.

### 7. Empty state and server name (`home-empty.tsx`)

Empty means:

- `resume` and `nextUp` succeeded with `[]`.
- `views` succeeded.
- Every `latest` query succeeded with `[]`, or `views` is `[]`.

Only then does a query `["home", scope, "server"]` run `gateway.connect(signal)` (`enabled` only when empty, `gcTime: 0`) and read `name`. This is the existing unauthenticated `/System/Info/Public` probe. It adds no new request type.

While that query is pending or failed, `{server}` is `new URL(gateway.origin).host`. A host is not a credential or an authenticated URL, and sign-in already shows it.

The icon is lucide `Clapperboard` (48 px line, `--text-3`, through `EmptyState`). The action is `ButtonLink variant="primary" href="#/next/settings"` "Open settings". It is the screen's only action (§7.19 "one per screen").

### 8. Contrast proofs (`tokens.test.ts`, using `src/styles/contrast.ts`)

- Nav text over a transparent nav: `--text-2` on `composite(--surface-0, 0.85, #ffffff)` is at least 4.5:1. This reads the 0.85 alpha of the 50% stop parsed from `--scrim-nav`. The nav band lies inside the full-strength half.
- Hero text: `--text-1` on white art under `--scrim-hero` at 42.5% of the width is at least 4.5:1. The alpha is interpolated between the parsed 38% stop (0.72) and the 72% stop (0) and comes to about 0.63. The test computes it from the token, so a token change re-checks it.

The text column must end at or before 42.5% of the hero width at medium and wider. Approach 3 caps it at 5/12 of the content width.

### 9. Home page structure (`home-view.tsx`)

```
  <p id={hintId} className="visually-hidden">Enter plays. Press i for details.</p>

```

- `.home-page` has no top padding (unlike `.home`), so the hero can sit under the nav. It creates a stacking context like `.home` (`position: relative; z-index: var(--z-content)`), because the ambient layers sit at `z-index: -1` and `.app-shell` paints `--surface-0`. Without it the ambient layer would paint behind the shell and be invisible while the `data-key` assertions still passed. With no hero, `.home-rows` gets `padding-block-start: var(--space-6)`.
- Home still does not move focus on mount. `nav.spec.ts` keyboard sequences rely on this (P13-06 Risks). TV initial focus belongs to P13-18.

### 10. `HomeHero` (`home-hero.tsx`)

It receives `card`, `gateway`, and `scope`.

- A detail query `["home", scope, "hero", card.id]` runs `gateway.itemDetail` for `Movie` and `Episode`, and also for `Series` (for the overview and year). `gcTime: 0`, `retry: false`. On error, render from the card alone, with no overview and no message (the enrichment is optional).
- `Series` only: a query `["home", scope, "hero-episode", card.id]` runs `seasons(seriesId)`. It picks the first season with `indexNumber >= 1`, else the first season, and then `episodes(seriesId, season.id)[0]`. These are existing gateway methods. Until it settles, `primary` is undefined and the hero shows `pending` buttons.
- Text from `hero-facts.ts` (pure, tested):
  - `primaryAction(card, episode?)`:
    - `resumePositionTicks > 0` → `Resume from {positionLabel(ticks)}` (`detail/format.ts:99`; §10 copy) with `startTicks = ticks`.
    - Episode → `Play S{s} · E{e}` when both numbers are present, else `Play`. It starts at 0.
    - Movie → `Play`.
    - Series → `Play S{s} · E{e}` from the resolved episode (`Play` without numbers). The route goes to the episode id, from 0. A fully watched series also gets S1 · E1 (`decisions-P13.md`, "Left to the spec").
  - `heroFacts(card, detail?)`. Every part is optional and the parts are joined by " · ":
    - Episode: `S{s} · E{e}`, then `timeLeftLabel(remainingTicks)` when there is progress, else `runtimeLabel(detail.runTimeTicks)`. This is the §7.3 example.
